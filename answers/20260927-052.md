## 解説

### 完成文: DMVPN Phase 1 / 2 / 3 の比較

| 項目 | Phase 1 | Phase 2 | Phase 3 |
|---|---|---|---|
| スポークのトンネル | p2p GRE(tunnel destination でハブを固定) | mGRE | mGRE |
| スポーク間トラフィックの経路 | 常にハブ経由 | スポーク間の動的トンネルで直接(経路の next-hop が対向スポーク) | スポーク間の動的トンネルで直接(経路はハブ向きのまま転送だけ切り替え) |
| スポークが持つ経路 | 集約や default でよい(next-hop はハブ) | **［①］対向 LAN ごとの具体的な経路が要る(集約不可・next-hop= 対向スポーク)** | 集約や default でよい(next-hop はハブのまま) |
| ハブの追加設定(EIGRP の場合) | なし | **［②］no ip next-hop-self eigrp(+ no ip split-horizon eigrp)** | **［③］ip nhrp redirect(+ no ip split-horizon eigrp)** |
| スポークの追加設定 | なし | なし | ip nhrp shortcut |
| OSPF ネットワークタイプの定石 | **［④］point-to-multipoint** | broadcast(ハブが DR・スポークは priority 0) | broadcast(同左) |

Phase の番号は設定の組合せで決まる動作モード(ソフトウェアの版ではない) で、ハブは 3 つのどれでも mGRE である。Phase 2 でハブが経路を集約できないのは、スポーク間直接通信のきっかけが **［⑤］経路の next-hop が対向スポークのトンネル IP であること(その解決で NHRP が走る)** だからである。Phase 3 では **［⑥］ハブが中継時に送る NHRP Redirect と、それを受けたスポークの解決(shortcut)** がきっかけになるので、スポークの経路はハブ向きのままでよく、ハブで集約しても直接通信が成立する。どの Phase でもハブの EIGRP には no ip split-horizon が要る(同じ Tunnel から学んだスポークの経路を他のスポークへ反射させるため)。

### 各空欄の要点

- ① = **D. 対向 LAN ごとの具体的な経路が要る(集約不可・next-hop= 対向スポーク)** — next-hop が対向スポークでないと直接通信が起きない
- ② = **C. no ip next-hop-self eigrp(+ no ip split-horizon eigrp)** — Phase 2 はハブが next-hop を書き換えないことが核心
- ③ = **F. ip nhrp redirect(+ no ip split-horizon eigrp)** — Phase 3 はハブが Redirect を送る
- ④ = **E. point-to-multipoint** — 全通信がハブ経由なら p2mp が素直。既定の p2p は複数隣接を張れない
- ⑤ = **G. 経路の next-hop が対向スポークのトンネル IP であること(その解決で NHRP が走る)** — だから集約すると next-hop がハブになり直接通信が消える
- ⑥ = **J. ハブが中継時に送る NHRP Redirect と、それを受けたスポークの解決(shortcut)** — 転送面だけがオンデマンドで切り替わる

### 語群の残り(どの空欄にも入らない)

- H. 集約や default でよい(next-hop はハブ) — next-hop が対向スポークでないと直接通信が起きない
- B. point-to-point(既定のまま) — 全通信がハブ経由なら p2mp が素直。既定の p2p は複数隣接を張れない
- A. ハブが GRE キープアライブを返すこと — だから集約すると next-hop がハブになり直接通信が消える
- I. スポーク同士の IKE の事前交渉 — 転送面だけがオンデマンドで切り替わる
