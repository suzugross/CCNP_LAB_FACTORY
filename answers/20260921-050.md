## 解説

### 完成文: FHS が検査する ND メッセージと DHCPv6 メッセージ

| ICMPv6 type | 名称 | 主な宛先 |
|---|---|---|
| 133 | RS(Router Solicitation) | ff02::2(全ルータ) |
| 134 | **［①］RA(Router Advertisement)** | ff02::1(全ノード) またはユニキャスト |
| 135 | NS(Neighbor Solicitation) | 要請ノードマルチキャスト ff02::1:ffxx:xxxx |
| 136 | **［②］NA(Neighbor Advertisement)** | 要請元ユニキャスト(または ff02::1) |
| 137 | Redirect | 送信元ホスト |
| DHCPv6 | クライアント UDP **［③］546** / サーバ・リレー UDP 547 | ff02::1:2(全 DHCP リレー/サーバ) |

第一ホップの機能は上の表のメッセージを対象にする。端末は起動時に RS(Router Solicitation) を全ルータ宛に送り、ルータは **［①］RA(Router Advertisement)** で応える。RA には M フラグと O フラグがあり、M=1 ならステートフル DHCPv6 でアドレスを取る、M=0/O=1 ならアドレスは SLAAC・その他情報(DNS 等)は DHCPv6 を意味する。RA guard はこの RA と、経路変更を指示する **［④］Redirect(type 137)** の 2 種類を検査する。DHCPv6 guard が破棄するのはサーバ側が送る ADVERTISE と REPLY で、クライアントが送る SOLICIT/REQUEST は通す。アドレス解決の NS と、それに答える **［②］NA(Neighbor Advertisement)** は ND inspection の検査対象で、表と食い違う「IPv6 アドレス→MAC」を主張する NA が捨てられる。

### 各空欄の要点

- ① = **F. RA(Router Advertisement)** — type 134 は RA
- ② = **A. NA(Neighbor Advertisement)** — type 136 は NA。NS への応答
- ③ = **G. 546** — DHCPv6 クライアントは UDP 546(IPv4 の 68 に相当)
- ④ = **D. Redirect(type 137)** — RA guard は RA と Redirect を検査する
