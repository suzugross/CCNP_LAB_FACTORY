## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/tag` — 再配送リングの定常ループ(ring=inject_ospf)
- 機構: `192.168.236.0/24` は RT06 が BGP 起点広告 → RT05 が iBGP(AD 200) で学習。
  RT05 が BGP を OSPF へ再配送し、RT07 の相互再配送で
  出自が一周。戻ってきた D EX (AD 170) が iBGP(200) に勝って RT05 が採用
  → 定常転送ループ RT05 → RT07 → RT03 → RT05。
- 出題形式: fix(是正手順を選ばせる)
- 正解法: tag(distance=iBGP の AD を戻り 170 未満へ /
  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 771779816`
  (sub-seed 3717150 / 展開パック PAPER-RD-3717150・撤収済)
- 赤ニシン: RT03・RT04・RT05 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)

## 各選択肢の判定

- **A**: (正解)
- **B**: 守る向きが逆。タグが付くのは RT07 で出自が一周した後であり、RT05 の deny の適用先(BGP から IGP への注入)を戻り経路は通らない。RT05 の RIB では戻り外部経路(AD 170)が iBGP に勝ったまま残り、ループは解消しない。
- **C**: iBGP 学習経路の IGP への注入が止まりループは解消するが、IGP 側の全ルータが `192.168.236.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない。
- **D**: 出自の一周は止まるが、RT07 の先のドメインの各ルータが `192.168.236.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない。
- **E**: 到達性・ループとも解消する(症状は直る)が、監査要件「管理距離(distance)の変更禁止」に違反する。
- **F**: 到達性・ループとも解消する(症状は直る)が、被害プレフィックスを個別に列挙する形であり、要件「遮断は経路の出自に基づくこと(プレフィックスの列挙による指定は不可)」を満たさない。
- **G**: 出自のタグは付くが、一周した経路を落とす側の deny が無いため、戻り外部経路はそのまま学習され、ループは解消しない。

## 検証コマンドと期待される出力

- RT05: `show ip route 192.168.236.0` が `Known via "bgp 65492"` に変わること
  (是正前は `Known via "eigrp"`)。
- 任意ルータから `traceroute 192.168.236.1` が RT06 まで一直線(是正前はリングを周回)。
- distance 解の場合、投入だけでは BGP 表の `r>`(RIB-failure) が残るため
  `clear ip route *`(または clear ip bgp)で再計算が要る。
- tag 解の場合、RT05 で `Known via "bgp"` に変わり、かつ RT07 は当該網を
  引き続き保持していること(戻りの再注入だけが止まる)を見る。
  タグの付与だけでは何も変わらない(deny 側が本体)。

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
