## 解説

### 完成文: RP の決め方: static・BSR・Auto-RP・anycast RP(MSDP)

static RP は `ip pim rp-address` で指定し、**［①］すべての PIM ルータ** に同じ設定が必要である。標準の方式は BSR で、候補 BSR から選ばれた BSR が候補 RP の一覧を hop-by-hop で配る。候補 RP の priority は **［②］値が小さい方** が優先される(Cisco の既定値は 0)。Cisco 独自の Auto-RP では、候補 RP が 224.0.1.39 へ announce し、mapping agent が **［③］IP アドレスが最大** の RP を選んで 224.0.1.40 で配る。インターフェイスが sparse-mode だけの場合、この 2 つのグループには RP が無いため、**［④］`ip pim autorp listener`** を設定しないと mapping agent の先へ情報が届かない。同じグループに static と動的(BSR / Auto-RP)の情報があると、**［⑤］static に override を付けない限り動的の情報が使われる**。anycast RP では複数の RP に同じアドレスを設定し、RP 同士は **［⑥］MSDP(TCP 639)** で送信元の情報(SA)を交換する。管理スコープの境界では `ip multicast boundary` で該当するグループを止め、その範囲への IGMP の参加も受け付けない。

### 各空欄の要点

- ① = **C. すべての PIM ルータ** — RP の位置を各ルータが知っている必要がある
- ② = **J. 値が小さい方** — 実測: priority 10 の候補より 0 の候補が選ばれた。同値ならハッシュ
- ③ = **B. IP アドレスが最大** — 実測: 3.3.3.3 と 5.5.5.5 から 5.5.5.5 が選ばれた
- ④ = **A. `ip pim autorp listener`** — 実測: 無しでは MA の先に discovery が届かず、設定後に届いた
- ⑤ = **D. static に override を付けない限り動的の情報が使われる** — 実測: static を 239.1.1.0/24 に絞っても 224/4 の Auto-RP が使われた。override で static
- ⑥ = **F. MSDP(TCP 639)** — SA cache に (S,G) と発信元 RP が載る(実測)
