## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/tag` — 再配送リングの定常ループ(ring=inject_ospf)
- 機構: `192.168.189.0/24` は RT04 が BGP 起点広告 → RT01 が iBGP(AD 200) で学習。
  RT01 が BGP を OSPF へ再配送し、RT05 の相互再配送で
  出自が一周。戻ってきた D EX (AD 170) が iBGP(200) に勝って RT01 が採用
  → 定常転送ループ RT01 → RT05 → RT02 → RT01。
- 出題形式: select2(タグ解の2アクションを複数選択で(BL-120 #8・正解2つ))
- 正解法: tag(distance=iBGP の AD を戻り 170 未満へ /
  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 925582297`
  (sub-seed 1939893 / 展開パック PAPER-RD-1939893・撤収済)
- 赤ニシン: RT01・RT02・RT03 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)

## 各選択肢の判定

- **A**: 到達性・ループとも解消する(症状は直る)が、監査要件「管理距離(distance)の変更禁止」に違反する。
- **B**: (正解)
- **C**: 出自の一周は止まるが、要件「既存の再配送設計の維持」に違反し、RT05 の先のドメインが `192.168.189.0/24` への経路を失う。
- **D**: 到達性・ループとも解消する(症状は直る)が、被害プレフィックスを個別に列挙する形であり、要件「遮断は経路の出自に基づくこと(列挙による指定は不可)」を満たさない。
- **E**: (正解)
- **F**: 定常状態は経路の構造に起因するため、再計算しても同一の状態に戻る。

## 検証コマンドと期待される出力

  (是正前は `Known via "eigrp"`)。

- distance 解の場合、投入だけでは BGP 表の `r>`(RIB-failure) が残るため

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
