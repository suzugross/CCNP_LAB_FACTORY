## 解説

### 完成文: SNMP 通知: trap と inform の違いと host 行の既定

| 項目 | trap | inform |
|---|---|---|
| 受信側の確認応答 | なし(受信側は何も返さない) | **［①］あり(受信側が Response を返す)** |
| 届かなかったとき | 再送しない(送りっぱなし) | 応答が来るまで再送する(回数・間隔は設定可) |
| 送信側の負担 | 小さい | 応答待ちの間メモリに保持するので大きい |
| 使える SNMP バージョン | v1 / v2c / v3 | **［②］v2c / v3(v1 では使えない)** |
| 宛先ポート(管理ステーション側) | UDP 162 | UDP 162 |

通知の宛先は `snmp-server host` で、何を通知するかは **［③］snmp-server enable traps** で決める。両方が揃って初めて通知が飛ぶ。`snmp-server host 192.168.100.20 mon-ro` のように version を省略するとバージョン 1 の trap として送られる(実測)。inform を送るには host 行に **［④］informs** を付け、version は 2c 以上を指定する。v1 を指定すると設定自体が拒否される(実測)。v3 で通知を送るときは `version 3` の後ろにセキュリティレベル(noauth/auth/priv)とユーザ名を書き、通知に使うユーザの鍵で認証・暗号化される。エージェントが要求を受けるのは UDP 161、通知を受け取る管理ステーション側は UDP **［⑤］162** である。

### 各空欄の要点

- ① = **B. あり(受信側が Response を返す)** — inform は確認応答付き
- ② = **D. v2c / v3(v1 では使えない)** — %Informs not supported in SNMPv1(実測)
- ③ = **F. snmp-server enable traps** — enable traps= 通知の種類 / host= 宛先
- ④ = **G. informs** — snmp-server host X informs version 2c <comm>
- ⑤ = **H. 162** — 通知の受け手は 162

### 語群の残り(どの空欄にも入らない)

- A. 514 — 通知の受け手は 162
- J. なし(受信側は何も返さない) — inform は確認応答付き
- C. v3 だけ — %Informs not supported in SNMPv1(実測)
- E. snmp-server community — enable traps= 通知の種類 / host= 宛先
- I. traps — snmp-server host X informs version 2c <comm>
