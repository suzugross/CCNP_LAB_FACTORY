## 解説

### 完成文: BGP ベストパス選択の順序

| 順 | 比較する属性と勝つ条件 |
|---|---|
| 1 | Weight が最大 |
| 2 | LOCAL_PREF が最大 |
| 3 | ローカルで生成した経路(network/redistribute > aggregate) |
| 4 | AS_PATH が最短 |
| 5 | **［①］ORIGIN が小さい(IGP < EGP < Incomplete)** |
| 6 | **［②］MED が最小** |
| 7 | **［③］eBGP 経路が iBGP 経路より優先** |
| 8 | ネクストホップへの IGP メトリックが最小 |
| 9 | 最も古い eBGP 経路(受信が早い方) |
| 10 | **［④］ルータ ID が最小** |
| 11 | クラスタリスト長が最短 |
| 12 | **［⑤］ネイバーアドレスが最小** |

上は Cisco IOS の BGP ベストパス選択で、同じプレフィックスの候補を上から順に比較して 1 本に絞る手順である。先頭 2 つは自 AS の中だけで意味を持つ値で、1 番はそのルータの中だけで有効(隣接へ広告されない)。3 番は自分で生成した経路を優先する段で、network/redistribute 由来が aggregate 由来より勝つ。4 番以降は AS 間で運ばれる属性の比較になり、5 番の origin は **［⑥］IGP(i) → EGP(e) → Incomplete(?)** の順で小さい方が勝つ。6 番の MED は既定では同じ隣接 AS から受けた経路どうしでだけ比較される。8 番までで決まらなければ安定性のために古い経路を残し、最後は識別子の小さい方という機械的な決着になる。なお maximum-paths を設定していると 8 番の後で等コストの複数経路が採用され、その場合でもベストパスは 1 本だけ選ばれる。

### 各空欄の要点

- ① = **F. ORIGIN が小さい(IGP < EGP < Incomplete)** — i < e < ?
- ② = **E. MED が最小** — 既定は同一隣接 AS からの経路間だけ
- ③ = **G. eBGP 経路が iBGP 経路より優先** — 外部学習を優先
- ④ = **A. ルータ ID が最小** — 識別子で機械的に決める
- ⑤ = **C. ネイバーアドレスが最小** — 最後の決着。誤答のホップ数/コミュニティ/AD/プレフィックス長は選択基準に無い
- ⑥ = **B. IGP(i) → EGP(e) → Incomplete(?)** — i が最良

### 語群の残り(どの空欄にも入らない)

- H. ホップ数が最少 — i < e < ?
- D. コミュニティ値が最小 — i < e < ?
