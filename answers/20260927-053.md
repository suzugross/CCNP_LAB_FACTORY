## 解説

### 完成文: RPF チェック

ルータはマルチキャストパケットを受けると、受信インターフェイスが **［①］送信元** へのユニキャスト経路の出口と一致するかを確かめる(RPF チェック)。一致しなければそのパケットは **［②］破棄される**。共有木を流れるパケットでは、RPF の基準は **［③］RP** になる。等コストの経路が複数あるとき、Cisco IOS は既定で **［④］IP アドレスが最大** のネクストホップを RPF に使い、`ip multicast multipath` を設定するとフローごとのハッシュで分散する。ユニキャストの経路と PIM の経路を変えたいときは **［⑤］`ip mroute`** で RPF を静的に指定でき、`show ip rpf` では RPF type が multicast (static) と表示される。

### 各空欄の要点

- ① = **C. 送信元** — ループを防ぐため、送信元へ戻る方向から来たものだけを受け付ける
- ② = **B. 破棄される** — `show ip mroute count` の RPF failed に数えられる(実測)
- ③ = **G. RP** — (*,G) の Incoming interface は RP 方向
- ④ = **J. IP アドレスが最大** — 実測: 10.0.34.3 と 10.0.45.5 から 10.0.45.5 を選び、multipath で変わった
- ⑤ = **H. `ip mroute`** — static mroute(実測で RPF type multicast (static))

### 語群の残り(どの空欄にも入らない)

- I. 受信インターフェイスへ返される — `show ip mroute count` の RPF failed に数えられる(実測)
- A. インターフェイス番号が小さい — 実測: 10.0.34.3 と 10.0.45.5 から 10.0.45.5 を選び、multipath で変わった
- D. `ip route` — static mroute(実測で RPF type multicast (static))
