## 解説

### 完成文: DMVPN 上の EIGRP と OSPF の設定上の注意

| 項目 | EIGRP | OSPF |
|---|---|---|
| ハブがスポークの経路を他スポークへ広告するために | **［①］no ip split-horizon eigrp <AS>** | 不要(リンクステートに split horizon の概念は無い) |
| Phase 2 で next-hop を対向スポークのまま届ける | no ip next-hop-self eigrp <AS> | ip ospf network broadcast(next-hop が元のまま届く) |
| トンネル IF のネットワークタイプ | (概念なし) | **［②］Phase 1= point-to-multipoint / Phase 2・3= broadcast** |
| DR/BDR | (概念なし) | ハブだけが DR(スポークは ip ospf priority 0) |
| Phase 3 のハブでの経路集約 | **［③］ip summary-address eigrp <AS> <集約> <マスク>** | エリア境界でしか集約できない(全員が同一エリアなら不可) |

OSPF の point-to-multipoint は **［④］next-hop を常に広告元(ハブ)に書き換える** ので Phase 1 向きで、Phase 2 の直接通信には使えない。broadcast タイプではスポークが DR になると **［⑤］他のスポークがその DR と直接隣接を張れず LSDB が同期しない** ため、スポーク側で priority を 0 にする。Tunnel IF の OSPF ネットワークタイプは既定で point-to-point であり、そのままでは複数のスポークと隣接を張れない。EIGRP では Phase を問わずハブの split horizon 解除が要り、Phase 2 だけ next-hop-self の無効化も要る。

### 各空欄の要点

- ① = **C. no ip split-horizon eigrp <AS>** — 同じ Tunnel への再広告
- ② = **J. Phase 1= point-to-multipoint / Phase 2・3= broadcast** — 教材の定石どおり
- ③ = **A. ip summary-address eigrp <AS> <集約> <マスク>** — Phase 3 では集約しても直接通信が成立
- ④ = **I. next-hop を常に広告元(ハブ)に書き換える** — p2mp は /32 のホスト経路を広告し next-hop は自分
- ⑤ = **F. 他のスポークがその DR と直接隣接を張れず LSDB が同期しない** — スポーク同士のマルチキャストは届かない

### 語群の残り(どの空欄にも入らない)

- D. Phase 1= broadcast / Phase 2・3= point-to-multipoint — 教材の定石どおり
- G. ホスト経路を広告しない — p2mp は /32 のホスト経路を広告し next-hop は自分
- E. hello の間隔が変わって隣接が落ちる — スポーク同士のマルチキャストは届かない
- B. 全 Phase で point-to-point — 教材の定石どおり
- H. DR を必要とする — p2mp は /32 のホスト経路を広告し next-hop は自分
