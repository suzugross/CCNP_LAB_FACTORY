## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/filter` — 再配送リングの定常ループ(ring=inject_eigrp)
- 機構: `192.168.42.0/24` は RT05 が BGP 起点広告 → RT03 が iBGP(AD 200) で学習。
  RT03 が BGP を EIGRP へ再配送し、RT02 の相互再配送で
  出自が一周。戻ってきた O E2 (AD 110) が iBGP(200) に勝って RT03 が採用
  → 定常転送ループ RT03 → RT01 → RT02 → RT03。
- 出題形式: cause(機構(原因)を選ばせる。錯乱肢に「そもそもループでない」機構=等コスト分散・遠回りと、結果を原因と取り違える RIB-failure を混入)

  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 936214`
  (sub-seed 4221562 / 展開パック PAPER-RD-4221562・撤収済)
- 赤ニシン: RT01・RT03・RT06 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)

## 各選択肢の判定

- **A**: 経路表の経過時間は単調に進行しており、再学習(タイマーのリセット)の痕跡がない。定常状態のループである。
- **B**: (正解)
- **C**: 等コスト分散であれば宛先には到達する。示された traceroute は同一のホップ列を反復しており、分散ではなく周回である。
- **D**: 遠回りであっても宛先には到達する。到達していない以上、経路の優劣ではなく転送の周回が生じている。
- **E**: 外部経路タイプは同一プロトコル内の優劣に影響するに過ぎず、iBGP と IGP 外部経路の比較は管理距離で決まる。
- **F**: RT03 の BGP テーブルに当該プレフィックスが存在する(広告は届いている)。

## 検証コマンドと期待される出力

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
