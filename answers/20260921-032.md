## 解説

### 完成文: PE の MP-BGP 設定と各アドレスファミリが担う範囲

```
vrf definition ACME
 rd 64512:20
 address-family ipv4
  route-target export 64512:200
  route-target import 64512:200
!
interface GigabitEthernet0/1
 vrf forwarding ACME
 ip address 192.168.1.1 255.255.255.252
!
router bgp 64512
 neighbor 192.168.255.2 remote-as 64512
 neighbor 192.168.255.2 update-source Loopback0
 !
 address-family ［①］vpnv4
  neighbor 192.168.255.2 ［②］activate
  neighbor 192.168.255.2 send-community extended
 !
 address-family ipv4 vrf ACME
  neighbor 192.168.1.2 remote-as 65001
  neighbor 192.168.1.2 ［②］activate
  neighbor 192.168.1.2 as-override
```

上は PE1 の設定である。`address-family **［①］vpnv4**` 配下のネイバー 192.168.255.2 は **［③］プロバイダ網内(PE-PE の iBGP)** に属する対向 PE で、この AF で VRF ACME の経路が RD 64512:20 付きの VPNv4 経路と VPN ラベルとして交換される。RT は BGP の拡張コミュニティなので、この AF で `send-community extended` が無いと RT が伝わらず、対向 PE はどの VRF にも取り込めない。ネイバーアドレスに Loopback0 の /32 アドレスを使うのは、その /32 に対して LDP が配るラベルがそのまま VPN パケットのトランスポートラベルになるからである。`address-family ipv4 vrf ACME` 配下のネイバー 192.168.1.2 は **［④］顧客側(PE-CE の eBGP)** に属し、ここで学んだ経路は VRF ACME の経路表にだけ入る。両拠点の CE が同じ AS 65001 を使うため、PE から CE へ広告する際に as-override で AS_PATH 中の 65001 を 64512 に書き換えないと、受け取った CE が自 AS を見つけてループ検出で捨ててしまう。

### 各空欄の要点

- ① = **E. vpnv4** — PE-PE で VPNv4 経路を交換する AF は vpnv4
- ② = **G. activate** — AF でネイバーを有効化するのは activate。next-hop-self は iBGP の次ホップ書き換え
- ③ = **H. プロバイダ網内(PE-PE の iBGP)** — vpnv4 のピアは同一 AS の PE 同士(iBGP)。P とは BGP を張らない
- ④ = **A. 顧客側(PE-CE の eBGP)** — ipv4 vrf 配下は CE との eBGP

### 語群の残り(どの空欄にも入らない)

- B. ipv4 vrf ACME — PE-PE で VPNv4 経路を交換する AF は vpnv4
- F. route-reflector-client — AF でネイバーを有効化するのは activate。next-hop-self は iBGP の次ホップ書き換え
- C. P ルータとの間 — vpnv4 のピアは同一 AS の PE 同士(iBGP)。P とは BGP を張らない
- D. next-hop-self — AF でネイバーを有効化するのは activate。next-hop-self は iBGP の次ホップ書き換え
