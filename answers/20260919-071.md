## 解説

### 完成文: 認可(authorization)の構成で変わるログイン後の権限

(この盤面の世界: **exec 認可はあるがフォールバック(local)が無い** — 同じ kind でも世界が違えば正解が変わる)

```
aaa new-model
aaa authentication login default group AAA-SRV local
aaa authorization exec default group AAA-SRV
aaa authorization console
username emg-admin privilege 15 secret 9 $9$xxxx      ! local だけに存在
! サーバ台帳: noc-taro= shell:priv-lvl=15 / helpdesk= shell:priv-lvl=1
```

認証が通ってもログイン後の権限は認可が決める。サーバは Access-Accept に **［①］shell:priv-lvl=15** を付けて返す。この盤面でサーバが正常なとき、noc-taro がログインした直後の権限レベルは 15(特権 EXEC)、helpdesk は 1(ユーザ EXEC)。サーバが 2 台とも無応答のとき、local だけにいる emg-admin は認証には通り、その後 EXEC を拒否され入れない(local ユーザも締め出し)。この構成に対する評価は **［②］exec 認可の末尾に local(または if-authenticated)を追加すべき**。なお認証は local で通っても、認可がサーバへ照会して **［③］拒否(Reject)** された場合は EXEC が拒否される(拒否は権威の原則)。コンソールは **［④］aaa authorization console** が無いと exec 認可自体が実行されない。

### 各空欄の要点

- ① = **D. shell:priv-lvl=15** — 権限レベルを運ぶ属性
- ② = **C. exec 認可の末尾に local(または if-authenticated)を追加すべき** — 全断時に全員締め出し
- ③ = **H. 拒否(Reject)** — 認可の Reject も確定
- ④ = **B. aaa authorization console** — コンソール認可の明示

### 語群の残り(どの空欄にも入らない)

- E. Framed-Protocol=PPP — 権限レベルを運ぶ属性
- A. aaa authorization exec default group AAA-SRV local を追加すべき — 全断時に全員締め出し
- F. タイムアウト — 認可の Reject も確定
- G. line con 0 の privilege level 15 — コンソール認可の明示
