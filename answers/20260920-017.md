# 解答 20260920-017

## 解説

### 完成文: SNMPv3 のセキュリティレベルと group/host のキーワード

| セキュリティレベル | 守られるもの | group / host で書くキーワード |
|---|---|---|
| noAuthNoPriv | **［①］ユーザ名の一致だけを確認する(合言葉に相当)** | noauth |
| authNoPriv | **［②］HMAC-MD5/HMAC-SHA で認証するが暗号化はしない** | auth |
| authPriv | 認証に加えて DES/3DES/AES で暗号化する | priv |

SNMPv3 は USM(User-based Security Model)でユーザごとに保護の強さを選ぶ。v1/v2c はコミュニティ文字列を **［③］平文** で送るので、v3 で言えば表の最上段と同じ強さしかない。装置では group にレベルのキーワードを書き、それが **［④］そのグループが受け付ける最低のセキュリティレベル** になる。その group に属するユーザが、group より低い(弱い) セキュリティレベルで要求を送ると authorizationError で拒否され(実測)、より強いレベルの要求はそのまま受け付けられる。認証と暗号の鍵はユーザ作成時にパスワードから **［⑤］engineID を混ぜた局所化(localized key)** で導出されるため、engineID を変更すると既存ユーザのダイジェストは無効になり作り直しになる。認証アルゴリズムは MD5 か SHA、暗号は DES/3DES/AES(128/192/256)から選ぶ。

### 各空欄の要点

- ① = **E. ユーザ名の一致だけを確認する(合言葉に相当)** — noAuthNoPriv= 認証も暗号化も無し。ユーザ名の照合のみ
- ② = **C. HMAC-MD5/HMAC-SHA で認証するが暗号化はしない** — authNoPriv= 認証あり・暗号化なし(盗聴はできるが改ざん・なりすましは防ぐ)
- ③ = **H. 平文** — コミュニティは平文。だから v3 が要る
- ④ = **B. そのグループが受け付ける最低のセキュリティレベル** — group の priv は「priv 以上で来い」の意味
- ⑤ = **J. engineID を混ぜた局所化(localized key)** — 鍵はパスワード+engineID から作る。engineID が変わると鍵が合わなくなる

### 語群の残り(どの空欄にも入らない)

- A. ハッシュ化した形 — コミュニティは平文。だから v3 が要る
- F. 通知(trap)を送るときのレベル — group の priv は「priv 以上で来い」の意味
- D. サーバ証明書の検証 — 鍵はパスワード+engineID から作る。engineID が変わると鍵が合わなくなる
- G. ユーザが使える最高のセキュリティレベル — group の priv は「priv 以上で来い」の意味
- I. 誰でも読める(ユーザ名も見ない) — noAuthNoPriv= 認証も暗号化も無し。ユーザ名の照合のみ
