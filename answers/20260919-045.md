### 完成文: show mpls ldp neighbor detail の読み方

```
P2# show mpls ldp neighbor detail
    Peer LDP Ident: 10.0.0.3:0; Local LDP Ident 10.0.0.4:0
        TCP connection: 10.0.0.3.646 - 10.0.0.4.14709; MD5 on
        State: Oper; Msgs sent/rcvd: 1020/1019; Downstream
        Up time: 02:13:40
        LDP discovery sources:
          Ethernet0/1; Src IP addr: 10.0.34.3
            holdtime: 15000 ms, hello interval: 5000 ms
        Addresses bound to peer LDP Ident:
          10.0.0.3        10.0.13.3       10.0.34.3
        Peer holdtime: 180000 ms; KA interval: 60000 ms; Peer state: estab
```

上は P2 で採った出力である。`Peer LDP Ident` の値は相手の LDP ルータ ID とラベル空間 ID の組で、末尾の :0 は **［①］プラットフォーム全体のラベル空間** を意味する。`TCP connection` の行で、ポート 646 で待ち受けているのは 10.0.0.3 側で、もう一方の一時ポートを使っている **［②］10.0.0.4** 側が接続を開始した。これはルータ ID(トランスポートアドレス)の **［③］大きい** 方がアクティブになる規則と一致する。`MD5 on` はセッション認証が有効なことを示す。`State: Oper` はセッション確立済み、`Downstream` はラベル配布が **［④］Downstream Unsolicited** であることを示す。`LDP discovery sources` は Hello を受け取ったインターフェースと送信元で、その下の一覧は相手が持つ全アドレスである。この一覧が重要なのは、自分の RIB のネクストホップ(例: 10.0.34.3)が Addresses bound to peer に含まれていて初めて、相手から受けたラベルを LFIB に採用できるからである。

### 各空欄の要点

- ① = **G. プラットフォーム全体のラベル空間** — :0 = per-platform label space
- ② = **F. 10.0.0.4** — 一時ポート 14709 側= 10.0.0.4 が接続を開始(アクティブ)
- ③ = **E. 大きい** — 10.0.0.4 > 10.0.0.3 なので 10.0.0.4 がアクティブ
- ④ = **B. Downstream Unsolicited** — Downstream 表示= DU モード

### 語群の残り(どの空欄にも入らない)

- A. VRF 番号 — :0 = per-platform label space
- D. 10.0.0.3 — 一時ポート 14709 側= 10.0.0.4 が接続を開始(アクティブ)
- H. 小さい — 10.0.0.4 > 10.0.0.3 なので 10.0.0.4 がアクティブ
- C. Downstream on Demand — Downstream 表示= DU モード
