## 解説

### 完成文: IPv6 source guard の前提と動作

```
ipv6 source-guard policy SG-HOSTS
 permit link-local
 deny global-autoconf
!
interface GigabitEthernet1/0/10
 ipv6 source-guard attach-policy SG-HOSTS
```

IPv6 source guard は、ポートに入ってきたデータパケットの送信元アドレスがバインディングテーブルに載っていない場合にそのパケットを破棄する。ND や DHCPv6 のメッセージ自体は検査しない。表は ND inspection や DHCPv6 のグリーニングが作るので、それらが無いと **［①］正当な端末も全部落ちる**。拒否が起きたとき、スイッチは正当な端末の見落としを避けるために、**［②］DHCP サーバへの照会または ND** によって束縛の復元を試みる。ポリシーには「リンクローカル送信元は表に無くても通す」指定や、**［③］SLAAC で自動生成した GUA を送信元とするパケットを拒否する** を意味する指定を副コマンドとして書ける(上の設定例)。同じ枠組みで送信元の「プレフィックス」がこのリンクに正当かを検査するのが IPv6 prefix guard で、RA や DHCPv6 PD から学んだプレフィックスの範囲外を落とす。IPv4 の **［④］IP Source Guard(DHCP snooping 連携)** に相当する機能と考えると位置づけが分かりやすい。

### 各空欄の要点

- ① = **C. 正当な端末も全部落ちる** — 表が空= 全拒否
- ② = **H. DHCP サーバへの照会または ND** — 復元は DHCP 照会か ND(公式記述)
- ③ = **D. SLAAC で自動生成した GUA を送信元とするパケットを拒否する** — global-autoconf= 自動設定のグローバルアドレス
- ④ = **E. IP Source Guard(DHCP snooping 連携)** — IPv4 で送信元を束縛表で検証するのは IP Source Guard。DAI は ARP 検査(= ND inspection 相当)

### 語群の残り(どの空欄にも入らない)

- A. 自動で表が作られる — 表が空= 全拒否
- B. RA の再送要求 — 復元は DHCP 照会か ND(公式記述)
- F. リンクローカルを拒否する — global-autoconf= 自動設定のグローバルアドレス
- G. DAI(Dynamic ARP Inspection) — IPv4 で送信元を束縛表で検証するのは IP Source Guard。DAI は ARP 検査(= ND inspection 相当)
