## 解説

### 完成文: サーバの死活判定(dead-criteria と deadtime)と show aaa servers

(この盤面の世界: **dead-criteria あり(1 台目が DEAD になり 2 台目へ直行)** — 同じ kind でも世界が違えば正解が変わる)

```
radius-server timeout 3
radius-server retransmit 1
radius-server dead-criteria time 3 tries 1
aaa group server radius AAA-SRV
 server name RAD1
 server name RAD2
 deadtime 5
!
RT01# show aaa servers
RADIUS: id 1, priority 1, host 10.99.1.2, auth-port 1812, acct-port 1813, hostname RAD1
     State: current DEAD, duration 312s, previous duration 0s
RADIUS: id 2, priority 2, host 10.99.2.2, auth-port 1912, acct-port 1913, hostname RAD2
     State: current UP, duration 4021s, previous duration 0s
```

RAD1(10.99.1.2)が停止して 5 分ほど経っている。**［①］radius-server dead-criteria time/tries** は「何秒応答が無く、何回失敗したら DEAD とみなすか」の条件で、**［②］deadtime** は DEAD とみなしたサーバを何分間スキップするかである。この 2 つは片方だけでは機能しない。上の出力で RAD1 の State が DEAD(スキップ対象) なのは **［③］判定条件(time 3・tries 1)を満たした** ためで、いまログインすると待ち時間は 6 秒程度(RAD2 の分だけ)。この構成に対する評価は意図どおり(是正不要)。RAD2 のポート 1912/1913 のように **［④］非標準ポート** は許され、サーバ側と一致していれば動く。なお DEAD は「応答が無かった」の判定であって、UP でも認証できないこと(鍵不一致など)はある。

### 各空欄の要点

- ① = **A. radius-server dead-criteria time/tries** — DEAD 判定条件
- ② = **G. deadtime** — スキップする時間(分)
- ③ = **F. 判定条件(time 3・tries 1)を満たした** — dead-criteria が DEAD を作る
- ④ = **H. 非標準ポート** — auth-port/acct-port は任意

### 語群の残り(どの空欄にも入らない)

- C. radius-server timeout — DEAD 判定条件
- B. retransmit — スキップする時間(分)
- E. deadtime 5 分が経過した — dead-criteria が DEAD を作る
- D. IPv6 アドレス — auth-port/acct-port は任意
