## 解説

### 完成文: 「入れるか」より「何秒待ったか」が原因を指す

```
RT01# test aaa group RADGRP noc-taro Adm-9876 legacy
Attempting authentication test to server-group RADGRP using radius
［①］No authoritative response from any server.

(参考) radius-server timeout 3 / radius-server retransmit 1 / グループ内サーバ 2 台
```

`test aaa` の応答は 3 種類しかない。即座(0.1 秒)に返る「User was successfully authenticated.」、約 1 秒で返る「User authentication request was rejected by server.」、そして約 12 秒待って返る「**［①］No authoritative response from any server.**」である。3 つ目の秒数は **［②］timeout 3 秒× (1+再送 1)回× 2 台** から来る。ログインの見え方も同じ 3 値で、拒否なら local に同じユーザがいても入れない、無応答なら 12 秒ほど待たされたあと **［③］local のユーザなら入れる**。したがって「待たされて入れた」は **［④］サーバに届いていない/鍵不一致/ポート違い** を、「すぐ弾かれた」はユーザ未登録やパスワード誤り(サーバが拒否) を疑う。厄介なのは共有鍵の不一致で、サーバは実は Reject を返しているのに、装置は鍵が違うため応答の Response Authenticator を検証できず捨てる。結果として装置側は「無応答」と全く同じ文言・同じ秒数になり、送信元アドレスの誤り(サーバ側で unknown client として破棄)とはサーバ側のログでしか区別できない。

### 各空欄の要点

- ① = **E. No authoritative response from any server.** — 無応答の文言(実測)
- ② = **A. timeout 3 秒 × (1+再送 1)回 × 2 台** — 3×2×2= 12 秒
- ③ = **H. local のユーザなら入れる** — 無応答は次メソッド(local)へ
- ④ = **D. サーバに届いていない/鍵不一致/ポート違い** — 待ち= 無応答系

### 語群の残り(どの空欄にも入らない)

- F. User was successfully authenticated. — 無応答の文言(実測)
- B. deadtime 5 分の一部 — 3×2×2= 12 秒
- G. サーバ台帳のユーザだけ入れる — 無応答は次メソッド(local)へ
- C. ユーザ未登録 — 待ち= 無応答系
