# 解答 20260906-012

## 正解

**B**

## 仕込んだ状態

- 種別: `riploop/wrong_tag_filter` — RIP⇄OSPF 二点相互再配送の「対策が効いていない」型
  (GEN-REDISTRO 盤面の紙面化・BL-116)
- 出題形式: fix
- 機構: タグ運用は実装済み(RIP 発= 100 / OSPF 発= 180 を set tag)だが、OSPF→RIP の deny エントリが `match tag 10` を参照しており、実際に経路へ付与されるタグ 100 と一致しない。遮断が素通りになり、(1)一方の境界が O E2(AD 110)のフィードバックを RIP(120)より優先して遠回りになり、(2)その境界がフィードバックを RIP へ再広告し続ける(**対策が存在するのに効いていない**のが本題)。★実測(2026-08-13)= ラボ版の seed metric 1 だと両境界の状態が入れ替わる振動になるため、紙面盤面は seed 5 で安定化してある。
- 正解法: RT01 と RT04 の両方で `route-map OSPF2RIP deny 10` の match tag を 100 へ修正する(タグ設計を意図どおりに機能させる)。
- 生成: `gen_paper_mcq.py --shape riploop --seed 198117585`
  (sub-seed 1187770 / 展開パック PAPER-RD-1187770・撤収済)

## 各選択肢の判定

- **A**: 経路の劣後は強まるが、フィードバックの経路が RIP へ広告されること自体は続き、再配送の時点での拒否という要件を満たさない。
- **B**: (正解)
- **C**: もう一方の境界の遮断は壊れたままであり、「両方の境界で機能させる」という要件を満たさない(境界の役割が入れ替われば再注入も再発する)。
- **D**: 修正の対象が逆方向の route-map であり、問題の再注入(OSPF→RIP)はそのまま残る。さらに OSPF 発の経路への遮断が壊れる。
- **E**: 構成に起因する定常状態であり、再計算しても同じ選択に戻る。
- **F**: 境界の選好は正されるが、管理距離は変更の凍結の対象であり、また出自による遮断(タグ)が機能していない状態は残る。

## 教育核心

ring(AD 反転)・mploop(同AD・メトリック差)と違い、この形は**対策そのものは
構成に存在する**(あるいは存在した痕跡がある)。読み筋は、症状の型で層を
当てること — **周回(TTL 超過)**ならタグ/seed の層、**遠回り**なら選好(AD)の層、
**偏り**なら広告の抑止。そのうえで「対策が機能している証拠」(match tag の一致・
適用の範囲・残置物)を、config と `show route-map` / `show ip protocols` で
突き合わせる。二点相互再配送の対策は**両方の境界に対**で入って初めて完成する。
