### 完成文: 稼働中の FNF を変更するときの手順(使用中オブジェクトのロック)

```
RT02(config)# flow record REC-CORP
RT02(config-flow-record)# match ipv4 tos
% Object is in use
RT02(config-flow-record)# exit
RT02(config)# interface Ethernet0/2
RT02(config-if)# no ip flow monitor MON-CORP input
RT02(config-if)# flow record REC-CORP
RT02(config-flow-record)# match ipv4 tos

```

レコードのキーを 1 つ追加しようとして拒否された場面である。使用中のレコードのフィールドは参照しているモニタが存在する限り変更できない。上のように IF から外しただけでは足りず(実測)、変更するには **［①］モニタで no record(参照解除)→レコードを編集→モニタに record を戻す** という 3 段が要る。モニタ側の record 行も別名で上書きできないので、レコードを差し替えるときは no record → record の 2 段で書く。エクスポータは扱いが違い、destination・source・transport udp は参照されたままでも変更できるが、**［②］export-protocol** だけは参照中は変更できない。新規に組むときは **［③］record → exporter → monitor → IF 適用** の順に投入すれば、このロックには当たらない。変更後は **［④］show flow monitor MON-CORP cache** でフローが採れているかを確認する。

### 各空欄の要点

- ① = **D. モニタで no record(参照解除)→ レコードを編集 → モニタに record を戻す** — 解錠するのは参照解除。IF の付け外しでは解けない(実測)
- ② = **G. export-protocol** — netflow-v9⇄ipfix の切替は参照中不可(実測)
- ③ = **C. record → exporter → monitor → IF 適用** — 参照される側を先に作る
- ④ = **A. show flow monitor MON-CORP cache** — 採取の確認はキャッシュ

### 語群の残り(どの空欄にも入らない)

- E. clear flow monitor → レコードを編集 → write memory — 解錠するのは参照解除。IF の付け外しでは解けない(実測)
