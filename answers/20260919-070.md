## 解説

### 完成文: Dropped カウンタの理由から原因を読む

(この盤面の世界: **GW ポートで RA が unauthorized on port で落ちている(host 扱い)** — 同じ kind でも世界が違えば正解が変わる)

```
SW# show device-tracking counters interface GigabitEthernet1/0/1
Received messages on GigabitEthernet1/0/1:
  Protocol  Protocol message
  NDP       RS[12] RA[40] NS[8] NA[8]
Dropped messages on GigabitEthernet1/0/1:
  Feature     Protocol Msg [Total dropped]
  RA guard    NDP      RA  [40]
     reason: Message unauthorized on port [40]

SW# show device-tracking counters interface GigabitEthernet1/0/12
Dropped messages on GigabitEthernet1/0/12:
  Feature     Protocol Msg [Total dropped]
  RA guard    NDP      RA  [15]
     reason: Message unauthorized on port [15]
  DHCP Guard  DHCPv6   REP [6]
     reason: Message type is not authorized by the policy on this port, device-role mismatch [6]
```

上は GW がつながる GigabitEthernet1/0/1 と、不正端末がつながる GigabitEthernet1/0/12 のカウンタである。GigabitEthernet1/0/12 側は **［①］意図どおり(不正 RA と偽 REPLY が落ちている)**。GigabitEthernet1/0/1 側の Dropped から読める状態は GW ポートが host 扱い(host を付けた、または VLAN の host だけが効いている) で、是正は GigabitEthernet1/0/1 にポート側で device-role router(または trusted-port)のポリシーを付ける。このとき端末はリンクローカルだけで GUA も既定 GW も無い。RA guard で落ちる理由は大きく 2 つあり、「Message unauthorized on port」は **［②］そのポート(の役割)では RA を受け付けない**、「Preference flag error」は **［③］RA の優先度が上限を超えた** を意味する。端末側の症状はどちらも同じなので、見分けるのは **［④］Dropped の理由文字列** である。

### 各空欄の要点

- ① = **C. 意図どおり(不正 RA と偽 REPLY が落ちている)** — 不正端末側で RA と REP が落ちるのは正常動作
- ② = **H. そのポート(の役割)では RA を受け付けない** — host 扱いのポートで RA を受けた
- ③ = **F. RA の優先度が上限を超えた** — router-preference maximum 超過
- ④ = **G. Dropped の理由文字列** — 理由が違えば是正も違う

### 語群の残り(どの空欄にも入らない)

- A. 無防備(何も落ちていない) — 不正端末側で RA と REP が落ちるのは正常動作
- D. prefix-list に無いプレフィックスだった — host 扱いのポートで RA を受けた
- B. ホップリミットが範囲外だった — router-preference maximum 超過
- E. show running-config — 理由が違えば是正も違う
