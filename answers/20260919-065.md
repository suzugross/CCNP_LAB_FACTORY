## 解説

### 完成文: RA guard ポリシーの意味と適用先

(この盤面の世界: **GW ポートに端末用(host)ポリシーを付けてしまった** — 同じ kind でも世界が違えば正解が変わる)

```
ipv6 nd raguard policy RAG-HOST
 device-role host
ipv6 nd raguard policy RAG-UPLINK
 device-role router
 router-preference maximum medium
!
interface GigabitEthernet0/1
 ipv6 nd raguard attach-policy RAG-HOST
interface GigabitEthernet0/2
 ipv6 nd raguard attach-policy RAG-HOST
interface GigabitEthernet0/4
 ipv6 nd raguard attach-policy RAG-HOST
```

上はアクセススイッチの設定で、GigabitEthernet0/1 に正規 GW、GigabitEthernet0/2 に端末、GigabitEthernet0/4 に不正端末がつながる(全ポート VLAN 30)。RA guard は **［①］着信(ingress)** 方向でだけ働く。不正端末が GigabitEthernet0/4 から送る RA は **［②］端末ポートの host ポリシーで破棄される**。正規 GW が GigabitEthernet0/1 から送る RA は **［③］GW ポートに付いた host ポリシーで無条件に破棄される**。その結果、端末 GigabitEthernet0/2 はリンクローカルだけで GUA も既定 GW も無い。この盤面で `show device-tracking counters interface GigabitEthernet0/1` の Dropped 欄には **［④］Message unauthorized on port が出る**。是正として妥当なのは GigabitEthernet0/1 のポリシーを device-role router のものに付け替える。なおポートと VLAN の両方にポリシーがあるときはポートのポリシーが勝ち、検査を一切しないポートにしたいときは device-role の代わりに trusted-port を書く。

### 各空欄の要点

- ① = **C. 着信(ingress)** — RA guard は ingress のみ
- ② = **H. 端末ポートの host ポリシーで破棄される** — 不正端末側は host 扱いなので RA は捨てられる
- ③ = **A. GW ポートに付いた host ポリシーで無条件に破棄される** — host は RA を無条件に捨てる
- ④ = **F. Message unauthorized on port が出る** — host 扱いのポートで RA を受けた理由文字列(実測)

### 語群の残り(どの空欄にも入らない)

- D. 双方向 — RA guard は ingress のみ
- E. VLAN の host ポリシーで破棄される — 不正端末側は host 扱いなので RA は捨てられる
- B. ポート側にポリシーが無く VLAN の host が効いて破棄される — host は RA を無条件に捨てる
- G. Preference flag error が出る — host 扱いのポートで RA を受けた理由文字列(実測)
