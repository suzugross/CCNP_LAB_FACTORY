## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/distance` — 再配送リングの定常ループ(ring=inject_ospf)
- 機構: `192.168.228.0/24` は RT01 が BGP 起点広告 → RT05 が iBGP(AD 200) で学習。
  RT05 が BGP を OSPF へ再配送し、RT02 の相互再配送で
  出自が一周。戻ってきた D EX (AD 170) が iBGP(200) に勝って RT05 が採用
  → 定常転送ループ RT05 → RT02 → RT03 → RT05。
- 出題形式: fix(是正手順を選ばせる)
- 正解法: distance(distance=iBGP の AD を戻り 170 未満へ /
  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 88105`
  (sub-seed 9211394 / 展開パック PAPER-RD-9211394・撤収済)
- 赤ニシン: RT03・RT04・RT05 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)
- AD操作世界(BL-118): adworld=stale_proto — 前任者の残骸= RT05 の router ospf 60 に「distance ospf external 212」。効いていない(ループの勝者は不変)。既定 AD の暗記では解けず、show ip protocols / 設定抜粋からの実効 AD の読取りが決め手。

## 各選択肢の判定

- **A**: RT02 は当該外部経路の広告側で、自身の RIB 選好を変えてもループの分岐点である RT05 の経路選択には影響しない。
- **B**: 定常ループは経路の構造(戻り外部経路の AD が iBGP に勝つ)に起因するため、再収束後も同一の状態に戻る。一時対処にもならない。
- **C**: BGP から IGP への注入そのものを止めるため、IGP 側の全ルータが `192.168.228.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない(戻りの遮断と注入の遮断の混同)。
- **D**: 残存する distance が対象とするのは OSPF の外部経路であり、戻り経路は EIGRP の外部経路(管理距離 170)として学習されている。対象が誤っている以上、値を変えても勝者は変わらない。
- **E**: iBGP 学習経路の IGP への注入が止まりループは解消するが、IGP 側の全ルータが `192.168.228.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない。
- **F**: (正解)

## 検証コマンドと期待される出力

- RT05: `show ip route 192.168.228.0` が `Known via "bgp 65450"` に変わること
  (是正前は `Known via "eigrp"`)。
- 任意ルータから `traceroute 192.168.228.1` が RT01 まで一直線(是正前はリングを周回)。
- distance 解の場合、投入だけでは BGP 表の `r>`(RIB-failure) が残るため
  `clear ip route *`(または clear ip bgp)で再計算が要る。
- tag 解の場合、RT05 で `Known via "bgp"` に変わり、かつ RT02 は当該網を
  引き続き保持していること(戻りの再注入だけが止まる)を見る。
  タグの付与だけでは何も変わらない(deny 側が本体)。

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
