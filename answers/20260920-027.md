## 解説

### 完成文: NHRP の役割: 登録・解決・Redirect と主要パラメータ

DMVPN のスポークは 2 つのアドレスを持つ。トンネルの内側のトンネル IP と、外側の NBMA アドレス(tunnel source の物理/WAN アドレス) である。起動したスポークはハブ(**［①］Next Hop Server**)に Registration Request を送り、自分のトンネル IP と外側アドレスの対応を登録する。スポーク間通信では、送信元スポークが Resolution Request で相手のトンネル IP に対応する外側アドレスを問い合わせ、その応答は解決先のスポークから直接返ってくる(これで両者の動的トンネルが張れる)。Phase 3 ではハブがスポーク宛のパケットを中継したときに NHRP Redirect(Traffic Indication) を送信元へ送り、スポークの解決を促す。登録や解決の応答には **［②］ip nhrp holdtime の値** が載り、相手側キャッシュの保持時間になる(既定 **［③］7200** 秒・登録はその 1/3 ごとに再送)。`ip nhrp network-id` は **［④］ローカル有意(ワイヤに乗らない)** なので、hub と spoke で値が違っても登録も通信も成立する(実測)。`ip nhrp authentication` は **［⑤］最大 8 文字** で、値が一致しないと登録要求はエラーも返さずに黙殺される(実測)。`tunnel key` は GRE のキーで、不一致だと GRE 自体を受け入れないため NHRP 登録に進めない。
