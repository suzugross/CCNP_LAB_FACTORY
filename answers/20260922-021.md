## 解説

### 完成文: PVST+ / Rapid PVST+ / MST(802.1s)の使い分けとリージョン

```
spanning-tree mode mst
!
spanning-tree mst configuration
 name REGION1
 revision 2026
 instance 1 vlan 10,20
 instance 2 vlan 30,40
!
spanning-tree mst 1 priority 24576
spanning-tree mst 2 priority 28672
```

Cisco スイッチの既定の STP モードは **［①］PVST+(per-VLAN 802.1D)** で、VLAN ごとに独立した 802.1D の木を作る。`spanning-tree mode rapid-pvst` にすると VLAN ごとの木のまま RSTP になる。VLAN が多いと木の数だけ BPDU と計算が増えるので、複数の VLAN を 1 つのインスタンスにまとめるのが **［②］MST(Multiple Spanning Tree)**(802.1s)である。上の設定では VLAN 10 と 20 の木が 1 本、30 と 40 の木が 1 本になり、それぞれ root を変えて負荷分散している。どのインスタンスにも書かれていない VLAN(例: VLAN 50)は **［③］IST(instance 0)** に属する。同じリージョンと見なされるには **［④］リージョン名・revision 番号・VLAN とインスタンスの対応表** の 3 つが完全に一致する必要があり、1 つでも違うスイッチは別リージョン扱いになって、その間のポートは **［⑤］boundary port(境界ポート)** になる。リージョン間や 802.1D/PVST+ との接続には CIST(Common and Internal Spanning Tree) が 1 本だけ張られ、外から見ると各リージョンは 1 台の巨大なスイッチに見える。設定の確認は `show spanning-tree mst configuration` で、変更は `exit` でサブモードを抜けるまで反映されない。

### 各空欄の要点

- ① = **A. PVST+(per-VLAN 802.1D)** — `spanning-tree mode pvst` が既定
- ② = **I. MST(Multiple Spanning Tree)** — インスタンスごとに 1 本の木・VLAN を束ねる
- ③ = **G. IST(instance 0)** — 未割当 VLAN は全部 instance 0
- ④ = **J. リージョン名・revision 番号・VLAN とインスタンスの対応表** — 3 つのダイジェストが BPDU に載って比較される
- ⑤ = **B. boundary port(境界ポート)** — 境界では CIST の BPDU だけを交換する

### 語群の残り(どの空欄にも入らない)

- F. CIST の外 — 未割当 VLAN は全部 instance 0
- H. ホスト名・revision 番号・priority — 3 つのダイジェストが BPDU に載って比較される
- E. edge port — 境界では CIST の BPDU だけを交換する
- D. backup port — 境界では CIST の BPDU だけを交換する
- C. Rapid PVST+ — `spanning-tree mode pvst` が既定
