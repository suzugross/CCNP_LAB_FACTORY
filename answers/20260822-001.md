## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/filter` — 再配送リングの定常ループ(ring=inject_eigrp)
- 機構: `192.168.151.0/24` は RT07 が BGP 起点広告 → RT03 が iBGP(AD 200) で学習。
  RT03 が BGP を EIGRP へ再配送し、RT01 の相互再配送で
  出自が一周。戻ってきた O E2 (AD 110) が iBGP(200) に勝って RT03 が採用
  → 定常転送ループ RT03 → RT05 → RT01 → RT03。
- 出題形式: fix(是正手順を選ばせる)
- 正解法: filter(distance=iBGP の AD を戻り 110 未満へ /
  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 705304214`
  (sub-seed 6794281 / 展開パック PAPER-RD-6794281・撤収済)
- 赤ニシン: RT02・RT03・RT05 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)

## 各選択肢の判定

- **A**: 出自の一周は止まるが、RT01 の先のドメインの各ルータが `192.168.151.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない。
- **B**: 定常ループは経路の構造(戻り外部経路の AD が iBGP に勝つ)に起因するため、再収束後も同一の状態に戻る。一時対処にもならない。
- **C**: BGP から IGP への注入そのものを止めるため、IGP 側の全ルータが `192.168.151.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない(戻りの遮断と注入の遮断の混同)。
- **D**: 到達性・ループとも解消する(症状は直る)が、監査要件「管理距離(distance)の変更禁止」に違反する。
- **E**: iBGP 学習経路の IGP への注入が止まりループは解消するが、IGP 側の全ルータが `192.168.151.0/24` への経路を失い、要件「全拠点からの到達性」を満たさない。
- **F**: (正解)

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
