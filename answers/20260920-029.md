## 解説

### 完成文: ハブの Tunnel 設定と Phase の判定(EIGRP)

(この盤面の世界: **Phase 2(ハブが next-hop を書き換えない・スポークに shortcut なし)** — 同じ kind でも世界が違えば正解が変わる)

```
! Hub
interface Tunnel0
 ip address 10.200.0.1 255.255.255.0
 no ip redirects
 ip mtu 1400
 ip tcp adjust-mss 1360
 ip nhrp authentication DMVPNKEY
 ip nhrp map multicast dynamic
 ip nhrp network-id 1
 ［①］no ip next-hop-self eigrp 1
 no ip split-horizon eigrp 1
 tunnel source Ethernet0/0
 tunnel mode gre multipoint
 tunnel key 65001
 tunnel protection ipsec profile IPSEC-DMVPN
!
! Spoke(抜粋): ip nhrp nhs 10.200.0.1 nbma 10.0.14.1 multicast / tunnel mode gre multipoint
!              (ip nhrp shortcut は設定されていない)
```

この構成は Phase **［②］2** である。ip nhrp map multicast dynamic は **［③］登録してきたスポークの NBMA を Hello などマルチキャストの宛先に自動で加える** ための行で、これが無いとスポークはハブからの Hello を受け取れず隣接が片側だけになる。no ip split-horizon eigrp 1 は **［④］同じ Tunnel から学んだスポークの経路を、他のスポークへ同じ Tunnel から広告する** ために要る(Phase に関係なく必須)。**［①］no ip next-hop-self eigrp 1** が Phase を決める行で、スポークが持つ対向スポークの LAN 経路の next-hop は **［⑤］対向スポークのトンネル IP** になる。この Phase でハブが対向スポークの経路を集約することはできない(集約すると next-hop がハブになり直接通信が消える)。tunnel key は全メンバで一致させ、`no ip redirects` は Tunnel 上で ICMP Redirect を出さないための定石である。

### 各空欄の要点

- ① = **H. no ip next-hop-self eigrp 1** — スポークに shortcut が無いので Phase 2。ハブは next-hop を書き換えない
- ② = **A. 2** — shortcut なし・next-hop-self 無効= Phase 2
- ③ = **I. 登録してきたスポークの NBMA を Hello などマルチキャストの宛先に自動で加える** — スポークごとの map multicast を書かずに済む
- ④ = **J. 同じ Tunnel から学んだスポークの経路を、他のスポークへ同じ Tunnel から広告する** — 距離ベクタの split horizon をハブで解除
- ⑤ = **B. 対向スポークのトンネル IP** — Phase 2 の署名= next-hop が対向スポーク

### 語群の残り(どの空欄にも入らない)

- F. 3 — shortcut なし・next-hop-self 無効= Phase 2
- D. ip nhrp redirect — スポークに shortcut が無いので Phase 2。ハブは next-hop を書き換えない
- G. スポークからのマルチキャスト登録を受け付ける — スポークごとの map multicast を書かずに済む
- E. スポーク間の直接トンネルを禁止する — 距離ベクタの split horizon をハブで解除
- C. 対向スポークの NBMA アドレス — Phase 2 の署名= next-hop が対向スポーク
