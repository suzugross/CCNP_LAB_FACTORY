## 解説

### 完成文: 「入れるか」より「何秒待ったか」が原因を指す

```
RT01# test aaa group RADGRP noc-taro Noc-1234 legacy
Attempting authentication test to server-group RADGRP using radius
No authoritative response from any server.

(参考) radius-server timeout 3 / radius-server retransmit 2 / グループ内サーバ 2 台
```

`test aaa` の応答は 3 種類しかない。即座(0.1 秒)に返る「User was successfully authenticated.」、約 1 秒で返る「User authentication request was rejected by server.」、そして約 18 秒待って返る「No authoritative response from any server.」である。3 つ目の秒数は **［①］timeout 3 秒× (1+再送 2)回× 2 台** から来る。ログインの見え方も同じ 3 値で、拒否なら local に同じユーザがいても **［②］入れない**、無応答なら 18 秒ほど待たされたあと **［③］local のユーザなら入れる**。したがって「待たされて入れた」はサーバに届いていない/鍵不一致/ポート違いを、「すぐ弾かれた」はユーザ未登録やパスワード誤り(サーバが拒否) を疑う。厄介なのは共有鍵の不一致で、サーバは実は Reject を返しているのに、装置は鍵が違うため応答の Response Authenticator を検証できず捨てる。結果として装置側は「無応答」と全く同じ文言・同じ秒数になり、送信元アドレスの誤り(サーバ側で unknown client として破棄)とは **［④］サーバ側のログ** でしか区別できない。

### 各空欄の要点

- ① = **H. timeout 3 秒 × (1+再送 2)回 × 2 台** — 3×3×2= 18 秒
- ② = **F. 入れない** — Reject は確定・local に落ちない
- ③ = **G. local のユーザなら入れる** — 無応答は次メソッド(local)へ
- ④ = **E. サーバ側のログ** — 機器側の出力は同一(実測)

### 語群の残り(どの空欄にも入らない)

- B. timeout 3 秒 × 4 回 — 3×3×2= 18 秒
- D. 権限レベル 1 で入れる — Reject は確定・local に落ちない
- C. サーバ台帳のユーザだけ入れる — 無応答は次メソッド(local)へ
- A. show aaa servers — 機器側の出力は同一(実測)
