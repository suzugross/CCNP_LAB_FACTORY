## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/distance` — 再配送リングの定常ループ(ring=inject_ospf)
- 機構: `192.168.143.0/24` は RT05 が BGP 起点広告 → RT02 が iBGP(AD 200) で学習。
  RT02 が BGP を OSPF へ再配送し、RT04 の相互再配送で
  出自が一周。戻ってきた D EX (AD 170) が iBGP(200) に勝って RT02 が採用
  → 定常転送ループ RT02 → RT04 → RT01 → RT02。
- 出題形式: cause(機構(原因)を選ばせる。錯乱肢に「そもそもループでない」機構=等コスト分散・遠回りと、結果を原因と取り違える RIB-failure を混入)
- 正解法: distance(distance=iBGP の AD を戻り 170 未満へ /
  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 368013098`
  (sub-seed 5706010 / 展開パック PAPER-RD-5706010・撤収済)
- 赤ニシン: RT01・RT02・RT03 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)
- AD操作世界(BL-118): adworld=stale_proto — 前任者の残骸= RT02 の router ospf 25 に「distance ospf external 212」。効いていない(ループの勝者は不変)。既定 AD の暗記では解けず、show ip protocols / 設定抜粋からの実効 AD の読取りが決め手。

## 各選択肢の判定

- **A**: RT02 が戻り経路として学習しているのは EIGRP の外部経路であり、その管理距離は既定(170)のまま iBGP(200) に勝っている。当該の distance の有無はこの比較に関与していない。
- **B**: (正解)
- **C**: 遠回りであっても宛先には到達する。到達していない以上、経路の優劣ではなく転送の周回が生じている。
- **D**: 外部経路タイプは同一プロトコル内の優劣に影響するに過ぎず、iBGP と IGP 外部経路の比較は管理距離で決まる。
- **E**: `r>` の `>` はベストパス選出済みを示し、RIB-failure は選出後に RIB へ載せられなかったという表示。これは原因ではなく、原因(他プロトコルが RIB を占有していること)の結果である。
- **F**: RT02 の BGP テーブルに当該プレフィックスが存在する(広告は届いている)。

## 検証コマンドと期待される出力

- RT02: `show ip route 192.168.143.0` が `Known via "bgp 65466"` に変わること
  (是正前は `Known via "eigrp"`)。
- 任意ルータから `traceroute 192.168.143.1` が RT05 まで一直線(是正前はリングを周回)。
- distance 解の場合、投入だけでは BGP 表の `r>`(RIB-failure) が残るため
  `clear ip route *`(または clear ip bgp)で再計算が要る。
- tag 解の場合、RT02 で `Known via "bgp"` に変わり、かつ RT04 は当該網を
  引き続き保持していること(戻りの再注入だけが止まる)を見る。
  タグの付与だけでは何も変わらない(deny 側が本体)。

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
