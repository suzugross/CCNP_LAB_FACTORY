## 解説

### 完成文: SNMPv3 のセキュリティレベルと group/host のキーワード

| セキュリティレベル | 守られるもの | group / host で書くキーワード |
|---|---|---|
| noAuthNoPriv | ユーザ名の一致だけを確認する(合言葉に相当) | **［①］noauth** |
| authNoPriv | HMAC-MD5/HMAC-SHA で認証するが暗号化はしない | **［②］auth** |
| authPriv | **［③］認証に加えて DES/3DES/AES で暗号化する** | **［④］priv** |

SNMPv3 は USM(User-based Security Model)でユーザごとに保護の強さを選ぶ。v1/v2c はコミュニティ文字列を平文で送るので、v3 で言えば表の最上段と同じ強さしかない。装置では group にレベルのキーワードを書き、それが **［⑤］そのグループが受け付ける最低のセキュリティレベル** になる。その group に属するユーザが、group より低い(弱い) セキュリティレベルで要求を送ると authorizationError で拒否され(実測)、より強いレベルの要求はそのまま受け付けられる。認証と暗号の鍵はユーザ作成時にパスワードから engineID を混ぜた局所化(localized key) で導出されるため、engineID を変更すると既存ユーザのダイジェストは無効になり作り直しになる。認証アルゴリズムは MD5 か SHA、暗号は DES/3DES/AES(128/192/256)から選ぶ。

### 各空欄の要点

- ① = **G. noauth** — snmp-server group … v3 noauth
- ② = **H. auth** — snmp-server group … v3 auth
- ③ = **J. 認証に加えて DES/3DES/AES で暗号化する** — authPriv= 認証+暗号化。監視の標準はこれ
- ④ = **E. priv** — snmp-server group … v3 priv(host 行の version 3 の後ろも同じ 3 語)
- ⑤ = **F. そのグループが受け付ける最低のセキュリティレベル** — group の priv は「priv 以上で来い」の意味

### 語群の残り(どの空欄にも入らない)

- D. コミュニティ名を SHA でハッシュして送る — authPriv= 認証+暗号化。監視の標準はこれ
- A. ユーザが使える最高のセキュリティレベル — group の priv は「priv 以上で来い」の意味
- C. plain — snmp-server group … v3 noauth
- I. none — snmp-server group … v3 noauth
- B. open — snmp-server group … v3 noauth
