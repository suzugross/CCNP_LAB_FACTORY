## 解説

### 完成文: Flexible NetFlow の 4 段(record → exporter → monitor → インターフェース)

(この盤面の世界: **隣接ルータへ出ていく通過トラフィックを見たい(output)** — 同じ kind でも世界が違えば正解が変わる)

```
flow record REC-CORP
 match ipv4 source address
 match ipv4 destination address
 match ipv4 protocol
 match transport source-port
 match transport destination-port
 collect counter bytes
 collect counter packets
!
flow exporter EXP-CORP
 ［①］destination 198.51.100.100
 ［②］source Loopback0
 transport udp 9995
 export-protocol ipfix
!
flow monitor MON-CORP
 ［③］exporter EXP-CORP
 ［④］record REC-CORP
!
interface Ethernet0/2
 ip flow monitor MON-CORP output
```

FNF は 3 つの部品と 1 つの適用で組む。レコードでは match で指定したフィールドがキーになり、その値の組が同じパケットは 1 つのフローにまとめられる。collect で指定したフィールドは集計や付加情報(バイト数・パケット数など) で、フローの識別には使われない。エクスポータはコレクタの宛先・送信元・UDP ポート・export-protocol(既定は **［⑤］netflow-v9**)を持つ。モニタはキャッシュを持つ実体で、レコードとエクスポータを名前で束ねる。最後にインターフェースへ適用して初めて計測が始まる。Ethernet0/2 は隣接ルータ側の IF なので、そこへ出ていく通過トラフィックを見るには output に適用する。コレクタが無くても show flow monitor MON-CORP cache でフローが採取されているかを確認できる。

### 各空欄の要点

- ① = **A. destination** — flow exporter の宛先は destination
- ② = **E. source** — エクスポートパケットの送信元 IF
- ③ = **F. exporter** — monitor は exporter を名前で参照
- ④ = **C. record** — monitor は record を名前で参照
- ⑤ = **H. netflow-v9** — export-protocol の既定は netflow-v9(実測)

### 語群の残り(どの空欄にも入らない)

- D. collector — flow exporter の宛先は destination
- B. origin — エクスポートパケットの送信元 IF
- I. flow-record — monitor は record を名前で参照
- J. netflow-v5 — export-protocol の既定は netflow-v9(実測)
- G. template — monitor は record を名前で参照
