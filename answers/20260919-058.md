### 完成文: Dropped カウンタの理由から原因を読む

```
SW# show device-tracking counters interface GigabitEthernet1/0/1
Received messages on GigabitEthernet1/0/1:
  Protocol  Protocol message
  NDP       RS[12] RA[40] NS[8] NA[8]
  DHCPv6    SOL[3] ADV[3] REQ[3] REP[3]
Dropped messages on GigabitEthernet1/0/1:
  Feature     Protocol Msg [Total dropped]
  RA guard    NDP      RA  [40]
     reason: Message unauthorized on port [40]

SW# show device-tracking counters interface GigabitEthernet1/0/12
Dropped messages on GigabitEthernet1/0/12:
  Feature     Protocol Msg [Total dropped]
  RA guard    NDP      RA  [15]
     reason: Message unauthorized on port [15]
  DHCP Guard  DHCPv6   REP [6]
     reason: Message type is not authorized by the policy on this port, device-role mismatch [6]
```

上は 2 つのポートのカウンタである。GigabitEthernet1/0/12 側は意図どおりで、不正端末の RA が RA guard に、偽サーバの REPLY が DHCPv6 guard に落とされている。問題は GigabitEthernet1/0/1 側で、正規 GW が送る RA が 40 通すべて落ちている。理由が「Message unauthorized on port」なら **［①］GW ポートが host 扱い(ポリシー無しで VLAN の host が効いている、または host を付けた)** が原因で、GW ポートに device-role router のポリシー(または trusted-port) を付けるのが是正になる。理由が **［②］Preference flag error** なら `router-preference maximum` が正規 GW の優先度より低く設定されているのが原因である。どちらの場合も端末側の見え方は同じで、`show ipv6 routers` に GW が現れず、端末は **［③］リンクローカルだけで GUA も既定 GW も無い状態** になる。この 2 つを見分けるのは症状ではなく **［④］Dropped の理由文字列** であり、だからこそカウンタを先に見る。

### 各空欄の要点

- ① = **D. GW ポートが host 扱い(ポリシー無しで VLAN の host が効いている、または host を付けた)** — unauthorized on port= そのポートでは RA 自体が認められていない
- ② = **C. Preference flag error** — 優先度上限超過の理由文字列(実測)
- ③ = **G. リンクローカルだけで GUA も既定 GW も無い状態** — RA が届かない症状
- ④ = **A. Dropped の理由文字列** — 理由が違えば是正も違う

### 語群の残り(どの空欄にも入らない)

- H. DHCPv6 guard の role 誤り — unauthorized on port= そのポートでは RA 自体が認められていない
- F. Message unauthorized on port — 優先度上限超過の理由文字列(実測)
- E. アドレスが重複する状態 — RA が届かない症状
- B. 端末の ping 結果 — 理由が違えば是正も違う
