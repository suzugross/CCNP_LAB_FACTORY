## 解説

### 完成文: show mpls forwarding-table の読み方(PE の LFIB)

```
PE1# show mpls forwarding-table
Local      Outgoing   Prefix           Bytes Label   Outgoing   Next Hop
Label      Label      or Tunnel Id     Switched      interface
16         Pop Label  10.0.0.2/32      0             Et0/1      10.0.12.2
17         31         10.0.0.4/32      524160        Et0/1      10.0.12.2
18         No Label   10.0.99.0/24     0             Et0/3      10.0.99.9
19         No Label   172.16.1.0/24[V] 0             Et0/0      192.168.1.2
20         Aggregate  192.168.1.0/30[V] 0
```

上は PE1 の LFIB である。ローカルラベル 16 の行は、隣接 P1(10.0.0.2)のループバック宛で Outgoing が **［①］Pop Label** になっている。これは P1 が自分の /32 に対して **［②］Implicit Null(3)** を広告してきたためで、PE1 がその 1 つ手前として PHP を行う。ローカルラベル 17 の行は対向 PE2(10.0.0.4)宛で、受け取ったパケットのラベルを 31 に付け替えて P1 へ送る。VPN パケットの先頭ラベルはこの行で決まる。ローカルラベル 18 の行は Outgoing が No Label で、次ホップ 10.0.99.9 との間に LDP セッションが無い(または相手がその FEC を広告していない)ことを示す。この宛先へラベル付きで届いたパケットは IP パケットに戻して送られるため、その先が VPN 経路なら **［③］LSP の穴(ブラックホール)** となって通信できない。末尾に [V] が付く 2 行は VRF の経路で、対向 PE から届いた VPN ラベル 19 はそのまま CE へ IP 転送され、ローカル生成の集約経路に付く **［④］Aggregate** は「ラベルで VRF を特定した後に IP 検索する」ことを意味する。

### 各空欄の要点

- ① = **H. Pop Label** — imp-null を受けた FEC は Pop Label
- ② = **E. Implicit Null(3)** — PHP を要求するのは imp-null
- ③ = **B. LSP の穴(ブラックホール)** — 途中でラベルが外れると出口 PE は VPN ラベルを失い、P は VPN 経路を知らないので捨てる
- ④ = **C. Aggregate** — Aggregate= per-VRF 集約ラベル(IP 再検索)

### 語群の残り(どの空欄にも入らない)

- G. No Label — imp-null を受けた FEC は Pop Label
- A. Router Alert(1) — PHP を要求するのは imp-null
- F. ルーティングループ — 途中でラベルが外れると出口 PE は VPN ラベルを失い、P は VPN 経路を知らないので捨てる
- D. 16
