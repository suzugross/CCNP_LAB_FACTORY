## 解説

### 完成文: RADIUS による管理アクセス制御の設定例

```
aaa new-model
!
radius server RAD1
 address ipv4 10.99.1.2 auth-port 1812 acct-port 1813
 key Rad-Key-2026
radius server RAD2
 address ipv4 10.99.2.2 auth-port 1812 acct-port 1813
 key Rad-Key-2026
!
aaa group server radius AAA-SRV
 server name RAD1
 server name RAD2
!
ip radius source-interface Loopback0
radius-server dead-criteria time 3 tries 1
!
aaa authentication login default group AAA-SRV ［①］local
aaa authorization exec default group AAA-SRV ［①］local
［②］aaa authorization console
!
username break-glass privilege 15 secret 9 $9$xxxx
line vty 0 15
 transport input ssh
```

上の設定を上から読む。サーバは radius server で名前を付けて定義し、アドレス・ポート・共有鍵を持たせる。ポートは既定の 1812/1813 以外も指定でき、サーバ側の設定と一致していればよい。2 台をサーバグループ(aaa group server radius) にまとめ、メソッドリストからはこのグループ名で参照する。ip radius source-interface は要求の送信元アドレスを固定するもので、サーバ側の **［③］クライアント(NAS)一覧** に登録したアドレスと一致させるために要る。これが無いと出力インターフェースのアドレスが送信元になり、サーバは要求を **［④］unknown client** として黙って捨てる。認証と認可の両方に **［①］local** を末尾に置き、サーバ無応答時にローカルの break-glass で入れるようにしている。**［②］aaa authorization console** はコンソールにも exec 認可を効かせるための行で、これが無いとコンソールでは認可が実行されない。

### 各空欄の要点

- ① = **C. local** — サーバ無応答時にローカル DB へ
- ② = **B. aaa authorization console** — コンソールの認可は明示が要る
- ③ = **F. クライアント(NAS)一覧** — サーバは登録済み NAS アドレスからの要求だけ受ける
- ④ = **E. unknown client** — 未登録の送信元はサーバログに unknown client(実測)

### 語群の残り(どの空欄にも入らない)

- D. enable — サーバ無応答時にローカル DB へ
- G. aaa authentication console — コンソールの認可は明示が要る
- A. 認可プロファイル — サーバは登録済み NAS アドレスからの要求だけ受ける
- H. invalid password — 未登録の送信元はサーバログに unknown client(実測)
