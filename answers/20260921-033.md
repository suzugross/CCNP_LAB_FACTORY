```
P2# show mpls ldp neighbor detail
    Peer LDP Ident: 10.0.0.3:0; Local LDP Ident 10.0.0.4:0
        TCP connection: 10.0.0.3.646 - 10.0.0.4.14709; MD5 on

          10.0.0.3        10.0.12.2       10.0.24.2
        Peer holdtime: 180000 ms; KA interval: 60000 ms; Peer state: estab
```

上は P2(10.0.0.4)で採った出力である。`Peer LDP Ident` の値は相手の **［①］LDP ルータ ID** とラベル空間 ID の組で、末尾の :0 はプラットフォーム全体のラベル空間を意味する。`TCP connection` の行で、ポート 646 で待ち受けているのは **［②］相手(10.0.0.3)** 側で、一時ポートを使っている **［③］自分(10.0.0.4)** 側が接続を開始した。これはトランスポートアドレス(既定はルータ ID)の大きい方がアクティブになる規則と一致する。`State: Oper` はセッション確立済み、`Downstream` はラベル配布が **［④］Downstream Unsolicited** であることを示す。`Addresses bound to peer` が重要なのは、自分の RIB のネクストホップ(10.0.24.2)がこの一覧に含まれていて初めて、相手から受けたラベルを LFIB に採用できるからである。

### 各空欄の要点

- ① = **A. LDP ルータ ID** — LDP Ident= LDP ルータ ID:ラベル空間 ID
- ② = **B. 相手(10.0.0.3)** — 646 を持つ側が待ち受け(パッシブ)
- ③ = **C. 自分(10.0.0.4)** — 一時ポート側が接続を開始(アクティブ)
- ④ = **G. Downstream Unsolicited** — Downstream 表示= DU モード
