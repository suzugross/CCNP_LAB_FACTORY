## 解説

### 完成文: RSVP-TE による LSP のシグナリング

RSVP-TE は LDP と違い、IGP の最短路に追随するのではなく、帯域などの制約を満たす経路に LSP(TE トンネル)を張る。経路計算はヘッドエンド(入口ルータ) が行い、TE 拡張された IGP(OSPF/IS-IS)が配る利用可能帯域や affinity を入力として CSPF で求める。求めた経路はホップの列として **［①］ERO(Explicit Route Object)** に載せ、**［②］PATH** メッセージを下流へ送る。**［③］テールエンド(出口ルータ)** まで届くと折り返しに RESV メッセージが上流へ返り、各ホップは帯域を予約すると同時に、自分が上流に使わせるラベルを割り当ててこのメッセージに載せる。つまり RSVP-TE でもラベルは **［④］下流から上流** 向きに配布される。実際に通ったホップと各ホップの保護状態は RRO(Record Route Object) に記録されて入口まで戻る。

### 各空欄の要点

- ① = **E. ERO(Explicit Route Object)** — 通す経路を指定するのは ERO
- ② = **H. PATH** — 下流へ送るのは PATH
- ③ = **G. テールエンド(出口ルータ)** — PATH の終点は出口(テールエンド)
- ④ = **B. 下流から上流** — ラベルは RESV に載って下流から上流へ(LDP の DU と同じ向き)

### 語群の残り(どの空欄にも入らない)

- C. RRO(Record Route Object) — 通す経路を指定するのは ERO
- D. Hello — 下流へ送るのは PATH
- F. PLR — PATH の終点は出口(テールエンド)
- A. 上流から下流 — ラベルは RESV に載って下流から上流へ(LDP の DU と同じ向き)
