## 解説

### 完成文: メソッドリストの読み方と「次のメソッドへ行く条件」

(この盤面の世界: **local → group の順(local 優先・local に無ければサーバ)** — 同じ kind でも世界が違えば正解が変わる)

```
aaa new-model
aaa authentication login default local group TAC-GRP
!
username emg-admin privilege 15 secret 9 $9$xxxx    ! local だけに存在
! 認証サーバの台帳: ope-suzuki(サーバだけに存在)
!
line vty 0 15
 transport input ssh
 ! (login authentication 未指定)
```

aaa new-model を入れた瞬間に全回線が AAA のメソッドリストで認証されるので、投入前に別のセッションを開いたままにしておく。上の default のリストは **［①］名前付きリストを付けていない全回線** に効く。メソッドは左から順に試され、次へ進むのは前のメソッドが応答しない(タイムアウト/到達不能) ときだけで、**［②］拒否(Reject)した** 場合はそこで確定する(次へは行かない)。この盤面でサーバが正常に応答しているとき、local だけにいる emg-admin は local で即座に入れる。サーバだけにいる ope-suzuki は **［③］local に無いので次のサーバへ進み、入れる**。サーバが 2 台とも無応答のとき、emg-admin は **［④］待たされずに local で入れる**。なお、回線に付けたリスト名が定義されていないと、IOS は default と同じ動きをする(実測)。

### 各空欄の要点

- ① = **G. 名前付きリストを付けていない全回線** — default は明示指定の無い回線すべてに効く
- ② = **A. 拒否(Reject)した** — Reject で確定・次のメソッドへは落ちない(実測 1.1s で失敗)
- ③ = **E. local に無いので次のサーバへ進み、入れる** — local の「ユーザ不在」は ERROR 扱いで次へ進む(拒否ではない)
- ④ = **F. 待たされずに local で入れる** — 先頭が local なのでサーバの状態は無関係

### 語群の残り(どの空欄にも入らない)

- C. コンソールだけ — default は明示指定の無い回線すべてに効く
