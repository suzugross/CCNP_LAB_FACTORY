## 仕込んだ状態(故障ではなく設計の帰結)

- 種別: `ring/tag` — 再配送リングの定常ループ(ring=inject_ospf)
- 機構: `192.168.97.0/24` は RT02 が BGP 起点広告 → RT06 が iBGP(AD 200) で学習。
  RT06 が BGP を OSPF へ再配送し、RT01 の相互再配送で
  出自が一周。戻ってきた D EX (AD 170) が iBGP(200) に勝って RT06 が採用
  → 定常転送ループ RT06 → RT01 → RT05 → RT06。
- 出題形式: cause(機構(原因)を選ばせる。錯乱肢に「そもそもループでない」機構=等コスト分散・遠回りと、結果を原因と取り違える RIB-failure を混入)

  filter=戻り経路を学習段で遮断(distribute-list) /
  tag=注入時に出自タグを付け、一周する箇所で match tag deny。監査要件で出し分け)
- 生成: `gen_paper_mcq.py --shape ring --seed 877216702`
  (sub-seed 2524056 / 展開パック PAPER-RD-2524056・撤収済)
- 赤ニシン: RT03・RT05・RT06 に未適用の route-map/prefix-list/ACL と無害な適用行を混入(実害なし)

## 各選択肢の判定

- **A**: (正解)
- **B**: 等コスト分散であれば宛先には到達する。示された traceroute は同一のホップ列を反復しており、分散ではなく周回である。
- **C**: 経路表の経過時間は単調に進行しており、再学習(タイマーのリセット)の痕跡がない。定常状態のループである。
- **D**: 外部経路タイプは同一プロトコル内の優劣に影響するに過ぎず、iBGP と IGP 外部経路の比較は管理距離で決まる。
- **E**: `r>` の `>` はベストパス選出済みを示し、RIB-failure は選出後に RIB へ載せられなかったという表示。これは原因ではなく、原因(他プロトコルが RIB を占有していること)の結果である。
- **F**: RT06 の BGP テーブルに当該プレフィックスが存在する(広告は届いている)。

## 検証コマンドと期待される出力

- RT06: `show ip route 192.168.97.0` が `Known via "bgp 65076"` に変わること
  (是正前は `Known via "eigrp"`)。
- 任意ルータから `traceroute 192.168.97.1` が RT02 まで一直線(是正前はリングを周回)。
- distance 解の場合、投入だけでは BGP 表の `r>`(RIB-failure) が残るため
  `clear ip route *`(または clear ip bgp)で再計算が要る。
- tag 解の場合、RT06 で `Known via "bgp"` に変わり、かつ RT01 は当該網を
  引き続き保持していること(戻りの再注入だけが止まる)を見る。
  タグの付与だけでは何も変わらない(deny 側が本体)。

## 教育核心

既定 AD の並び(eBGP 20 / EIGRP内 90 / OSPF 110 / EIGRP外 170 / **iBGP 200**)。
再配送リングでは出自が一周して「自分が注いだ経路」が外部経路として戻り、
iBGP より強い AD で勝ってしまう。切り分けの型は
「`show ip bgp` の r>(RIB-failure) × `show ip route <prefix>` の Known via 不一致」。
