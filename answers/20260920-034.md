State 列は下の層から **［①］IKE → NHRP → UP** の順に上がる。この盤面で疑うべきなのは **［②］GRE/NHRP(tunnel key・NHRP 認証・NHS のトンネル IP)** で、次に打つコマンドは **［③］show ip nhrp nhs detail**。Attrb の S は静的エントリ(スポークが設定で持つ NHS の対応)、ハブ側で見える D は動的エントリ(登録や解決で学んだ対応) を表す。Phase 3 でショートカットが成立すると Attrb に **［④］DT1 / DT2(T1= 経路がインストール済・T2= next-hop override)** が付く。State が UP でも Attrb に X(No Socket)= IX や DX が残っているときは、スポーク間の IPsec ソケットが作れていない(keyring をピアごとに絞った典型)。tunnel key の不一致はハブ側に痕跡が出ない一方、NHRP 認証の不一致はハブのログに wrong authentication string が出る(IOL 実測)。

### 各空欄の要点

- ① = **C. IKE → NHRP → UP** — IPsec が上がらないと GRE/NHRP に進めない
- ② = **B. GRE/NHRP(tunnel key・NHRP 認証・NHS のトンネル IP)** — IKEv2 READY なのに登録が通らない= GRE/NHRP 層
- ③ = **G. show ip nhrp nhs detail** — 登録要求の送信回数と応答ゼロを見る
- ④ = **H. DT1 / DT2(T1= 経路がインストール済・T2= next-hop override)** — shortcut 成立の印(実測)

### 語群の残り(どの空欄にも入らない)

- D. NHRP → IKE → UP — IPsec が上がらないと GRE/NHRP に進めない
- F. EIGRP(split-horizon・next-hop-self の誤り) — IKEv2 READY なのに登録が通らない= GRE/NHRP 層
- E. show ip eigrp neighbors — 登録要求の送信回数と応答ゼロを見る
- A. N / L — shortcut 成立の印(実測)
