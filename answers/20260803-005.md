## 注入した故障

- 種別: `wrong_id` — redistribute の参照プロセス/AS が誤り(config は一見完備・無言で経路ゼロ)
- 対象: RT07 の router ospf 91 への注入方向(OSPF 77 出自)
- 赤ニシン: RT01・RT03・RT05・RT07 に未適用の route-map/prefix-list/ACL と無害な適用行(passive-interface Lo0 等)を混入(実害なし)
- 適用基準(可変): seed metric=`10000 10 255 1 1500` / 付与方式=redistribute 文へ直接指定
- 生成: `gen_paper_mcq.py --seed 204738`(sub-seed 5480630 / 展開パック PAPER-RD-5480630・撤収済)

## 各選択肢の判定

- **A**: 逆方向の再配送は参照 ID も含めて正常(対比側の経路表で確認できる)。削除すればかえって逆方向の到達性を壊す。
- **B**: 参照先のプロセス/AS が実在しない以上、メトリックを与えても注入は発生しない。症状は解消しない。
- **C**: 設定上の欠陥が原因であり、再計算しても状態は変わらない。
- **D**: 隣接関係は確立しており内部経路も学習済み。passive は本事象と無関係。
- **E**: 経路は注入されるようになる(症状は改善する)が、実在しないプロセス/AS への参照が残置され、要件「実在しないプロセスへの参照残置の禁止」を満たさない。
- **F**: (正解)

## 検証コマンドと期待される出力

- `show ip protocols`(RT07): 対象プロセスの Redistributing 節に出自プロトコルが
  正しい ID・(EIGRP なら) metric 付きで載ること。
- `show ip route`(症状側 RT01): 対岸 Loopback 群が `O E2` として
  現れること。是正前は当該経路が不在(対比側 RT05 には最初からある)。
- 是正後に反映が遅い場合は境界ルータで `clear ip route *`。
