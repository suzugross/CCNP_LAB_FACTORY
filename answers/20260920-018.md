# 解答 20260920-018

## 解説

### 完成文: SNMPv3 設定の 4 行(view → group → user → host)の参照関係

```
snmp-server view V3VIEW iso included
snmp-server group V3GROUP v3 priv read V3VIEW access 99
snmp-server user zbx-ro ［①］V3GROUP v3 auth ［②］sha Auth-N0c-77 priv aes 128 Priv-N0c-77
snmp-server host 10.99.0.2 version 3 priv zbx-ro
snmp-server enable traps
access-list 99 permit 10.99.0.2
!
! NOC 標準: 認証 SHA・暗号 AES-128・authPriv のみ許可・ポーラは 10.99.0.2
```

SNMPv3 の設定は上から順に後の行が前の行で付けた名前を参照するという関係で読む。view は見せる MIB の範囲、group はセキュリティレベルと view の組、user は group に属する実体で鍵を持ち、host は通知の宛先とそのときに使う user を指定する。group の `access 99` は **［③］要求の送信元アドレスの制限** で、許可されない送信元からの要求には応答しない(タイムアウト・実測)。user 行は投入しても running-config に表示されないので、設定の確認は `show snmp user`(鍵は出ない)と `show snmp group` で行う。group が存在しない view 名を参照していると認証は通るのに値が取れないため、`show snmp group` の readview 欄を疑う(実測)。エージェントは UDP **［④］161** で要求を受け、通知は管理ステーションの UDP 162 へ送る。`snmp-server enable traps` を引数なしで入れると **［⑤］すべての種類の通知** が有効になり、running-config には種類ごとの行として展開される。

### 各空欄の要点

- ① = **C. V3GROUP** — user 行の 2 語目は所属 group 名
- ② = **F. sha** — NOC 標準が SHA(md5 も構文としては通るが標準に反する)
- ③ = **D. 要求の送信元アドレスの制限** — group(または user)の access は送信元制限。MIB 範囲は view
- ④ = **I. 161** — エージェント 161 / 通知の受け手 162
- ⑤ = **J. すべての種類の通知** — 引数なし= 全種(running-config に多数の行として展開・実測)

### 語群の残り(どの空欄にも入らない)

- A. 123 — エージェント 161 / 通知の受け手 162
- H. V3VIEW — user 行の 2 語目は所属 group 名
- E. aes — NOC 標準が SHA(md5 も構文としては通るが標準に反する)
