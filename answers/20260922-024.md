## 解説

### 完成文: RSTP(802.1w): 役割・状態・高速収束の仕組み

RSTP(802.1w)は 802.1D の役割と状態を整理し、収束を数秒以内(サブ秒〜) にした。ポート役割は root・designated に加え、root port の予備である alternate port と、同じセグメントに自分のポートが 2 本ある時の予備である backup port を持つ。ポート状態は 802.1D の 5 つを三つに畳み、blocking と listening は **［①］discarding** にまとめられた。BPDU は **［②］すべてのスイッチ(自分の情報で)** が hello ごとに出し、3 回続けて届かなければ隣接情報を捨てる(802.1D の max age を待たない)。2 台の間で designated port を即座に forwarding にする仕組みが proposal/agreement(sync) で、対向が全二重の **［③］point-to-point** リンクであることが前提になる(半二重は shared 扱いで 802.1D と同じタイマ待ちになる)。端末が繋がるポートは edge port(PortFast) として宣言すると即 forwarding になり、トポロジ変化にも数えられない。トポロジ変化(TC)を受けたスイッチは **［④］edge 以外のポートで学習した MAC** を消し、802.1D のように root へ TCN を上げる必要はない。対向が 802.1D しか話せない場合、そのポートだけが **［⑤］802.1D(旧 STP)モード** に落ちる。

### 各空欄の要点

- ① = **B. discarding** — discarding / learning / forwarding の 3 状態
- ② = **A. すべてのスイッチ(自分の情報で)** — keepalive 兼用。802.1D は root だけが起点(対比)
- ③ = **D. point-to-point** — 全二重= 相手は 1 台と判断して即時遷移を許す
- ④ = **I. edge 以外のポートで学習した MAC** — TC while の間、非 edge ポートの MAC を即フラッシュ
- ⑤ = **F. 802.1D(旧 STP)モード** — ポート単位で互換動作。そのポートだけ収束が遅くなる
