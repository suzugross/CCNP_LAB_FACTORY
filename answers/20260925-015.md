## 解説

### 完成文: STP(802.1D)の基礎: root・ポート役割・状態・タイマ

STP(802.1D)は冗長リンクのある L2 網で **［①］ブリッジングループ(ブロードキャストストーム・MAC テーブルの不安定)** を防ぐため、論理的に木を作って余分なポートを止める。木の根になる root bridge は Bridge ID が最小のスイッチで、その判定に使う Bridge ID は **［②］priority(4096 刻み)+ extended system ID(VLAN 番号)+ MAC アドレス** で構成される。BPDU は **［③］root bridge だけ** が hello 間隔(既定 **［④］2** 秒)で送り、他のスイッチはそれを中継しながら自分の情報で書き換える(宛先 MAC は 01:80:C2:00:00:00)。root 以外の各スイッチは root への合計コストが最小のポートを root port に選び、同点なら送信元 Bridge ID →送信元 port priority →送信元 port ID の順で決める。各セグメントでは root への合計コストが最小のスイッチ側のポートが designated port になり、root のポートはすべてこれである。それ以外のポートは non-designated(blocking)port として BPDU を受け取るだけになる。802.1D のポート状態は blocking → listening → learning → forwarding と進み、listening と learning はそれぞれ forward delay(既定 15 秒)を待つ。blocking のポートが動き出す判断は max age(既定 20 秒)の間 BPDU が来ないことで行うため、間接障害の収束は最大で約 **［⑤］50** 秒かかる。トポロジ変化に気づいたスイッチは **［⑥］TCN BPDU** を root 向きに送り、root が TC フラグ付きの BPDU を流すと、全スイッチは MAC テーブルのエージング時間を forward delay に短縮する。

- ⑤ = **D. 50** — max age 20 + listening 15 + learning 15
- ⑥ = **F. TCN BPDU** — Topology Change Notification。root port から上流へ
