## 解説

### 完成文: PIM-SM: DR・Join・Register・SPT への切り替え・Assert

PIM は独自の経路表を持たず、**［①］ユニキャストの経路表** を使って RPF を判断する(Protocol Independent の由来)。Hello は 224.0.0.13 宛てに 30 秒ごとに送られ、LAN 上の DR は **［②］DR priority が最大、同じなら IP アドレスが最大** のルータに決まる。受信者のいる LAN の DR は、IGMP で参加を知ると RP へ向けて **［③］(*,G) Join** を送り、共有木を作る。送信元の LAN の DR は、最初のパケットを **［④］ユニキャストでカプセル化(Register)** して RP へ届ける。RP が送信元へ (S,G) Join を送って木ができると、RP は Register-Stop を返す(受信者がいなくても返す)。Cisco IOS の既定では、受信側のルータは **［⑤］最初のパケットを受けた時点で** 送信元木へ切り替え、`ip pim spt-threshold infinity` を設定すると共有木に留まる。同じ LAN に 2 台のルータが同じフローを転送すると Assert が起き、AD →メトリック→ **［⑥］IP アドレスが最大** の順で勝った 1 台だけが転送を続ける。

### 各空欄の要点

- ① = **A. ユニキャストの経路表** — OSPF でも EIGRP でも static でもよい
- ② = **B. DR priority が最大、同じなら IP アドレスが最大** — 既定 priority 1。実測: `ip pim dr-priority 10` で IP の小さいルータが DR になった
- ③ = **F. (*,G) Join** — RP を根とする共有木への参加
- ④ = **H. ユニキャストでカプセル化(Register)** — 実測: 送信元側 DR の (S,G) に F(Register)フラグ
- ⑤ = **C. 最初のパケットを受けた時点で** — 既定の SPT しきい値は 0(実測: 受信側 DR の (S,G) に JT)
- ⑥ = **I. IP アドレスが最大** — 実測: AD とメトリックが同じで .8 が .4 に勝った(OIF フラグ A)

### 語群の残り(どの空欄にも入らない)

- G. IGMP のグループ表 — OSPF でも EIGRP でも static でもよい
- E. 10 kbps を超えたときに — 既定の SPT しきい値は 0(実測: 受信側 DR の (S,G) に JT)
- D. (*,G) Join に載せて — 実測: 送信元側 DR の (S,G) に F(Register)フラグ
- J. PIM 専用の経路表 — OSPF でも EIGRP でも static でもよい
