## 解説

### 完成文: メソッドリストの読み方と「次のメソッドへ行く条件」

```
aaa new-model
aaa authentication login default group AAA-SRV local
aaa authentication login REMOTE group AAA-SRV local-case
aaa authentication login CONSOLE ［①］none
!
line con 0
 login authentication CONSOLE
line vty 0 4
 login authentication REMOTE
line vty 5 15
 ! (login authentication 未指定)
```

aaa new-model を入れた瞬間に全回線が AAA のメソッドリストで認証されるようになるので、投入前に別のセッションを開いたままにしておく。リストは「メソッドを最大 4 つ順に並べたもの」で、名前が default のものは **［②］名前付きリストを付けていない全回線** に自動で効き、名前付きのものは回線に `login authentication <名前>` で付けたときだけ効く。上の例では vty 5〜15 には **［③］default のリスト** が効く。重要なのは次のメソッドへ進む条件で、先頭のサーバグループが応答しない(タイムアウト/到達不能) ときだけ次(local)へ進む。サーバが応答して **［④］拒否(Reject)した** 場合はそこで確定し、local に同じユーザがいてもログインできない。この「拒否は権威・無応答だけが素通り」の原則は認可と enable 認証にも同じく効く。`local-case` はユーザ名の大文字小文字を区別する local である。回線に付けたリスト名が定義されていないと、IOS は default と同じ動きをする(実測)。上の CONSOLE リストにある **［①］none** は「認証なしで許可」のメソッドで、締め出し保険に使えるが、そのぶん危険でもある。

### 各空欄の要点

- ① = **H. none** — none は認証なしで許可。enable は enable secret、line は回線パスワード
- ② = **E. 名前付きリストを付けていない全回線** — default は明示指定の無い回線すべてに効く
- ③ = **D. default のリスト** — 未指定の回線は default
- ④ = **A. 拒否(Reject)した** — Reject で確定・local へは落ちない(実測 1.1s で失敗)

### 語群の残り(どの空欄にも入らない)

- G. line — none は認証なしで許可。enable は enable secret、line は回線パスワード
- C. vty だけ — default は明示指定の無い回線すべてに効く
- B. CONSOLE のリスト — 未指定の回線は default
- F. タイムアウトした — Reject で確定・local へは落ちない(実測 1.1s で失敗)
