## 解説

### 完成文: スポーク(Phase 3・IPsec あり)の Tunnel 設定例

```
interface Tunnel0
 ip address 10.255.0.2 255.255.255.0
 ip mtu ［①］1400
 ip tcp adjust-mss 1360
 ip nhrp authentication NHRPK3Y
 ip nhrp network-id 1
 ip nhrp nhs 10.255.0.1 nbma 203.0.113.1 multicast
 ［②］ip nhrp shortcut
 tunnel source GigabitEthernet0/1
 tunnel mode gre ［③］multipoint
 tunnel key 100
 tunnel protection ipsec profile IPSEC-DMVPN
!
! ハブ: トンネル IP 10.255.0.1 / NBMA 203.0.113.1   スポークの WAN IF= GigabitEthernet0/1
```

NHS の行は従来の map・map multicast・nhs の 3 行を 1 行にまとめた現代構文で、末尾の multicast は **［④］ルーティングプロトコルの Hello などマルチキャストをハブへ送るための対応** を意味する。203.0.113.1 はハブの NBMA(WAN 物理)アドレスである。tunnel destination を書かないのは **［⑤］宛先(ハブや対向スポークの NBMA)を NHRP が解決する** からで、そのために tunnel mode を gre **［③］multipoint** にする。**［②］ip nhrp shortcut** はハブからの Redirect を受けて解決・直接転送するための Phase 3 のスポーク設定である。MSS は IP ヘッダと TCP ヘッダの分だけ ip mtu より 40 バイト小さくする。tunnel protection を付けると GRE パケット全体が ESP で保護される(平文 GRE は相手に捨てられる)。

### 各空欄の要点

- ① = **H. 1400** — GRE+IPsec の余地を見た定番値
- ② = **F. ip nhrp shortcut** — Phase 3 のスポーク側

- ④ = **D. ルーティングプロトコルの Hello などマルチキャストをハブへ送るための対応** — map multicast <NBMA> と同じ意味
- ⑤ = **J. 宛先(ハブや対向スポークの NBMA)を NHRP が解決する** — mGRE は宛先固定なし
