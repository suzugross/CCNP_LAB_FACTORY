## 解説

### 完成文: ハブの Tunnel 設定と Phase の判定(EIGRP)

(この盤面の世界: **Phase 3(ハブが redirect・スポークに shortcut)** — 同じ kind でも世界が違えば正解が変わる)

```
! Hub
interface Tunnel0
 ip address 172.31.255.1 255.255.255.0
 no ip redirects
 ip mtu 1400
 ip tcp adjust-mss 1360
 ip nhrp authentication CCNP2026
 ［①］ip nhrp map multicast dynamic
 ip nhrp network-id 10
 ［②］ip nhrp redirect
 no ip split-horizon eigrp 100
 tunnel source GigabitEthernet0/1
 tunnel mode gre multipoint
 tunnel key 100
 tunnel protection ipsec profile DMVPN-PROF
!
! Spoke(抜粋): ip nhrp nhs 172.31.255.1 nbma 203.0.113.1 multicast / tunnel mode gre multipoint
!              ip nhrp shortcut
```

この構成は Phase **［③］3** である。**［①］ip nhrp map multicast dynamic** は **［④］登録してきたスポークの NBMA を Hello などマルチキャストの宛先に自動で加える** ための行で、これが無いとスポークはハブからの Hello を受け取れず隣接が片側だけになる。no ip split-horizon eigrp 100 は同じ Tunnel から学んだスポークの経路を、他のスポークへ同じ Tunnel から広告するために要る(Phase に関係なく必須)。**［②］ip nhrp redirect** が Phase を決める行で、スポークが持つ対向スポークの LAN 経路の next-hop はハブのトンネル IP(172.31.255.1)のままになる。この Phase でハブが対向スポークの経路を集約することは **［⑤］できる(next-hop はもともとハブ・Redirect で直接通信が成立)**。tunnel key は全メンバで一致させ、`no ip redirects` は Tunnel 上で ICMP Redirect を出さないための定石である。

### 各空欄の要点

- ① = **E. ip nhrp map multicast dynamic** — ハブは登録してきたスポークの NBMA をマルチキャスト宛先に自動追加
- ② = **H. ip nhrp redirect** — スポークに shortcut があるので Phase 3。ハブは Redirect を送る
- ③ = **G. 3** — redirect+shortcut= Phase 3
- ④ = **J. 登録してきたスポークの NBMA を Hello などマルチキャストの宛先に自動で加える** — スポークごとの map multicast を書かずに済む
- ⑤ = **D. できる(next-hop はもともとハブ・Redirect で直接通信が成立)** — Phase 3 の利点

### 語群の残り(どの空欄にも入らない)

- B. 1 — redirect+shortcut= Phase 3
- C. ip nhrp nhs dynamic — ハブは登録してきたスポークの NBMA をマルチキャスト宛先に自動追加
- A. ip summary-address eigrp 100 0.0.0.0 0.0.0.0 — スポークに shortcut があるので Phase 3。ハブは Redirect を送る
- F. スポークからのマルチキャスト登録を受け付ける — スポークごとの map multicast を書かずに済む
- I. どちらの Phase でもできない — Phase 3 の利点
