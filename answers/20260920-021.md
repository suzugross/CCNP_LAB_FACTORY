## 解説

### 完成文: コミュニティ(v1/v2c)の RO/RW と ACL の効き方

```
snmp-server community readonly RO 55
snmp-server community private RW 77
access-list 55 permit 10.99.0.2
! (access-list 77 は定義されていない)
```

コミュニティは RO と RW の 2 種類で、RO では GET は成功するが SET は **［①］noAccess** として拒否され、RW では両方成功する。コミュニティに付けた ACL が要求の送信元を許可しないとき、装置は **［②］応答を返さない(タイムアウトになる)**。一方、参照している ACL が定義されていないときは全許可になる(拒否しない)(実測)。したがって上の private は送信元を問わず書き込める危険な状態である。誤ったコミュニティ名での要求は `show snmp` の Unknown community name カウンタ、RO への SET は **［③］Illegal operation** カウンタに現れる。コミュニティ名は running-config に **［④］平文で表示される** ので、v3 のユーザ(表示されない)とは扱いが違う。

### 各空欄の要点

- ① = **G. noAccess** — RO への SET= noAccess(実測)
- ② = **D. 応答を返さない(タイムアウトになる)** — ACL 不許可= 無応答(実測)
- ③ = **F. Illegal operation** — RO への SET のカウンタ(実測)
- ④ = **H. 平文で表示される** — コミュニティは running-config に平文

### 語群の残り(どの空欄にも入らない)

- A. authorizationError — RO への SET= noAccess(実測)
- C. authorizationError を返す — ACL 不許可= 無応答(実測)
- E. Unknown community name — RO への SET のカウンタ(実測)
- B. ハッシュで表示される — コミュニティは running-config に平文
