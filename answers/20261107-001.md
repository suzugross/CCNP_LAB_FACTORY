## 解説

入口 PE はラベルを 2 枚積む。外側(先頭)は運ぶ層のラベルで、出口 PE のループバックへの道を表す。番号は**次の機器**が決めて LDP で配ったもので、入口 PE の表では出口 PE のループバックの行の Outgoing の列にある(Local の列は自分が隣に配った番号)。内側はサービスのラベルで、番号は**出口 PE** が決める(L3VPN と EVPN は BGP で広告し RR が変えずに反射する・LDP の疑似回線(VPWS・VPLS)は出口 PE が targeted LDP で直接渡す)。P は外側だけを見て付け替え、出口の 1 つ手前の P は外側を外して渡す(PHP。表では Pop Label / Pop)。出口 PE が explicit null を広告していれば、外側を外さずラベル 0 に付け替える(表では explicit-n)。出口 PE は内側の番号で、どの VRF の経路か・どの回線か・どのブリッジ ドメインかを決める。ラベルの番号は決めた機器の中でだけ意味を持つので、別の機器が同じ番号を別の用途に使っていてもよい。 L2 のサービスでも外側は L3VPN と同じ道のラベルで、違うのは内側だけである。VPLS と EVPN の E-LAN では、入口 PE が宛先 MAC から相手の PE と内側の番号を選ぶ(VPLS= 疑似回線ごとの VC_LABEL・EVPN= MAC/IP 広告ルートのLabel1。宛先が分からないフレームとブロードキャストは EVPN では Inclusive Multicast のルートの BUM 用のラベル)。

- 外側: XE2 の表で XE3 のループバック 10.255.0.43 の行は、Local が 23・Outgoing が 19。XE2 が付けるのは次の P1 が決めた 19。
- 内側: XE2 の `show l2vpn evpn vpws vc id 140 detail` で Labels の Remote 25(XE3 が決めてタイプ 1 のルートで広告し、RR1 が反射した番号)。
- P1 の表で 10.255.0.43 の行の Outgoing は Pop Label(PHP)。P1 は外側を外して渡し、XE3 は内側の 25 で l2ckt(1) の行(Gi2 から CE3 へ)を引く。
- 線の上の実測(CML のリンクの捕獲): XE2 から P1 は `19 | 25`、P1 から XE3 は `25`。
