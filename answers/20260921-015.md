## 解説

### 完成文: RADIUS による管理アクセス制御の設定例

```
aaa new-model
!
radius server RAD1
 address ipv4 192.168.100.11 auth-port 1645 acct-port 1646
 key N0c-Radius
radius server RAD2
 address ipv4 192.168.100.12 auth-port 1645 acct-port 1646
 key N0c-Radius
!
aaa group server radius RADGRP
 server name RAD1
 server name RAD2
!
［①］ip radius source-interface Loopback0
radius-server dead-criteria time 3 tries 1
!
aaa authentication login default group RADGRP ［②］local
aaa authorization exec default group RADGRP ［②］local
aaa authorization console
!
username local-admin privilege 15 secret 9 $9$xxxx
line vty 0 15
 transport input ssh
```

上の設定を上から読む。サーバは radius server で名前を付けて定義し、アドレス・ポート・共有鍵を持たせる。ポートは既定の 1645/1646 以外も指定でき、サーバ側の設定と一致していればよい。2 台を **［③］サーバグループ(aaa group server radius)** にまとめ、メソッドリストからはこのグループ名で参照する。**［①］ip radius source-interface** は要求の送信元アドレスを固定するもので、サーバ側の **［④］クライアント(NAS)一覧** に登録したアドレスと一致させるために要る。これが無いと出力インターフェースのアドレスが送信元になり、サーバは要求を unknown client として黙って捨てる。認証と認可の両方に **［②］local** を末尾に置き、サーバ無応答時にローカルの local-admin で入れるようにしている。aaa authorization console はコンソールにも exec 認可を効かせるための行で、これが無いとコンソールでは認可が実行されない。

### 各空欄の要点

- ① = **F. ip radius source-interface** — RADIUS の送信元固定
- ② = **C. local** — サーバ無応答時にローカル DB へ
- ③ = **H. サーバグループ(aaa group server radius)** — 複数サーバの束がグループ
- ④ = **D. クライアント(NAS)一覧** — サーバは登録済み NAS アドレスからの要求だけ受ける
