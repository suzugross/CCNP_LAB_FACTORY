### 完成文: 顧客経路が対向拠点へ届くまで

CE1 が広告した 172.16.1.0/24 が対向拠点の CE2 に届くまでを追う。PE1 は PE-CE の経路交換で受け取った経路を **［①］VRF の経路表** に入れる。それが BGP へ再配送または VRF 配下の AF で受信されると、PE1 は VRF に設定した RD を前置し、**［②］export** の RT を付けて VPNv4 BGP テーブルに載せる。同時に PE1 はこの経路に **［③］VPN ラベル** を割り当てる(既定はプレフィックスごと)。MP-iBGP で PE2 に届くと、PE2 は自分の各 VRF の import 一覧と経路の RT を突き合わせ、一致した VRF にだけ取り込む。ネクストホップは PE1 の Loopback アドレス(/32) のままなので、PE2 からそこへ至る LSP が IGP と LDP で完成している必要があり、無ければ経路はベストにならず VRF に入らない。確認は、VPNv4 表全体なら `show ip bgp vpnv4 **［④］all**`、特定 VRF の分だけなら `show ip route vrf <名前>` を使う。
