## 設問

次の説明文(設定例を含む)の空欄 ①〜④ に入る語句を、下の語群 A〜H から 1 つずつ選択してください。同じ語句を 2 つの空欄に使うことはありません。語群にはどの空欄にも当てはまらない語句が含まれます。

```mermaid
graph LR
  GW[GW ルータ] ---|GigabitEthernet1/0/1| SW[アクセス SW]
  SW ---|GigabitEthernet1/0/10| H1[PC1]
  SW ---|GigabitEthernet1/0/11| H2[PC2]
  SW ---|GigabitEthernet1/0/12| ROG[不正端末]
```

```
ipv6 dhcp guard policy DH-EDGE
 device-role client
ipv6 dhcp guard policy DHG-SERVER
 device-role server
 match server access-list DHCP-SRV
!
ipv6 access-list DHCP-SRV
 permit ipv6 host FE80::2 any
!
interface GigabitEthernet1/0/1
 ipv6 dhcp guard attach-policy DH-EDGE
interface GigabitEthernet1/0/10
 ipv6 dhcp guard attach-policy DH-EDGE
interface GigabitEthernet1/0/12
 ipv6 dhcp guard attach-policy DH-EDGE
```

上はアクセススイッチの設定で、GigabitEthernet1/0/1 の先に正規の DHCPv6 サーバ(リレー)、GigabitEthernet1/0/10 に端末、GigabitEthernet1/0/12 に偽サーバを動かす不正端末がつながる。DHCPv6 guard が破棄するのは、サーバやリレーがクライアント向きに送る ADVERTISE と REPLY で、端末が送る SOLICIT/REQUEST は検査せず通す。この盤面で、正規サーバの応答が GigabitEthernet1/0/1 から入ると［①］。偽サーバの応答が GigabitEthernet1/0/12 から入ると［②］。その結果、端末 GigabitEthernet1/0/10 は RA は正常だが DNS やドメイン名を取得できない。`show device-tracking counters interface GigabitEthernet1/0/1` の Dropped 欄には［③］。是正として妥当なのは［④］。なお match server access-list でサーバ/リレーの送信元アドレスも検査でき、優先度は preference min/max で範囲を絞れる。

## 選択肢

A. device-role mismatch を含む理由が出る

B. GW ポートに付いた client ポリシーで破棄される

C. 是正不要(意図どおり)

D. match server access-list で破棄される

E. Message unauthorized on port が出る

F. GigabitEthernet1/0/1 のポリシーを device-role server(または trusted-port)にする

G. 端末ポートの client ポリシーで破棄される

H. server ポリシーなので検査を通って転送される
