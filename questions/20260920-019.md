# 問題 20260920-019

> **本問は機器に接続せずに解答すること。追加の show 実行は認めない。**

## 設問

次の説明文(設定例を含む)の空欄 ①〜④ に入る語句を、下の語群 A〜H から 1 つずつ選択してください。同じ語句を 2 つの空欄に使うことはありません。語群にはどの空欄にも当てはまらない語句が含まれます。

```
! ルータ側
snmp-server group NMS-GRP v3 priv read NMS-VIEW access 99
snmp-server user nms-poller NMS-GRP v3 auth sha CCNP-Auth-2026 priv aes 128 CCNP-Priv-2026
access-list 99 permit 192.168.100.20
!
! 管理ステーション(192.168.100.20)のポーリング設定
  user  : nms-poller
  level : authNoPriv
  auth  : SHA / CCNP-Auth-2026
  priv  : (未使用)
```

この盤面で管理ステーションから GET を送ると、返ってくるのは［①］。原因は group が要求する priv より弱い authNoPriv で要求している。USM は受け取った要求を［②］の順に処理するので、認証鍵の誤りはエラー応答として即座に見えるが、暗号鍵の誤りは復号に失敗した時点で黙って捨てられ、管理ステーションからは無応答にしか見えない。装置側では［③］でユーザの認証・暗号プロトコルと所属 group を確認できるが、鍵そのものは表示されないので、鍵の不一致は装置の表示からは割れない。是正は［④］。なお ACL の deny や到達性の問題も無応答になるため、無応答のときは鍵より先に `show access-lists` と ping で切り分ける。

## 選択肢

A. ユーザ名の照合 → 認証(ダイジェスト検証) → 復号

B. noSuchName

C. show snmp community

D. 管理ステーション側を authPriv で要求させる(または group を auth に下げる)

E. ACL → 復号 → 認証 → ユーザ名の照合

F. 管理ステーション側の暗号パスワードを装置の user と一致させる

G. show snmp user

H. authorizationError
