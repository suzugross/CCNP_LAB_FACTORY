# 問題 20260919-064

> **本問は機器に接続せずに解答すること。追加の show 実行は認めない。**

## 設問

次の説明文(設定例を含む)の空欄 ①〜④ に入る語句を、下の語群 A〜H から 1 つずつ選択してください。同じ語句を 2 つの空欄に使うことはありません。語群にはどの空欄にも当てはまらない語句が含まれます。

```
RT01# show aaa servers
RADIUS: id 1, priority 1, host 10.99.1.2, auth-port 1812, acct-port 1813, hostname RAD1
     State: current DEAD, duration 312s, previous duration 0s
     Dead: total time 0s, count 0
RADIUS: id 2, priority 2, host 10.99.2.2, auth-port 1645, acct-port 1646, hostname RAD2
     State: current UP, duration 4021s, previous duration 0s

radius-server dead-criteria time 3 tries 1
aaa group server radius RADGRP
 deadtime 5
```

サーバグループの 1 台目が落ちたとき、装置が毎回そのサーバでタイムアウトを待たされないようにするのが死活判定である。［①］は「何秒応答が無く、何回失敗したら DEAD とみなすか」の条件で、deadtime は DEAD とみなしたサーバを何分間スキップするかである。この 2 つは片方だけでは機能せず、判定条件が無いと［②］(実測)。上の出力で RAD1 の State が DEAD なので、以後 5 分間は RAD2 に直接問い合わせるので、ログインの待ち時間は 12 秒から［③］に縮む。RAD2 のポート 1645/1646 のように非標準ポートは許され、サーバ側と一致していれば動く。一致していなければ要求は届かず、そのサーバだけが DEAD になる。なお State が UP でも認証できないことはある(鍵不一致など)。DEAD は「［④］」であって「認証が通らない」ではない。

## 選択肢

A. 24 秒

B. radius-server deadtime

C. 認証を拒否した

D. 何回失敗しても UP のままで、スキップの出番が来ない

E. radius-server dead-criteria time/tries

F. 全サーバが DEAD になる

G. 6 秒程度(2 台目分だけ)

H. 応答が無かった
