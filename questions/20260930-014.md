# 問題 20260930-014

> **本問は機器に接続せずに解答すること。追加の show 実行は認めない。**

## 設問

次の説明文(設定例を含む)の空欄 ①〜④ に入る語句を、下の語群 A〜H から 1 つずつ選択してください。同じ語句を 2 つの空欄に使うことはありません。語群にはどの空欄にも当てはまらない語句が含まれます。

トンネルの宛先(NBMA)への経路をトンネル自身から学ぶと再帰ルーティング(トンネルが自分の中を通ろうとして落ちる) になる。p2p GRE では［①］が出て Tunnel が周期的に落ちるが、mGRE ではこのログが出ず、約 15 秒周期の EIGRP 隣接フラップと `show ip route <NBMA>` が via Tunnel0 になることで見抜く(実測)。原因の典型はハブが underlay の網をクラスフルな network 文でオーバーレイの IGP に広告してしまうことで、対策は［②］。旧来 3 行構文の `ip nhrp map multicast` の引数は［③］で、トンネル IP を書くとユニキャストは全部正常なのに EIGRP だけ retry limit でフラップする(実測)。同じ tunnel source を持つ複数の Tunnel に同じ IPsec プロファイルを貼るときは tunnel protection … shared(全 Tunnel に) が要り、片方だけに付けると設定が拒否される(実測)。稼働中の Tunnel で tunnel protection を変更すると Tunnel が自動的に shutdown されるので、作業手順に no shutdown を入れておく(実測)。underlay と overlay の経路表を分けたいときは［④］で tunnel source 側の IF と default route を別 VRF に置く。

## 選択肢

A. ハブの NBMA アドレス

B. underlay の経路をオーバーレイの IGP に入れない(NBMA への経路は WAN 向きの static/既定経路に限る)

C. ハブのトンネル IP

D. %TUN-5-RECURDOWN

E. %TUN-4-MTUCONFIG

F. tunnel key

G. tunnel key を両端で揃える

H. front-door VRF(tunnel vrf <名>)
