## Question

For each of the blanks ① through ④ in the following explanation (which includes a configuration example), select one term from choices A through H below. No term is used in two blanks. The choices include terms that do not fit any of the blanks.

```
radius-server timeout 3
radius-server retransmit 1
! (radius-server dead-criteria is not configured)
aaa group server radius RADGRP
 server name RAD1
 server name RAD2
 deadtime 5
!
RT01# show aaa servers
RADIUS: id 1, priority 1, host 192.168.100.11, auth-port 1812, acct-port 1813, hostname RAD1
     State: current UP, duration 4333s, previous duration 0s
RADIUS: id 2, priority 2, host 192.168.100.12, auth-port 1912, acct-port 1913, hostname RAD2
     State: current UP, duration 4021s, previous duration 0s
```

RAD1 (192.168.100.11) has been down for about 5 minutes. radius-server dead-criteria time/tries is the condition for how many seconds without a response and how many failures cause a server to be considered DEAD, and ［①］ specifies for how many minutes a server considered DEAD is skipped. Neither of the two works without the other. In the output above, the State of RAD1 is UP (not skipped) because ［②］, and a login now has a wait time of ［③］. The assessment of this configuration is that radius-server dead-criteria time 3 tries 1 should be added. ［④］ is permitted, as with ports 1912/1913 of RAD2, and works if it matches the server side. Note that DEAD is a determination that there was no response; authentication can still fail even when the state is UP (for example, a key mismatch).

## Choices

A. deadtime

B. 0 seconds

C. still 12 seconds (the RAD1 timeout is waited out every time)

D. dead-criteria

E. an IPv6 address

F. the criteria (time 3, tries 1) are met

G. there are no criteria, so the state does not change no matter how many failures occur

H. a non-standard port
