# 問題 GEN-RTCTL-52169 : 選択的経路制御の実装（難易度4）

## シナリオ

あなたは、ある企業のネットワーク・エンジニアです。図に示されているところの
ネットワークは、すでに基本的なコンフィギュレーションが完了しており、EIGRP AS 54194
および OSPF プロセス 84 の隣接関係は、確立されています。再配送は、まだ設定されて
いません。あなたのタスクは、以下のタスクを、順番に完了することです。
いくつかのタスクには、使用できる手段に関する制約が、含まれています。

```
        RT04 ── 拠点網(Loopback 群)
        /            \
     RT02            RT03        EIGRP AS 54194
        \            /
         RT01 ─────── RT05       OSPF 84 Area 0(RT05 の Loopback 群)
```

## 構成（初期状態で投入済み・変更不可）

| リンク | ネットワーク | 備考 |
|---|---|---|
| RT01 - RT02 | 10.1.12.0/30 | RT01 側 = Ethernet0/0（.1） |
| RT01 - RT03 | 10.1.13.0/30 | RT01 側 = Ethernet0/1（.1） |
| RT01 - RT05 | 10.1.15.0/30 | RT01 側 = Ethernet0/2（.1） |
| RT02 - RT04 | 10.1.24.0/30 | |
| RT03 - RT04 | 10.1.34.0/30 | |

RT04 が広告しているルート（EIGRP）:

- 172.19.128.0/24、172.19.129.0/25、172.19.130.0/26、172.19.131.0/24、172.19.136.0/24
- 10.41.2.0/24、10.41.7.0/24、10.41.9.0/24
- 192.168.234.0/24、192.168.59.0/24

RT05 が広告しているルート（OSPF）:

- 10.25.71.0/24、10.25.81.0/24、10.25.73.0/24、172.31.100.0/24

## タスク

**すべての作業は、RT01 の上で行われる必要があります。** 他のデバイスの構成を
変更してはいけません（採点で検出されます）。

### Task 1

RT01 のルーティング・テーブルで、10.41.2.0/24、10.41.7.0/24、10.41.9.0/24 への経路は、すべて **RT02 を経由**する必要があります。ただし、**10.41.9.0/24 だけ**は、**RT03 を経由**する必要があります。いずれかのリンクに障害が発生した場合には、もう一方の経路が、使用される必要があります。

### Task 2

RT01 が RT02 から学習するルートから、192.168.234.0/24 と 192.168.59.0/24 を除外してください。RT03 から学習されるルート、および、除外の対象ではないところのルートに、影響を与えてはいけません。

**制約**: この要件は、**CORP-IN-FILTER** という名前の標準アクセス・リストを使用した distribute-list で、実現される必要があります。除外の対象は、**deny エントリで指定**してください。それ以外のすべてのルートは、**包括の permit** によって通過させる必要があります。通過させるルートを、**個別に列挙する permit エントリの使用は、認められません**。

### Task 3

RT05 のルーティング・テーブルに、172.19.128.0/24、172.19.129.0/25、172.19.130.0/26、172.19.131.0/24 の 4 つのルートだけが、外部ルートとして現れるようにしてください。再配送の設定も、あなたが行います。

**制約**: このフィルタリングに、route-map を使用してはいけません。OSPF プロセスにおける、**プロトコル指定の distribute-list**（ACL 番号: **30**）で実現される必要があります。

### Task 4

OSPF ドメインのルートのうち、**10.25.71.0/24 と 10.25.81.0/24 だけ**を、EIGRP ドメインへ再配送してください。シード・メトリックには **100000 100 255 1 1500** を使用します。

**制約**: このフィルタリングに、route-map を使用してはいけません。EIGRP プロセスにおける、**プロトコル指定の distribute-list**（ACL 番号: **78**）で実現される必要があります。

### Task 5

追加の要件が、判明しました。**10.25.73.0/24 も**、EIGRP ドメインへ再配送される必要があります。

**制約**: ACL **78** の、既存のエントリを削除・再作成せずに、実現してください。

### Task 6

RT04 から、送信元を **172.19.128.1** として、**10.25.71.1** への ping が成功することを、確認してください。

## 注意

- 設定の変更が、ルーティング・テーブルに反映されるまでに、**最大で 1〜2 分**を
  要することがあります（clear コマンドは、必要とされません）。
- データ・プレーン（インターフェイスの IP アドレス / network 文）を、変更しては
  いけません。
