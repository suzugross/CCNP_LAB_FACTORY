# 問題 GEN-RTCTL-15723 : 選択的経路制御の実装（難易度4）

## シナリオ

あなたは、ある企業のネットワーク・エンジニアです。図に示されているところの
ネットワークは、すでに基本的なコンフィギュレーションが完了しており、EIGRP AS 6884
および OSPF プロセス 53 の隣接関係は、確立されています。再配送は、まだ設定されて
いません。あなたのタスクは、以下のタスクを、順番に完了することです。
いくつかのタスクには、使用できる手段に関する制約が、含まれています。

```
        RT04 ── 拠点網(Loopback 群)
        /            \
     RT02            RT03        EIGRP AS 6884
        \            /
         RT01 ─────── RT05       OSPF 53 Area 0(RT05 の Loopback 群)
```

## 構成（初期状態で投入済み・変更不可）

| リンク | ネットワーク | 備考 |
|---|---|---|
| RT01 - RT02 | 10.1.12.0/30 | RT01 側 = Ethernet0/0（.1） |
| RT01 - RT03 | 10.1.13.0/30 | RT01 側 = Ethernet0/1（.1） |
| RT01 - RT05 | 10.1.15.0/30 | RT01 側 = Ethernet0/2（.1） |
| RT02 - RT04 | 10.1.24.0/30 | |
| RT03 - RT04 | 10.1.34.0/30 | |

RT04 が広告しているルート（EIGRP）:

- 172.17.44.0/24、172.17.45.0/24、172.17.46.0/24、172.17.47.0/24、172.17.20.0/24
- 10.30.73.0/24、10.30.77.0/24、10.30.85.0/24
- 192.168.198.0/24、192.168.209.0/24

RT05 が広告しているルート（OSPF）:

- 10.58.34.0/24、10.58.37.0/24、10.58.40.0/24、172.23.100.0/24

## タスク

**すべての作業は、RT01 の上で行われる必要があります。** 他のデバイスの構成を
変更してはいけません（採点で検出されます）。

### Task 1

RT05 のルーティング・テーブルに、172.17.44.0/24、172.17.45.0/24 の 2 つのルートだけが、外部ルートとして現れるようにしてください。再配送の設定も、あなたが行います。

**制約**: フィルタリングには、**1 行の prefix-list**（名前: **PL-BRANCH24**）を使用すること。route-map（名前: **RM-REDIST-OUT**）を使用できるのは、RT01 のみです。

### Task 2

RT01 が RT03 から学習するルートから、192.168.198.0/24 と 192.168.209.0/24 を除外してください。RT02 から学習されるルート、および、除外の対象ではないところのルートに、影響を与えてはいけません。

**制約**: この要件は、**PL-EDGE-IN** という名前の prefix-list を使用した **distribute-list** で、実現される必要があります。除外の対象は、**deny エントリで指定**してください。それ以外のすべてのルートは、**包括の permit** によって通過させる必要があります。通過させるルートを、**個別に列挙する permit エントリの使用は、認められません**。

### Task 3

RT01 のルーティング・テーブルで、10.30.73.0/24、10.30.77.0/24、10.30.85.0/24 への経路は、すべて **RT02 を経由**する必要があります。ただし、**10.30.73.0/24 だけ**は、**RT03 を経由**する必要があります。いずれかのリンクに障害が発生した場合には、もう一方の経路が、使用される必要があります。

### Task 4

OSPF ドメインのルートのうち、**10.58.34.0/24 と 10.58.37.0/24 だけ**を、EIGRP ドメインへ再配送してください。シード・メトリックには **10000 1000 255 1 1500** を使用します。

**制約**: 実現の手段は、問いません。

### Task 5

追加の要件が、判明しました。**10.58.40.0/24 も**、EIGRP ドメインへ再配送される必要があります。

**制約**: 実現の手段は、問いません。

### Task 6

RT04 から、送信元を **172.17.44.1** として、**10.58.34.1** への ping が成功することを、確認してください。

## 注意

- 設定の変更が、ルーティング・テーブルに反映されるまでに、**最大で 1〜2 分**を
  要することがあります（clear コマンドは、必要とされません）。
- データ・プレーン（インターフェイスの IP アドレス / network 文）を、変更しては
  いけません。
