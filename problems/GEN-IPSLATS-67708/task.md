# 問題 GEN-IPSLATS-67708 : WAN 経路監視標準 適合トラブルシュート（難易度3）

## シナリオ

あなたは、ある企業のネットワーク管理者です。エッジルータ RT01 はデュアルホームで
2つの ISP（RT02 = primary / RT03 = backup）に接続されており、インターネット上の
サービス `9.9.9.9` に到達します。この会社の「WAN 経路監視標準（抜粋・下記）」に
従い、primary 経路の健全性を能動的に監視し、障害時には backup へ自動的に切り替える
必要があります。

先般、この監視に関する導入・変更作業が実施されました。その後、下記の障害報告が
提出されています。監視標準に完全に準拠するように、RT01 の構成を調査し、是正して
ください。

## 障害報告

> 監視導入後、外部向けトラフィックは一度も primary 経由へ切り替わっていません。監視の統計情報は成功を示している、と一次対応者は報告しています。

## トポロジ

```
RT01 ──10.239.107.0/30── RT02 ──10.239.60.0/30── RT04(Internet)
    ╲─10.239.186.0/30── RT03 ──10.239.27.0/30──┘
              （RT02↔RT03 間に inter-ISP リンク 10.239.191.0/30 あり）
```

- 各 /30 は RT01 側・ISP 側の順に .1/.2、アップリンクは ISP 側 .1・RT04 側 .2 です。
- RT01 の社内アドレス: `Loopback0 = 1.1.1.1`（データ通信の送信元）。
- `9.9.9.9` は primary / backup どちらの ISP からも到達可能です（データ用）。
- プロバイダは primary 経路の死活確認用に、**primary 経路（RT01→RT02→RT04）での
  み到達可能なヘルスビーコン `100.64.161.145`** を提供しています。backup ISP はこの
  ビーコンへの経路を持ちません。

## WAN 経路監視標準（抜粋）

1. **監視** — IP SLA **2** を使用し、**ICMP echo** でヘルスビーコン
   **`100.64.161.145`** を監視する。送信元は primary 側インタフェースのアドレス
   **`10.239.107.1`** とする。
2. **プローブ経路の固定** — ビーコン宛の /32 スタティックルートを primary
   next-hop **`10.239.107.2`** へ固定する（プローブがデフォルトルートに依存
   しないこと）。
3. **トラッキング** — Track **95** で IP SLA 2 の
   **reachability** を監視する。
4. **経路切替** — default route は、通常時 primary **`10.239.107.2`**
   （Track 95 連動）、障害時 backup **`10.239.186.2`**
   （AD **180** のフローティングスタティック）とする。
5. **スケジュール** — 監視は **恒久的（life forever, start-time now）**に実行する。
6. **是正の完全性** — 監視標準に含まれないオペレーション定義や、監視を阻害する
   フィルタを残置しないこと。

## 遵守事項

- **RT02 / RT03 / RT04 はプロバイダ管理機器です。参照は可能ですが、変更しては
  いけません。**設定を変更してよいのは RT01 のみです。
- RT01 のインタフェースアドレス・Loopback0 は変更してはいけません。
- 原因の種類・箇所・数は開示されません。監視標準と実機の状態を突き合わせて
  差分を特定してください。

## アクセス・採点

SSH `SUZUKI / CCNP`（mgmt は割当順）または CML コンソール。
```
ansible-playbook playbooks/grade.yml -e problem=GEN-IPSLATS-67708 --vault-password-file <(printf 'CCNP\n')
```
> 採点では、監視の定義・稼働状態・経路構成に加え、`9.9.9.9` への実疎通を確認
> します。任意で、奥障害（RT02↔RT04）の注入と切替・復帰の実証を行うには:
> `ansible-playbook playbooks/verify_ipsla_generated.yml -e problem=GEN-IPSLATS-67708`
