# 模範解答 : GEN-REDISTLOOP-3357(variant=ad_eigrp)

## なぜ壊れるか(再配送リングのループ)
`192.168.51.0/24` は RE が **BGP** で起点広告し、RC が **iBGP(AD 200)** で学習する。
再配送が **BGP → OSPF → EIGRP** のリングを成すため、この経路の出自がドメインを一周して RC に戻る。
戻ってきた経路は **EIGRP 外部(D EX・AD 170)** で、その **AD が iBGP(200)より低い**ため RC はそれを優先し、
`192.168.51.0/24` 宛を EIGRP 側へ転送してしまう → **RC → RA → RB → RC** の定常転送ループ。

RC は RIB 勝者プロトコルを再配送源にするので、BGP だけでなく戻り側 IGP も OSPF へ再配送して
P を常時循環させている(＝振動でなく定常ループに固定)。

## 解(RC)
BGP の管理距離を戻り経路の AD(**170**)未満に下げ、RC が **iBGP(＝起点 RE 方向)** を選ぶ。

```
router bgp 65000
 distance bgp 20 165 165
```

### ★変更後は経路の再計算が必要
`distance` は既にインストール済みの経路に即時反映されない。RC で

```
clear ip route *
```

を実行して初めて iBGP が採用される(実行前は BGP エントリが `RIB-failure(17)` のまま)。

## 確認
- RC: `show ip route 192.168.51.0` が **`Known via "bgp 65000"`**(`eigrp 100` ではない)。
- RC/RB/RA から `traceroute 192.168.51.1` が **RE に一直線**(3台を回らない)。

## 別解(効果ベース採点なのでいずれも可)
- **`distance eigrp 90 201`**(戻り側の外部経路 AD を iBGP 200 超へ)＝ RC が iBGP を優先。
- **経路タグ / フィルタ**: RC が BGP→OSPF 再配送時に `set tag`、戻ってきた自ドメイン発を
  RC の学習側で `distribute-list ... in` 遮断(プレフィックスリスト等)。
- **不可**: いずれかの再配送を丸ごと削除して回避、静的経路・デフォルトでの回避。

## 教育核心(再配送リング×AD反転 型)
- 多点再配送がドメインをまたいで **リング**を成すと、経路の出自が一周して戻る。戻り経路の AD が
  元の学習元より低いとループ/振動する。
- 既定 AD(eBGP 20・EIGRP内部 90・OSPF 110・EIGRP外部 170・**iBGP 200**)の並びは必修。
  **iBGP は最も信用されない(200)** ため、iBGP 経路を IGP へ再配送するとこの罠を踏みやすい。
