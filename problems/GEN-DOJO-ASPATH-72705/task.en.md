# Problem GEN-DOJO-ASPATH-72705 : as-path access-list Dojo (10 drills, difficulty 3)

## About This Problem (form practice)

The upstream router **RT02 (FEEDER)** is a route generator for testing. It has
**four parallel eBGP sessions** with RT01 and, acting as a different neighboring AS on each
(**AS65099 / AS65010 / AS65020 / AS65030**),
advertises a set of routes (the battery) with a wide variety of **AS_PATH** values.
**AS65100 / AS65200 / AS65300** appear in the paths as transit/origin ASs.
RT01 itself also injects two local routes (empty AS_PATH) into BGP.

On **RT01 (AS65001)**, for each of the 10 small tasks below,
**define one ip as-path access-list with the specified number**. That is the entire problem.

- The as-path access-lists only need to be **defined** (applying them to a neighbor is not required).
- Scoring is not based on how the regular expression is written, but on the semantic match of
  "**which routes are permitted and which routes are dropped**" (1 task = 10 points, no partial credit).

## Topology

```
  RT01 (TARGET, AS65001)  Lo0=1.1.1.1  + 2 local routes (empty AS_PATH)
    ||||  <- 4 parallel eBGP sessions (1 directly connected + 3 between loopbacks)
  RT02 (FEEDER)  <- advertises the battery as AS65099/65010/65020/65030 (do not change)
```

## How to Practice (self-check)

- Observe the whole battery and the AS_PATHs: `show ip bgp` (read the Path column)
- Verify the effect of your list **on the spot**: `show ip bgp filter-list <number>`
  (read-only. It displays the list applied to the BGP table and does not affect the sessions)
- Try a regular expression (without defining a list): `show ip bgp regexp <regular expression>`

## Tasks (the list numbers must match exactly)

### Task 1 — list number `1`

> Permit all routes **received from neighboring AS 65030** (the AS_PATH begins with 65030), regardless of which AS is the origin.

### Task 2 — list number `2`

> Permit all routes that **contain AS 65300** anywhere in the AS_PATH (regardless of position). Do not permit anything else.

### Task 3 — list number `3`

> Permit all routes **received from neighboring AS 65020** (the AS_PATH begins with 65020), regardless of which AS is the origin.

### Task 4 — list number `4`

> Permit all routes **originated by AS 65100** (the AS_PATH ends with 65100). Do not permit routes that only transit it.

### Task 5 — list number `5`

> Permit only the routes that are received directly from neighboring AS **65099** and are also **originated by AS 65099 itself** (no other AS appears in the AS_PATH).

### Task 6 — list number `6`

> Permit only the routes **generated by RT01 itself** (routes with an empty AS_PATH). Do not permit any route received from outside.

### Task 7 — list number `7`

> Permit all routes **originated by AS 65200** (the AS_PATH ends with 65200). Do not permit routes that only transit it.

### Task 8 — list number `8`

> Permit only the routes that **transit AS 65100 but are not originated by AS 65100** (extract the routes that passed through 65100 only as a transit).

### Task 9 — list number `9`

> Permit all routes whose origin is either **AS 65100 or AS 65300**. Do not permit anything else.

### Task 10 — list number `10`

> Permit only the routes that **transit AS 65200 but are not originated by AS 65200** (extract the routes that passed through 65200 only as a transit).

## Restrictions

1. **Changing the configuration of RT02 (FEEDER) is not allowed** (checking its state with show commands is allowed).
2. **Changing the BGP, interface, and routing configuration of RT01 is not allowed**
   (the work is only the definition of ip as-path access-lists).
3. The list numbers must match the task specification (`1` through `10`).
