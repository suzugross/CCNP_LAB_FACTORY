# 問題 GEN-EGVRF-9153 : VRF-aware EIGRP 収容標準 適合トラブルシュート（難易度5）

## 状況

共有集約ルータ **RT02** に、昨夜 前任者が 2テナントの EIGRP 収容作業を実施した。
今朝から下記のトラブルチケットが届いている。社内の**マルチテナント収容標準
（抜粋・下記）に完全準拠**するよう調査・是正せよ。

```
RT01 (テナントA site1) ──10.204.140.0/30──┐e0/0
  Lo1 172.31.178.1/24  Lo2 172.31.179.1/24 │
                                        RT02 (共有集約・被疑)
RT04 (テナントA site2) ──10.204.141.0/30──┤e0/1
  Lo1 172.31.157.1/24                    │
                                            │e0/2
RT03 (テナントB site1) ──10.204.142.0/30──┘
  Lo1 172.31.178.1/24  Lo2 172.31.179.1/24  Lo3 172.31.242.1/24
  (★Lo1/Lo2 はテナントAと意図的に重複)
```

## トラブルチケット

> 1. テナントA site2 のルータに、収容標準で禁止されている**明細経路**が見えている。逆に site1 側 CE には不要な集約経路が広告されている。
> 2. テナントA site1 のみ不通。site2 は正常(「同じテナントなのになぜ」と顧客)。

## マルチテナント収容標準（抜粋）

1. **VRF**: `TENANT-A` (rd **65000:110**) = `Ethernet0/0`, `Ethernet0/1` /
   `TENANT-B` (rd **65000:200**) = `Ethernet0/2`。リンクアドレスは現行計画を維持。
2. **EIGRP**: named mode の単一仮想インスタンス **`CORPNET`** に両テナントの
   アドレスファミリを収容。テナントA = **AS 110** / テナントB = **AS 200**。
3. **認証**: テナントA の CE 向け IF は **MD5**
   (key chain **`KC-DC1`** / key **7** / key-string **`Ten4016Key`**)。
4. **集約**: テナントA site2 (RT04) へは site1 の 2 つの /24 を
   **`172.31.178.0/23` に集約して広告**。site2 に明細 /24 を見せない。
5. **分離**: テナント間で経路が混ざらないこと。

## 遵守事項

- 設定変更は **RT02 のみ**。CE 3台(RT01/RT03/RT04)は変更禁止（show・ping は可）。
- 収容の**撤去・作り直しによる「復旧」は不可**（収容標準の名前・値に一致させる）。
- 静的ルート・再配送は使用しない。

## 切り分けの観点

- 原因の種類・場所・数は伏せている。収容標準と実機状態を突き合わせること。
- チケットは各顧客の**申告時点の記述**であり、相互に矛盾して見える場合は
  複数原因が重なっているサインと考えること。
- 採点は設定の字面に加え、**経路・疎通の実効**まで見る。
