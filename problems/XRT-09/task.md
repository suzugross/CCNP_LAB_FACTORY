# XR Track 09 — L3VPN

このラボは、XR トラックの単元 **M9 L3VPN** の実践編です。ラボ XRT-07 の終わったところから続きます。コアは同じで、
XR01 は課題 M8-1〜M8-5 を終えた状態から始まります。先に単元のページ「M9 — L3VPN」を読んでから、ここで課題に
順番に取り組みます。各課題は前の課題の上に積み上げます。

## 進め方の約束

- 設定するのは **XR01** と、課題 M9-2 からは **XR02** です。他のルータはすべて据え付けで、変更しないでください。
  確認のためにログインするのは構いません。CE、SVC、INET は、顧客、共有サービス、インターネットのものです。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。IOS ルータとの BGP セッションは、上がるまでに最大 1 分かかることがあり、
  IOS ルータが学習したばかりのルートを次に渡すまでに、さらに最大 1 分かかることがあります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は **IOS XRv 9000** 26.1.1 で動作しています。XR02 は **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。
  XR02 はルート リフレクタで、転送パスの外にあります。
- XR01 の顧客側のインターフェイス(GigabitEthernet0/0/0/2〜0/0/0/5)には、説明だけがあり、アドレスはありません。

  送るものを受け入れます。SVC はルーティング プロトコルを実行しません。XR01 に向けたスタティックなデフォルト ルートを持っています。

## M9 — L3VPN

### 課題 M9-1

顧客 A と顧客 B は、新しい VPN の顧客です。2 つ目のサイトは RT02 で既にサービスを開始しており、1 つ目のサイトは XR01 に
接続されています。

- 顧客 A のサイト 1(CEA1)と顧客 B のサイト 1(CEB1)を、表の VRF、ルート識別子、ルート ターゲットで XR01 に接続してください。
  インターフェイスには表のとおりにアドレスを設定します。
- CEA1 と CEB1 とは eBGP でルートを交換してください。XR01 は、それらがアドバタイズするすべてのルートを受け入れ、
  それぞれの VPN のルートをそれらにアドバタイズする必要があります。
- XR01 は、ルート リフレクタ XR02 とだけ、自分の Loopback0 からのセッションで VPN のルートを交換する必要があります。
  XR01 と RT02 の間に VPNv4 のセッションを作成しないでください。
- この課題では XR02 を変更しないでください。

### 課題 M9-2

課題 M9-1 の後も、同じ顧客のサイトどうしが互いに到達できません。同僚が変更 CHG-1201 で、XR02 を XR01 と RT02 の
VPNv4 ルート リフレクタとして設定し、XR02 は両方のプロバイダー エッジのルートを保持していると報告しています。

- 各顧客の 2 つのサイトの LAN が、両方向で互いに到達できるようにしてください。10.101.1.0/24 と 10.101.2.0/24、
  10.102.1.0/24 と 10.102.2.0/24 です。
- 顧客 A と顧客 B は、互いに到達できてはなりません。
- XR01 と XR02 は変更して構いません。CE と RT02 は変更せず、XR01 と RT02 の間に VPNv4 のセッションを作成しないでください。

### 課題 M9-3

プロバイダーは、XR01 の背後の SVC から共有サービスを提供します。サーバは 10.99.1.0/24 にあり、10.99.2.0/24 は
プロバイダーの内部用です。

- 表の VRF SVC で、SVC を XR01 に接続してください。XR01 は、スタティック ルートで SVC のネットワークに到達します。
- 顧客 A と顧客 B のすべてのサイトが 10.99.1.0/24 に到達でき、SVC が両方の顧客のすべてのサイトに到達できる必要があります。
  顧客のサイトが 10.99.2.0/24 を学習してはなりません。顧客 A と顧客 B は、引き続き互いに到達できてはなりません。
- SVC のルートに関するプロバイダーの規約: すべてのルートにルート ターゲット 65000:999 を付け、10.99.1.0/24 には加えて
  65000:900 を付けます。SVC の他のルートに 65000:900 を付けてはなりません。

### 課題 M9-4

顧客 A は、公開セグメント(サイト 1 の 198.51.100.0/25 とサイト 2 の 198.51.100.128/25)のためにインターネット接続を購入します。
INET(AS 64500)は、グローバル ルーティング テーブルで XR01 に接続され、デフォルト ルートと 203.0.113.0/24 をアドバタイズします。

- グローバル ルーティング テーブルで、XR01 と INET の間に eBGP を実行してください。
- 顧客 A の両方のサイトがデフォルト ルートを学習し、それらの公開セグメントが両方向で 203.0.113.0/24 に到達できる必要があります。
- INET は、顧客 A の 2 つの公開セグメントを学習し、AS 65000 からそれ以外のルートを学習してはなりません。
- 顧客 B はデフォルト ルートを学習してはなりません。
