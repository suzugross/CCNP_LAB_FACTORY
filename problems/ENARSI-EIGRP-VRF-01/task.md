# 問題 ENARSI-EIGRP-VRF-01 : VRF-Lite × EIGRP named mode マルチテナント収容

## シナリオ
データセンターの共有集約ルータ **RT02** に、2つのテナントを収容することになった。

- **テナントA**: 2拠点(RT01 = site1 / RT04 = site2)。EIGRP **AS 100**。
- **テナントB**: 1拠点(RT03 = site1)。EIGRP **AS 200**。

両テナントは統合前の名残で **同じ 172.16.0.0/16 のアドレス計画を重複使用**している
(テナントAのsite1とテナントBのsite1はどちらも 172.16.10.0/24・172.16.11.0/24 を持つ)。
RT02 に VRF-Lite を構成し、テナント毎に完全に分離したルーティングを提供せよ。

```
RT01 (A-site1)  ──10.10.1.0/30──┐
  Lo1 172.16.10.1/24            │e0/0
  Lo2 172.16.11.1/24            │
                              RT02 (共有集約・受験者スコープ)
RT04 (A-site2)  ──10.10.2.0/30──┤e0/1
  Lo1 172.16.20.1/24            │
                                │e0/2
RT03 (B-site1)  ──10.20.1.0/30──┘
  Lo1 172.16.10.1/24  ← テナントAと重複
  Lo2 172.16.11.1/24  ← テナントAと重複
  Lo3 172.16.30.1/24
```

## 既設構成(変更しないこと)
- CE 3台(RT01/RT03/RT04)は**設定済み・変更禁止**。
  - テナントAのCEは EIGRP AS100(classic)で、RT02向けIFに **MD5認証**
    (key chain `KC-A` / key 1 / key-string `Suzu2026A`)を設定済み。
  - テナントBのCEは EIGRP AS200(classic)・認証なし。
- RT02 の各IFにはリンクアドレスが投入済み。**現状のアドレス計画を維持すること**。

## 到達目標(RT02 にのみ設定)

1. **VRF**: テナント毎のVRFを作成し、対応するIFを収容する。
   - `TENANT-A` (rd **65000:100**) … `Ethernet0/0`(RT01向け), `Ethernet0/1`(RT04向け)
   - `TENANT-B` (rd **65000:200**) … `Ethernet0/2`(RT03向け)
2. **EIGRP**: 会社標準に従い、**named mode の単一仮想インスタンス `SUZUNET`** で
   両テナントのアドレスファミリを収容する。
   - テナントA = **AS 100** / テナントB = **AS 200**
   - 各CEと隣接が確立すること(テナントAは**認証込み**で)。
3. **経路集約**: テナントAの site2(RT04)へは、site1 の2つの/24を
   **1本 (`172.16.10.0/23`) に集約して広告**する。site2 には明細/24を見せないこと。
4. **分離**: テナント間で経路が混ざらないこと。両テナントの重複プレフィックスが
   RT02 上でそれぞれのVRFに共存していること。

## 動作確認の目安
- RT04 から 172.16.10.1 への ping(送信元 172.16.20.1)が成功する。
- RT02 からテナントBの 172.16.30.1 への ping が成功する。
- RT02 の各VRFの経路テーブルに、172.16.10.0/24 がそれぞれ別の隣接から載っている。

## 制約
- 設定変更は **RT02 のみ**。CEへのログインは確認(show)のみ可。
- 静的ルート・再配送は使用しない(EIGRPのネイティブ機能だけで構成する)。
