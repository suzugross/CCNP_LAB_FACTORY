# 問題 ENCOR-DHCP-01 : DHCPv4 一気通貫（配布・固定割当・リレー・DHCP-only ACL）

## シナリオ

社内 3 セグメントのアドレス配布を **RT01 の IOS DHCP サーバに集約**する。
リモートセグメントは **RT02 をリレーエージェント**にして届ける。
さらにセキュリティ標準により、クライアント収容 IF では
**DHCP と ICMP 以外の通信を遮断**する。

```
CL3 ── RT01(DHCPサーバ) ──10.0.12.0/30── RT02(リレー) ─┬─ CL1  (segment A)
10.0.10.0/24 (LOCAL)      .1        .2                 └─ CL2  (segment B)
                                            A: 10.0.20.0/24 / B: 10.0.30.0/24
```

- RT01: `E0/0`=10.0.12.1 (RT02 向け) / `E0/1`=10.0.10.1 (CL3 収容)
- RT02: `E0/0`=10.0.12.2 / `E0/1`=10.0.20.1 (CL1 収容) / `E0/2`=10.0.30.1 (CL2 収容)
- CL1/CL2/CL3 の対象 IF (`Ethernet0/0`) は **IP 未設定**（DHCP で取得させる）

## 要件

1. **配布と取得（ローカル）** — RT01 に LOCAL セグメント用プールを作り、CL3 が取得する。
2. **MAC(識別子)指定の固定割当** — CL1 には必ず **`10.0.20.50`** を割り当てる。
   CL1 の MAC アドレス／DHCP 識別子は**実機で調査**すること。
3. **リレーエージェント** — RT02 経由で segment A / B のクライアントに配布する。
4. **DHCP-only ACL** — RT02 の**両クライアント収容 IF (E0/1・E0/2) の in** に、
   **DHCP (UDP 67/68) と ICMP のみ許可**する ACL を適用する（他は遮断）。
   適用後も**取得（初回含む）・更新が壊れないこと**。

## 指定値（採点が固定値で判定する）

- プール名: LOCAL=**`NET10`** / segment A=**`NET20`** / segment B=**`NET30`**、
  固定割当プール=**`CL1-FIXED`**
- 各プール: default-router は各セグメントの GW (`.1`)、DNS サーバ **`198.51.100.53`**
- **各セグメント `.1`〜`.9` は配布禁止**（excluded）
- CL1 固定 IP: **`10.0.20.50`**
- ACL 名: **`DHCP-ONLY`**（named ACL・RT02 の E0/1 と E0/2 に in 適用）。
  最終行に**明示の `deny ip any any`** を置くこと（遮断実績をカウンタで監査するため）
- クライアント側: CL1/CL2/CL3 の `Ethernet0/0` で DHCP 取得

## 遵守事項

- RT01/RT02 の**既設 IP アドレス・静的経路は変更禁止**。
- ルーティングプロトコルの追加は禁止（このラボに不要）。
- クライアントのアドレスを手動設定して「取得した事」にするのは不可
  （採点はサーバ側バインディングと release/renew の実効まで確認する）。
