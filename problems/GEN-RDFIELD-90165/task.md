# 問題 GEN-RDFIELD-90165 : 経路到達性障害チケット(難易度5)

## 状況
社内網は **OSPF 17 ドメインと EIGRP AS 301 ドメイン**を、**境界2台(RT05、RT01)** の
相互再配送で結ぶ冗長構成である。昨夜、境界まわりの作業が行われた形跡があり、
今朝から下記のチケットが届いている。**社内の収容標準(下記)に完全準拠**するよう調査・是正せよ。

## リンク一覧(L2 直結・アドレスは /30 の .1/.2)

```
  RT04 ── RT05   (OSPF 17 area 0 / 10.201.90.0/30)
  RT04 ── RT01   (OSPF 17 area 0 / 10.58.42.0/30)
  RT05 ── RT01   (EIGRP AS 301 / 10.53.199.0/30)
  RT05 ── RT02   (EIGRP AS 301 / 10.150.80.0/30)
  RT01 ── RT02   (EIGRP AS 301 / 10.199.186.0/30)
  RT02 ── RT03   (EIGRP AS 301 / 10.52.76.0/30)
```

## ルータ / 参加プロトコル / Loopback

| ルータ | 参加プロトコル | Loopback |
|--------|----------------|----------|
| RT01 | OSPF 17 / EIGRP AS 301 | `70.70.70.70/32` |
| RT02 | EIGRP AS 301 | `17.17.17.17/32` |
| RT03 | EIGRP AS 301 | `56.56.56.56/32` |
| RT04 | OSPF 17 | `5.5.5.5/32` |
| RT05 | OSPF 17 / EIGRP AS 301 | `68.68.68.68/32` |

## トラブルチケット(申告のみ・裏取りはあなたの仕事)
> 1. **RT02 側の拠点**から OSPF 側の宛先に**届かない**との申告(方向・範囲の裏取りはまだ)。

## 収容標準(抜粋)
1. 境界2台は OSPF⇄EIGRP の**相互再配送**を行い、**全ルータの Loopback が相互到達**すること。
2. **EIGRP への注入は seed metric `100000 100 255 1 1500` を必須**とする。
3. **2点相互再配送の再注入対策**: OSPF 出自の経路には**タグ `254` を付与**し、
   境界の **EIGRP 受信(in)で自ドメイン発(タグ `254`)を遮断**すること。
4. **EIGRP の AD は internal 90 / external 95 に固定(変更不可・会社ポリシー)**。
5. 経路は**最短**であること(再配送由来の次善経路・ループの残存は不適合)。

## 制約
- 設定変更してよいのは境界2台(RT05、RT01)のみ。他は変更禁止(show・ping・traceroute は可)。
- 静的経路・デフォルトルート・AD 変更・ドメイン構成の変更による回避は不可。

## 備考
※ 設定変更後に経路が変わらない時は `clear ip route *` で再計算する。
