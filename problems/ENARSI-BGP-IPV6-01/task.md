# 問題 ENARSI-BGP-IPV6-01 : デュアルスタック BGP のトラブルシュート（難易度4）

## 状況
3 つの AS が eBGP で数珠つなぎになった **デュアルスタック（IPv4 / IPv6 両対応）** の
ネットワーク。各リンクは IPv4 と IPv6 の両方でアドレス付けされ、各ルータの
`Loopback0` を **IPv4(/32) と IPv6(/128) の両方**で BGP 広告する設計。

```
 RT01(AS65001) ═══ RT02(AS65002) ═══ RT03(AS65003)
   Lo0                Lo0                Lo0
 1.1.1.1/32         2.2.2.2/32         3.3.3.3/32
 2001:DB8:1::1      2001:DB8:2::2      2001:DB8:3::3
```

## トラブルチケット（代表症状）
> **IPv4 は全拠点間で問題なく到達できる。** ところが **IPv6 の通信が成立しない** —
> RT01 から RT03 の IPv6 Loopback (`2001:DB8:3::3`) へ届かない、という申告。
> 「IPv4 が正常なのだから BGP は動いているはず」と言われているが、直らない。

## 設計書（＝あるべき姿）
- 各リンク: IPv4 `/30`（10.1.12.0/30・10.1.23.0/30）＋ IPv6 `/64`
  （`2001:DB8:12::/64`・`2001:DB8:23::/64`）。
- BGP は **MP-BGP 書式**（`no bgp default ipv4-unicast` ＋
  `address-family ipv4 unicast` / `address-family ipv6 unicast` で **各ネイバーを
  activate**）。
- 各ルータは自分の `Loopback0` を **IPv4 と IPv6 の両アドレスファミリで network 広告**。
- 全ルータが、全ルータの Lo0 へ **IPv4 でも IPv6 でも到達**できること。

## ルータ台帳
| ルータ | AS | Lo0 (IPv4 / IPv6) | mgmt(SSH) |
|--------|-----|-------------------|-----------|
| RT01 | 65001 | `1.1.1.1` / `2001:DB8:1::1` | 割当順 10.1.10.11〜 |
| RT02 | 65002 | `2.2.2.2` / `2001:DB8:2::2` | 〃 |
| RT03 | 65003 | `3.3.3.3` / `2001:DB8:3::3` | 〃 |

## 到達目標
1. すべてのルータが、全 Lo0 の **IPv4 経路**を学習し到達（現状すでに満たされている）。
2. すべてのルータが、全 Lo0 の **IPv6 経路**を学習し到達。
   - `RT01: ping 2001:DB8:3::3 source Loopback0` が成功すること。
   - `RT03: ping 2001:DB8:1::1 source Loopback0` が成功すること（戻りも）。

## 制約
- IPv4 側は健全。**触るのは IPv6 に関わる設定のみ**でよい（IPv4 を壊さないこと）。
- スタティックルート・再配布による回避は不可（BGP のみで解決）。
- アドレッシング（IF の IP）と AS 設計は変更しない。

## 診断のヒント（控えめ）
- **「IPv4 で ping が通る＝ BGP 健全」ではない。** デュアルスタックでは IPv4 と IPv6 は
  **別々のアドレスファミリ**として独立して動く。IPv4 の見え方に惑わされないこと。
- 各機で `show bgp ipv6 unicast summary` を見よ。**IPv6 のセッションはどうなっているか**
  （IPv4 とは別に AFI/SAFI をネゴシエートする）。次に `show bgp ipv6 unicast` で
  **どの経路が来て・どの経路が来ていないか**、`show ipv6 route` で RIB を確認。
- 「セッションが上がらない」「セッションは上がるが経路が無い」「経路はあるが転送されない」
  は別々の原因。IPv6 を **端から端まで**（広告 → 交換 → 転送）追うこと。
