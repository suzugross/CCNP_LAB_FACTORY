# JUNOS-BUILD-01: Junos 基礎組み立て — 隣社の PTX を預かることになった

> **チケット #4101**: 提携先(スズグロス・パートナーズ)のラック統合に伴い、先方持ち込みの
> Juniper ルータ **JUN01** を弊社バックボーン(OSPF area 0)に参加させることになった。
> 機器はラック据付・結線・管理アクセスまで完了しているが、**中身はまっさら**である。
> 先方の運用規定により、投入は「誤設定時に自動復旧できる安全な方法」で行うこと。

- 難易度: ★★★ (Junos 初体験を想定した組み立て問)
- 対象機器: **JUN01 のみ**(Cisco RT01/RT02 は据え付け・**変更禁止**)
- アクセス: `ssh admin@172.20.20.2`(パスワード: admin@123)。CML コンソールは使いません

## トポロジ

```
RT02 ────── RT01 ────────────── JUN01   ← あなたが設定する
2.2.2.2     1.1.1.1      et-0/0/0 (10.0.12.1/30)
   10.77.12.0/30  10.0.12.0/30   lo0: 192.168.0.1/32
              全て OSPF area 0
```

- RT01 の対向 IF は 10.0.12.2/30 で稼働済み(OSPF area 0)

## 要件

1. ホスト名を `JUN01` にする
2. `et-0/0/0` に 10.0.12.1/30 を設定する
3. ループバック `lo0` に 192.168.0.1/**32** を設定し、**router-id も 192.168.0.1 に明示**する
4. OSPF area 0 を有効化: et-0/0/0 で隣接を張り、lo0 は **passive** で収容する
5. 社内サービス網の代表経路として **static route 172.16.10.0/24 discard** を作成し、
   **ポリシー(policy-statement)を使って OSPF に広告**する(RT02 から外部経路として見えること)
6. 最終確認: JUN01 の lo0 から 2.2.2.2 へ ping が通ること
7. **作法要件**: 少なくとも1回は「誤設定時に自動ロールバックされる安全なコミット方法」で
   投入すること(コミット履歴で採点します)

## Junos 作法チートシート(基本形のみ)

Cisco との対応を最低限だけ。**具体的な設定コマンドは自分で探すこと**(`?` 補完と
`show … | compare` が友達です)。

| やりたいこと | Junos |
|---|---|
| 設定モードに入る | `configure` |
| 設定を書く/消す | `set …` / `delete …` |
| 投入前に差分を見る | `show | compare` |
| 反映する | `commit`(※要件7の「安全な方法」は別にある) |
| 直前に戻す | `rollback 1` → `commit` |
| 設定を set 形式で見る | `show configuration | display set` |
| 候補設定を捨てて出る | `rollback 0` → `exit` |

ヒント: Junos の設定は commit するまで機器に**一切反映されません**(candidate config)。
Cisco の「打った瞬間反映」との最大の違いです。

## 採点(100点)

設定監査(JUN01)＋隣接の両面確認＋据え付け Cisco 側から見た経路伝搬効果＋E2E＋作法。
RT01/RT02 を変更した場合は採点対象外の操作です(変更禁止)。
