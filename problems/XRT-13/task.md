# XR Track 13 — The MPLS Services Side by Side

このラボは、XR トラックの「MPLS のサービスを並べて見る」の実践編です。コアだけがあり、ほかには何もないネットワークから、
1 つの顧客のために 5 つのサービスを構築します。IP VPN、LDP の疑似回線による E-Line、VPLS による E-LAN、EVPN による E-LAN、
EVPN-VPWS による E-Line です。読み物の 2 つのページ「サービスを並べて見る」と「組み立て順」は、同じトポロジを別の値で
使っています。課題の前にそれらを読み、ここで課題に順番に取り組みます。

## 進め方の約束

- 設定するのは **XE1**、**XE2**、**XE3**、**XR01** です。P1、RR1、CE は据え付けで、変更しないでください。確認のためにログインするのは
  構いません。CE は顧客のものです。
- 各課題は、必要な動作を記述しています。読み物の各ページには、同じ種類のサービスの設定例が別の値で載っています。
  CLI のヘルプ(`?`)、`show` コマンド、IOS XE と IOS XR の Cisco のコンフィギュレーション ガイドとコマンド リファレンスも使えます。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取り、サービスの段ごとに結果を分けて
  示すので、どこで止まっているかが分かります。押す前にコンフィギュレーション モードを抜けてください。変更の後は、
  LDP と BGP が落ち着くまで 30 秒ほど待ってください。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XE1、XE2、XE3 は **Catalyst 8000V** 17.15.1a で、ブート ライセンスのレベルは `network-advantage` です(MPLS を使えます)。
  IOS XE にはコミットがなく、各行は入力した時点で有効になります。XR01 は **IOS XRv 9000** 26.1.1 で、変更はコミットした時点で
  有効になります。P1 と RR1 は IOS XE 17.15 のルータです。

  サイト番号をホスト部に持ちます(たとえば 172.31.33.2 は CE2 です)。サービスに端ごとの識別子が必要な場合、端の識別子は
  そのサイトの番号です。

## サービスを並べて見る

### 課題 S-1

顧客 D の IP VPN は、VLAN 310 でサイト 2、3、4 を接続します。

- プロバイダー エッジでは、顧客を VRF **CUST-D** に収容します。各プロバイダー エッジのルート識別子は、その Loopback0 の
  アドレスに `:310` を付けたものです。VRF はルート ターゲット **65000:310** をインポートおよびエクスポートします。
- プロバイダー エッジは、ルート リフレクタ RR1 を経由してだけ VPN の経路を交換します。2 台のプロバイダー エッジの間に
  BGP のセッションがあってはなりません。各プロバイダー エッジの BGP のルータ ID は、その Loopback0 のアドレスです。
- サイト 2 と 4 では、顧客はプロバイダーと eBGP を実行します(CE2 は AS 65102、CE4 は AS 65104)。サイト 3 の CE は
  ルーティング プロトコルを実行せず、プロバイダーへのデフォルト ルートを持ちます。それでもプロバイダーは、サイト 3 の LAN
  (10.30.3.0/24)をほかのサイトへ伝えます。
- 各サイトは、ほかの 2 つのサイトの LAN に到達できます。

### 課題 S-2

- 顧客 D のフレームを、サイト 3(VLAN 320)とサイト 4(VLAN 321)の間で 1 本のポイントツーポイントの回線
  (172.31.32.0/24)として運んでください。疑似回線 ID **320** の、LDP でシグナリングする疑似回線を使います。
- この回線は BGP を使いません。

### 課題 S-3

- 顧客 D のフレームを、サイト 1、2、3(VLAN 330)の間で 1 つの LAN(172.31.33.0/24)として運んでください。VPN ID **330**、
  LDP のシグナリングの VPLS を使います。
- どのサイトも、ほかの 2 つのサイトに到達できます。

### 課題 S-4

- 顧客 D のフレームを、サイト 1、2、3(VLAN 340)の間で 1 つの LAN(172.31.34.0/24)として運んでください。EVPN インスタンス
  **340**(VLAN ベース)を使います。
- プロバイダーのルート ターゲットの計画により、この EVPN インスタンスはルート ターゲット **65000:3400** だけをインポートおよび
  エクスポートします。
- プロバイダー エッジは、互いの顧客の MAC アドレスを BGP で学習し、EVPN の経路をルート リフレクタ RR1 を経由してだけ交換します。
  各プロバイダー エッジの BGP のルータ ID は、その Loopback0 のアドレスです。
- コアはマルチキャストを運びません。顧客からブロードキャストのフレームを受け取ったプロバイダー エッジは、ほかのプロバイダー
  エッジのそれぞれへ 1 つずつコピーを送ります。

### 課題 S-5

- 顧客 D のフレームを、サイト 1(VLAN 350)とサイト 2(VLAN 350)の間で 1 本のポイントツーポイントの回線
  (172.31.35.0/24)として運んでください。EVPN インスタンス **350** を使います。各端の識別子は、そのサイトの番号です。
- この回線のシグナリングに LDP を使いません。
