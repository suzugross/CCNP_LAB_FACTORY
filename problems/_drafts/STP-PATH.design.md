# STP 経路づくり(BL-270)— 要件どおりの経路になるよう木を組み替えるゲーム

2026-11-11 ユーザ構想:「ポートの状況を当てるのではなく、要件に沿った経路を通るように、各スイッチの役割・接続する
ケーブルの速さ・プライオリティを決めて、ポートの役割と状態を切り替え、要件どおりの経路を作り上げる。STP のルールは
完全に本物準拠。経路を作り上げるのがミソで、ネットワークっぽい」。テーマは**非エンジニアでもネットワークを体験できる**こと。

STP パズル(BL-268・[STP-PUZZLE.design.md](STP-PUZZLE.design.md))の逆向き。あちらは「設定を見て結果(役割と状態)を当てる」、
こちらは「結果(経路)が先にあり、設定を組み立てる」。

## 1. 決めたこと

| 論点 | 決定 |
|---|---|
| 制約 | **手数の上限**を設け、少ない手数ほど星が増える。速いケーブルなどは在庫(本数の上限)を持たせることがある(ユーザ了承・2026-11-11) |
| お題の数 | 序盤は 1 本、後半は 2 本(片方を直すともう片方が崩れる駆け引き)(ユーザ了承) |
| 用語と数値 | **本物を使う**(ユーザ決定)。Root Bridge・Bridge ID・Root Port・Designated・Alternate・FWD/BLK・Path Cost など、ネットワークの用語をそのまま「ゲーム内の専門用語」として使う。たとえ言葉に置き換えない |
| ブリッジ ID | 本物の形(priority + MAC)だが、**MAC は数字だけの簡単な値**(`0000.0000.0007` の類い。a〜f は使わない)(ユーザ決定) |
| パス コスト | **ショート法**(`spanning-tree pathcost method short`)(ユーザ決定) |
| 置き場 | STP パズルとは**別のゲーム**として、ポータルの同じ「Games」の区画に並べる(ユーザ了承) |
| ルール | STP の計算は本物どおり。計算は `stp_model.py`(実機と照合済み)だけで行う |
| 遊ぶ場所・保存・言語・ノルマ | STP パズルと同じ(ポータル・スマホは LAN 経由・進み具合はサーバ保存でリセット可・日英切替で既定は英語・ノルマに数えない) |

### 数値の決まり

- **Bridge Priority**: 0〜61440 を 4096 刻み(本物の範囲)。表示は本物どおり設定値 + VLAN ID(sys-id-ext)。1 VLAN のステージは
  VLAN 1(買ってきたままの状態)なので既定の表示は 32769。
- **MAC**: `0000.0000.00NN`(NN = 01〜99)。スイッチ名の番号とは一致させない(SW1 がいつも勝つ、を防ぐ)。数字だけで桁数が同じなので、
  16 進として比べても 10 進として読んでも大小は同じになり、`stp_model.mac_key` をそのまま使える。
- **リンク速度**: 100M / 1G / 10G(コスト 19 / 4 / 2)。ポートは Catalyst 9300 のマルチギガ ポート風の `Te1/0/n` に固定し、
  速度は `speed` で変える(実機でも 100M/1G/10G を選べる種類のポート)。速度はリンクの性質なので両端が同時に変わる。
  10M は使わない(マルチギガ ポートが対応しない)。
  ポート名の Te は「最大 10G で動けるポート」の名前で、1G で動いていても Te のまま(実機どおり)。CCNA に届かない人が
  「Te なのに 1G?」と迷わないよう、ルールの枠と速度の枠に 1 行ずつ説明を出す(2026-11-11 ユーザ指摘・案 1 を採用。
  速度に合わせて名前を変える案は、実機では別のポートへの差し替え= ポート番号とポート ID まで変わり、同点の決着が崩れるので不採用)。
- **Port Cost**(`spanning-tree vlan N cost`): 選べる値は「自動(速度から)」と 1・2・4・10・19・30・50・100 のプリセット(本物の範囲の一部)。
  効くのは**自分の受信ポート**(下流から見た自分のルート ポート選び)。
- **Port Priority**(`spanning-tree vlan N port-priority`): 0〜240 を 16 刻み(本物の範囲)。効くのは**上流(送信元)側**の値。
- **手数** = 答え合わせの時点で初期状態から変わっているつまみの数(タップの回数ではない)。元に戻せば減る。
  リンク速度は両端に設定が入るが 1 手と数える。

## 2. 遊び方

1. 盤面: スイッチ(名前・Bridge ID・計算後の Root Path Cost)、リンク(速度とコスト)、端末(PC・サーバ。エッジ ポートで接続)。
2. お題: 「PC1 → SRV1 の通信がこの経路を通ること」。目標の経路を図に点線で描き、文でも示す(`PC1 → SW3 → SW4 → SW1 → SRV1`)。
3. つまみ: スイッチを押すと Bridge Priority、リンクを押すと速度、ポートを押すと Port Cost / Port Priority。ステージごとに使えるつまみを開放する。
4. 変えるたびに STP を計算し直し、ポートの役割と状態(Root/Desg/Altn・FWD/BLK)、ルート ブリッジの印、実際の経路(流れる点)が切り替わる。
5. 実際の経路が目標と一致したら「開通」。手数で星を付ける。
6. 画面の隅に「変更した設定」を IOS のコマンドで並べる(ネットワークらしさ。用語の実物との結び付け):

```
spanning-tree pathcost method short          ← 固定(全台)
SW2: spanning-tree vlan 1 priority 4096
SW3: interface Te1/0/3 → speed 100           (相手 SW4 も同じ)
SW4: interface Te1/0/2 → spanning-tree vlan 1 cost 10
SW1: interface Te1/0/1 → spanning-tree vlan 1 port-priority 64
```

### お題の種類

| 種類 | 例 | 使うステージ |
|---|---|---|
| 経由 | PC1 → SRV1 は SW4 を通ること | 序盤(緩い) |
| 経路 | PC1 → SRV1 は SW3 → SW4 → SW1 を通ること(並行リンクなら線まで指定) | 主力 |
| ルート指定 | ルート ブリッジは SW1 であること | 後半の追加条件(設計のお作法) |

### 星

- ★3 = 最少手数で開通、★2 = 最少 + 1、★1 = 上限以内で開通。上限 = 最少 + 2(level 1〜2 は + 3)。上限を超える変更は画面が受け付けない。
- 「答えを見る」は 2 回目の失敗から出し、最少手数の解の一例を示す(開通扱い・星 0)。
- 開通後の解説は STP パズルの `explain()` と同じ順(ルート ブリッジ → 各スイッチのルート ポート → 各リンクの指定ポート → 残りが代替)に、
  「どのつまみがどの判定を変えたか」を足す。最少より多い手数だったら最少の解の一例も示す。

## 4. 生成と最少手数

- 盤面の形は STP パズルの `SHAPES`・`_wire`・キャンパスの配線を使い回す。
- 生成: 初期状態(既定寄りの設定)を作る → 目標状態を作る → 目標の木での端末間の経路をお題にする(初期と同じ経路の流れは、
  他の流れが変わる時だけ残す)→ 最少手数を探索で求める → 初期状態がお題を満たさず、最少手数が level の範囲に入る盤面だけを採る。
- 目標の作り方は 2 通りを半々(実装で決めた): ①1 手ずつ積み、どの手もその時点の経路を実際に変える(空振りの手が無い)/
  ②開放されたつまみを k 個でたらめに変える(途中の手が経路を変えない形= ルートを替えてから同点の決着を変える、などは ② でしか出ない)。
  ステージ 2 の level 1〜3 は、ルート以外のスイッチのプライオリティをルートより大きい値で変える(変わるのは同点の決着だけ)。
  ステージ 1 は、目標の経路が同点の決着に頼らない盤面だけを採る(経路の上のスイッチのルート ポートに同点が無い= ルートを選ぶだけで解ける)。
  ステージ 7 は VLAN ごとに別のスイッチをルートに(24576)＋level 4〜5 は経路を実際に変える追加の 1 手。ステージ 8 は上の層の 1 台を
  24576(root primary 相当)、ときどきもう 1 台を 28672(secondary 相当)＋残りは他のつまみ。
- 最少手数の探索: 手数 1, 2, … の順に全組み合わせを試す。値の候補は意味のある分類に縮める
  (Bridge Priority は他のスイッチとの大小関係・Port Priority は隣の並行リンクとの大小・速度は 3 値・Cost はプリセット 8 値)。
  Port Priority は並行リンクのポートだけ探す(ポート ID の比較は送信元 BID が同じ= 同じスイッチからの BPDU どうしでしか起きない)。
  2 手までを総当たりし、生成で k 手(k ≤ 3)使った盤面に k−1 手以下の解が無ければ最少は k。ステージ 7 は VLAN ごとに独立なので VLAN ごとの和。
  selftest で、小さい盤面は全域の値(priority 16 値・port-priority 16 値・並行リンク以外の port-priority も)の総当たりと突き合わせる。
- 受け入れる最少手数(実装): ステージ 1 は全部 1。ほかの多くの level は 1・1・2・2・2〜3。ステージ 6 の level 5 は 2〜3(お題 2 本で
  最少 3 手ちょうどの盤面はまれ)。ステージ 7 は 1・2・2・2〜3・3〜4。生成の時間は 1 盤面あたり平均 0.3 秒以下(ステージ 8 の level 5 だけ約 1.2 秒)。
  作った盤面はサーバが覚える(lru_cache)。
- 端末の置き場所はサーバが選ぶ(箱・線・他の端末・ポートの印から離れた所。画面の geom() の印の位置と同じ計算で近さを見る)。
- 同じ seed なら同じ盤面(ランダム モードを後で足せる作りは STP パズルと同じ)。

## 6. 裏どり

- 計算: `stp_model.py`。Bridge Priority・Port Cost(受信側)・Port Priority(上流側)・sys-id-ext・VLAN ごとの木は実機と照合済み
  (poc/stp/README.md 第2回・stp_model の selftest)。
- 速度からのコスト(ショート法の表): Cisco 公式の既定表(stp_model の docstring)。IOL・IOSvL2 は速度を変えられないため、
  `speed` で変えたときのコストの変化は実機では測っていない(公式の表に拠る)。
- 「コストは実際の速度から決まる」(ルールの枠・速度の枠の文): Catalyst 9300 Layer 2 Configuration Guide(IOS XE 16.11/17.6 ほか)の
  STP の章「the default value is derived from the media speed of the interface」(2026-11-11 確認)。
- 「Te ポートが 100M/1G/10G で動く」: Catalyst 9300 Interface and Hardware Components Configuration Guide(IOS XE 17.13)の
  `speed {10 | 100 | 1000 | 2500 | 5000 | 10000 | auto …}`・マルチギガ ポートは全速度に対応(2026-11-11 確認)。
- 版による食い違い(記録のみ・出題に使わない): 9300 の L2 ガイドは版で既定のパス コスト方式の記述が違う(16.x は short が既定、
  17.6 は long が既定と書く)。このゲームは `spanning-tree pathcost method short` を前提として明示しているので影響しない
  (U-A3 の出典照合表 D2 と同じ論点)。
- チュートリアルと解説の事実は U-A3 の出典照合表(`curriculum/U-A3-stp.sources.md`)で「確定」の項目だけを使う。

## 8. 試験のしかた

- `python3 topologies/stp_path.py selftest [N]` … 8 ステージ × 5 level × N seed: 初期は未達・解の手数 = 最少・在庫と開放つまみ・
  まだ見せていない値で答えが決まらないこと(§10)・ステージ 1 の答えが同点に頼らないこと・ステージ 2 の 1〜3 でルートが動かないこと・
  最少手数の範囲・JSON の往復・端末が図の中・小さい盤面の全域総当たり・決定性・下流の port-priority が効かないこと・不正な設定を断る・
  上限超えは ok にしない・進み具合の保存とリセット(N=16 で NG 0)。
- 画面(ポータルを起動して): `/_stp_path/?autotest=20` … 各 level を 20 通り(800 盤面): 初期は未達・答えで ok かつ星 3・画面の手数の
  数え方がサーバと同じ・答えの設定を送り直しても ok・印/ラベル/端末/箱/速度の表示(押す場所)の重なりとはみ出し(NG 0)。
  `/_stp_path/?uitest=1` … チュートリアル → ステージ 1 の盤面が最小限 → 答えの priority を枠から入れて開通・星 3・解説(① だけ)→
  ルールの枠(出ているものだけ)→ 次のレベル → ステージ 2(ポートの印と RPC・NEW・ルートを動かさないお題・ポートの足し算)→
  上限(ステージ 6)→ やり直し・元に戻す → 答えを見る → 速度(ステージ 3)→ ポート名(ステージ 5)・port-priority → VLAN のタブ(ステージ 7)→ 言語(NG 0)。
  見た目は `?demo=1|solved|sw|link|port#p<s>-<l>`・`&card=N` とヘッドレス Chrome のスクリーンショット(幅 390)。
- 共通部品に切り出したあとの STP パズル: `/_stp/?autotest=20` NG 0。`?uitest=1` の「次のレベルへ進む」1 件は、切り出し前の版でも
  同じく NG(この試験の待ち時間が足りないだけ・画面の不具合ではない)。

## 9. 情報量を詰めた(2026-11-11 ユーザ指摘)

指摘:「イメージ通り。ただ小難しい解説は、読みたい人がクリックで開けばよい。お題の出し方が簡素すぎて、慣れていないと一瞬『ん?』と
なる。ルート パス コストやプライオリティなどの最低限のルールはいつでも参照できるように。正確さは保ったまま情報量をコンパクトに。
対象は CCNA にちょっと興味があるくらいの人(本当の素人を基準にしなくてよい)」。

| 箇所 | 変えたこと |
|---|---|
| お題 | 文の形(「PC1 → SRV1 の通信を SW3 → SW4 → SW1 の順に通す」「SW4 を通るようにする」「SW01 をルート ブリッジにする」)。並行リンクは「◯◯ の線を使う」。満たしていない間は**今の経路**(「今: SW3 → SW2 → SW1」・ルート指定なら今のルート)を添える。先頭に 1 行「色の帯どおりに通信(流れる点)が通れば開通」。手数は「手数 n / 上限 m ・ ★★★ a 手以内 ・ ★★ b 手以内」 |
| ルール | 右上の「?」を「ルール」に。枠に決まり(ルート ブリッジ・R・RPC・D・A・ショート法のコスト表)と、変えられる設定 4 つ(このステージで使えるものに印)・前提・星の決まり。チュートリアルの読み直しもここから |
| 開通後 | 星と手数だけ。設定・最少の答え・4 段の解説は「解説を読む」(details)の中 |
| 盤面の下 | 凡例は 1 行(R・D・A・塗り/白抜き・★・破線)。前提の説明はルールの枠へ。下の枠は「変更した設定」だけ |
| チュートリアル | 決まりの一覧はルールの枠に任せ、カードは「何をするか」と例に絞った(ステージ 2・5・6・7 はカードを減らした) |

## 10. 盤面に出すものを順に増やす(2026-11-11 ユーザ指示)

指摘:「一番最初に全部の STP の要素を見せられるときつい。最初は最小限のパラメータしか見せず、順次新しいパラメータが出現するイメージ。
見せないだけで裏では動いている。そうすると問題数を増やしてグラデーションを付けるべきか」→ 案(下の表・ステージ 2 を挟んで 40 問)を
示し、「最初はシンプルにゲームに入り込めるように」で了承。

| ステージ | 盤面に新しく出るもの(`stp_path.SHOW_FROM`) | 押して開く枠・ルールの枠 |
|---|---|---|
| 1 | スイッチの箱(名前・priority・MAC)・★・止まったリンク(破線)・通信 | ルールは「ルート ブリッジ」と「ルートへの道(通るリンクが最も少ない道・同じ本数なら隣のブリッジ ID)」だけ |
| 2 | ポートの印(R/D/A・FWD/BLK)・RPC | R/RPC/D/A・「このステージのコストはすべて 4」・ポートの枠に足し算 |
| 3 | リンクの速度とコスト | Te の 1 行・ショート法の表・凡例に「1G · 4 = 速度 · コスト」 |
| 4 | 手で決めたポート コスト(印の横に `cost 10`) | 変えられる設定にポート コスト |
| 5 | ポート名(Te1/0/3)・ポート ID | R の同点に「→ 送信元のポート ID」・変えられる設定にポート プライオリティ |

- **隠すのは表示だけ**。計算(stp_model)はいつも STP の決まりをすべて回す。
- **まだ見せていない値で答えが決まる盤面は出さない**(selftest で検査): ポート ID を見せる前は並行リンクを出さない・速度を見せる前は
  全リンク 1G・ポート コストを見せる前は手で決めたコストなし・ステージ 1 の答えの経路は同点の決着に頼らない。
- 初めて出たものには NEW の札(凡例・ルールの枠)。チュートリアルの最初のカードで「このステージから … が出ます」と知らせる。
- 見え方はステージで決まる(進み具合では変えない)。先へ進んだ後でステージ 1 を遊び直しても、1 の見え方のまま。
- ルールの枠の末尾に「ここに無い決まりは、このステージの盤面では結果を左右しない(先のステージで増えていく)」(ステージ 1〜4)。
  これは上の「出さない」検査が保証している。
- 解説(押すと開く)は、ポートの印を見せる前(ステージ 1)は ① ルート ブリッジの節だけ。
- 問題数: ステージを 1 つ挟んで 8 ステージ 40 問(MST を入れて 9)。各ステージ 5 問は据え置き(盤面は乱数で作るので、一律に増やしても
  同じ型が増えるだけ)。旧ステージ 1 の level 4〜5(2 手・同点の決着を使う形)はステージ 2 の level 4〜5 へ移した。
- 旧ステージ 4 は同点の話がステージ 2 に移ったので「並行リンク」に改名(中の 2 枚目のカードは「送る側で効く」)。
- 進み具合: 保存の版を 2 にし、版 1 の記録はステージ 2 以降の番号を 1 つずつ後ろへずらして読む(`stp_path.load_state`)。
  ブラウザに残る下書きの鍵も `stpp2.draft.*` に変えた(古い番号の下書きを読まない)。

## 11. チュートリアルを丁寧に・図に番号の札(2026-11-11 ユーザ指示)

指摘:「ポートの役割のチュートリアルで、図に直接『この R はこういう理由で R』のような解説を入れられるか」→ 番号の札の案を示したところ、
「さらにいうと、もっとチュートリアルは丁寧にしてほしい。ポートの役割は役割ごとに 1 つずつ解説するところが欲しい」。

- **§9 との関係**: §9 で詰めたのは**遊ぶ画面**(お題・凡例・開通後)。チュートリアルは逆に、1 枚 1 つの話で丁寧に書く。
- **図の札**(stages.yml のカードの `notes`): 図の指す物(ポート・スイッチ・端末・リンク)のそばに番号の札を置き、図の下にその番号の理由を
  1 行ずつ並べる。番号か行にカーソルを置く(スマホは押す)と、図のその物と行が光る(教材の流れの図 `:::walk` と同じ触り方)。
  札の置き場所は画面が自動で選ぶ(指す物のまわりの候補から、ほかの印・箱・★・端末・線・表示中の文字・先の札から離れた所。ほかの印とは
  余分に 8 離して取り違えを防ぐ。印のすぐ脇に空きが無ければ少し離して細い線でつなぐ)。
- **同じ理由が複数に当てはまるときは全部を指す**(同日ユーザ指摘「ルート ブリッジのポートはすべて D なのに札が片側にしか付いていない」):
  `at` をリストにすると、同じ番号の札がそれぞれに付き、まとめて光る。D の ①(SW2 の D 2 つ)・D の ③(PC 側とサーバ側)・
  ステージ 1 の「ルート ブリッジ」の ②(SW1 と SW3)・「道が同点のとき」の ③(SW4 と SW2)を直した。札の文が「すべて」「どちらも」
  「〜と〜を比べる」と言うときは、指す先も全部にする。
- **注目**(`focus`): その役割のポートだけを濃く出し、ほかを薄くする(R・D・A の各カード)。`flow: false` でお題の帯と点を消す。
- **検算**: 札に `role`(R/D/A)・`root`・`rpc`・`blocked` を書くと、selftest が例の盤面の計算と照らし合わせる(理由の文と計算が食い違わない)。
  札がまだ見せていないもの(ステージ 1 のポートなど)を指していないことも検査。画面の autotest は札の重なりを見る(実際のすき間 < 0 で NG)。
- 例の盤面を 3 つ足した: `ex_tree_low`(SW1 を 24576 に下げた三角)・`ex_cost10`(SW3–SW4 を 10G)・`ex_pcost`(SW3 の SW4 側に cost 10)。
- 枚数: ステージ 1= 6 枚(経路をつくる・ブリッジ ID・ルート ブリッジ・ルートへの道・プライオリティを下げると・遊び方)/
  ステージ 2= 7 枚(NEW: 印と RPC・RPC・**R**・**D**・**A**・道が同点のとき・遊び方)/ 3= 4 枚 / 4= 3 枚 / 5= 4 枚 / 6〜8= 各 3 枚。
- 事実は U-A3 の出典照合で「確定」の項目だけ(#7 A は BPDU を受信・#12 AP は RP のバックアップ・#17 自側のリンク障害で A が R を即時に引き継ぐ・
  #47 RPC= 受信ポートのコスト＋上流の RPC を足した)。「R の向かいの端は必ず D」は p2p リンク(このゲームの全リンク)での話。
