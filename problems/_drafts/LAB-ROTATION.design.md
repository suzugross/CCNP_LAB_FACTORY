# ラボ単元ローテーション(デフォルト問題パック)— BL-223

2026-09-27 ユーザ指示。ENARSI 合格後、デフォルトの問題パックのラボ配分を「試験範囲からランダム 2 本」から
「単元の曜日表＋遅れ補正」に切り替える。将来 ENARSI モード・ENCOR モード・1 単元モードを足す前提で、
**設定ファイル(`topologies/lab_modes.yml`)の差し替えでモードが増える**形にする。

## 1. 要件(ユーザ発言の要約)

- 「この曜日はこの単元かこの単元か」という規則性がほしい。
- 1 単元が 1 曜日に固定されるのではなく、最低 2 曜日に出る。
- サボる日・飛び飛びの日があっても、ある程度満遍なく回る。
- これは**デフォルト**パックの扱い。範囲で絞るモード(ENARSI/ENCOR/1 単元)は将来別に作る。

## 2. 決定事項(2026-09-27・推奨値で確定)

> ★2026-10-06 改定(BL-233): 1 日 3 本のうち 1 本を**発掘枠**に充て、単元は 2 本・補正は最大 1 枠にした。経緯と現行値は §8。

| 論点 | 決定 |
|---|---|
| 1 日の本数 | 曜日表の 3 単元を**すべて出す**(ノルマ= ラボ 3 問・3 ジャンル と一致・40 ノードで同時起動可)。追加枠は使わない |
| 補正の強さ | 遅れ度 ≥ 2.0 の単元を最大 **2 枠**まで差し込む。曜日表から最低 1 枠は必ず出す |
| 「出た」の基準 | **採点記録**(`records/attempts.jsonl`・private 側も)の日。採点記録が 1 件も無い単元だけ出題履歴(`_history.md`)の日で代用 |
| モード間の履歴 | 共有する(どのモードで解いても「その単元をやった」に数える) |
| 単元内の TS/構築 | 従来の `--build-rate`(既定 0.4・1 パック最大 1 本)を単元の中で適用。単元内のジャンルは前回出したものを避ける |

## 4. 選び方(`topologies/lab_rotation.py`)

1. 日付は**ノルマ日**(JST 04:00 境界・`quota.quota_day`)。曜日もノルマ日で決める。
2. 単元ごとに `最後にやった日` を出す(§2 の基準)。今日すでに出題した単元(同日の再実行)も「やった」に数える。
3. 遅れ度 = 経過日数 ÷ (7 / 週回数)。一度もやっていない単元は遅れ度 99。
4. 枠の埋め方:
   1. 遅れ度 ≥ `catchup_ratio`(2.0)で**今日の曜日表に無い**単元を、遅れ度の大きい順に最大 `max_catchup`(2)枠。
   2. 残りを今日の曜日表から。遅れ度の大きい順。今日すでに出した単元は飛ばす。
   3. まだ空きがあれば(曜日表の単元が今日すでに出ている等)、遅れ度の大きい順に残りの単元から。
5. 単元 → ジャンル: 単元の `genres`(`gen_pack.LAB_GENRES` のキー)から、構築は `--build-rate` の当たり時だけ候補に入れ、
   前回出した日(パックの manifest に記録した `genre`)が古い順に試す。解決できない(台数予算・カタログ欠落)なら次のジャンル、
   単元ごと解決できなければ 4.3 の順で**代わりの単元**を試す。
6. ローテーションモードでは `gap_days`(MPLS の再出題間隔 6 日)は**掛けない**。頻度は曜日表が決めるため
   (MPLS は週 2 回= 水・日で間隔 3〜4 日。gap_days を残すと日曜の MPLS が毎回見送られる)。
7. 「やった」の判定は単元の `genres` の接頭辞・静的 ID(`prefixes`/`ids`/`gap_families`/`gap_ids`)＋単元の `also`(正規表現)。
   `also` は既定プール外の旧問題(`ENARSI-BGP-*`・`GEN-EIGRPCX` 等)も単元に数えるための補助。

## 5. `gen_pack.py` への接続

- `--lab-genres` を**明示したときだけ**従来の固定ジャンル抽選(select_genre_labs)。無指定かつ `--profile` 無しなら
  `--lab-mode`(既定 `default`)のローテーション。`--profile` 指定時は従来どおり(範囲で絞るモードは将来ここを置き換える)。
- ローテーション時の本数は mode の `slots`(3)。`--lab N` で上書き可。追加枠(`--lab-extra`)は既定 0。
- manifest のラボ行に `genre`・`unit` を書く(単元内ローテーションの履歴)。
- dry-run・`--assume-used` はそのまま使える。`--lab-date YYYY-MM-DD` でノルマ日を仮定して曜日/遅れ度を確認できる。

## 6. 将来のモード

`lab_modes.yml` の `modes:` に足す。例:
- `enarsi`: units= ENARSI 範囲の単元、`per_week` をブループリント配点比で、`week` 無し(遅れ度だけで選ぶ)。
- `single`: units= 1 単元、slots= 3(単元内のジャンルを回す)。
`week` が無いモードは 4.4.2 を飛ばして遅れ度順だけで埋める。`--profile`(CURRICULUM 単元の範囲指定)との統合は
その時に行う(二系統を並存させない)。

## 8. 発掘枠(BL-233・2026-10-06)

### 8.1 なぜ要るか

ユーザ相談「ラボがマンネリ」の調査で、単元ローテーションが引ける資産が `LAB_GENRES` に登録した
生成器 16 接頭辞＋静的 12 本に限られ、それ以外(119 資産)は手動の差し替えでしか出ないと分かった。
ローテーション導入前はカタログ全体から 1 本引く追加枠(`--lab-extra`)がこの役を担っていたが、
導入時に既定 0 にしたため経路が無くなっていた。ユーザ指示= 「眠っている資産や、現状選ばれないものも
抽選で必ず入るように」。承認された前提= 3 本のうち 1 本を充てる／非 Cisco・自動化の除外は維持／難 1〜2 は除外。

### 8.2 規則

1. 対象= mode の `units` → `LAB_GENRES` が**引けない**生成器と静的問題(`gen_pack.discovery_pool`)。
   外すもの= `discovery.hold`(保留)・後継がある旧生成器・非 Cisco・自動化・専用 CLI 運用の特殊ラボ・難易度 `min_diff` 未満。
2. 順序= **最後に出した日が古い順**(記録なしが最優先)。乱数は同じ日のもの同士の並びにしか使わない。
   候補が N 件なら N 回以内に全件が一巡する(抽選だけでは偏って出ないものが残る)。
3. 種別(生成器/静的)は `discovery.kinds` の順に**日替わりで交互**。生成器は新 seed で何度でも出せるが、
   静的問題は 1 問 1 回なので、混ぜて古い順にすると未出題の静的問題が先に並び切ってしまうため。
   その種別に台数予算へ入るものが無い日は、もう一方から選ぶ。
4. 「最後に出した日」= 出題履歴(`_history.md`)の ID を接頭辞の前方一致で引いた日と、パック manifest のラボ行
   `pool`(発掘枠が選んだ候補キー)の日の、新しいほう。`pool` を控える理由= 生成器が書く ID がカタログの接頭辞と
   食い違うと(BL-175 の型)その候補が永久に「記録なし」= 毎回先頭に来て他が回らなくなるため。
5. **発掘枠を先に取り**、残りの台数予算で単元を埋める(後回しにすると大型の候補が予算に入らず永久に出ない)。
   予算に入らない候補は飛ばすが待ち行列の先頭に残る。
6. 発掘枠の問題がどれかの単元に当たる(単元の `prefixes`/`ids`/`also` に一致する)日は、その単元を今日の
   ローテーションから外す(同じ単元を 1 日に 2 本出さない)。空いた枠は遅れ度順で埋めるが、**翌日の曜日表にある
   単元は後回し**にする(遅れ度が最大なのはたいてい「明日が出番の単元」で、そのまま埋めると連日になる)。
7. 構築は 1 日最大 1 本を保つ: 発掘枠が構築問(TS 判定でないもの)を出した日は、単元側の構築スロットを使わない。
8. `--lab N` で本数を絞り N ≤ 発掘枠の本数になった回は、発掘枠を使わず単元を優先する。`--discovery 0` で無効。
