# OSPFv3 マルチエリア prefix-list 紙面ファミリ — 設計メモ (BL-097)

作成: 2026-08-07 / 発端: ユーザ手組みラボ「OSPFv3 Prefix-List exam」(CML, 5×IOL, wr mem済stop保管)
実測土台: poc/ospfv3-pl/ (POC-OSPFV3PL・挙動軸6件全実測・results-raw.md)

## 出題意図(ユーザ要望の整理)

マルチエリアOSPFv3のエリア間経路フィルタを題材に、**prefix-list の包含判定を
「手を動かさないと解けない」レベルで問う**紙面ファミリ。選択肢はコマンド(群)。

- **16進の繰り上がり読み**: 第3ヘクステット 9→A→B→C(さらに F→10 跨ぎ)。
- **ヘクステット中間マスク**: /44〜/47 は2進展開しないと包含判定不可。1bit刻みで被覆が
  16/8/4/2本と反転(実測済: /45=9ABC全部 → /46=C:Cだけ外れる → A::/47=A,Bのみ)。
- **第3=第4同値(C:C)の視覚ノイズ**: 包含に効くのは第3のみ(/48以下)、と切り分けさせる。
- 適用場所・フィルタ種別・ge/le・seq のレパートリーを可能な限り充実させる。

## 盤面(紙面トポロジ)

PoC と同型の3エリア・スター(全て図+設定エキシビットで提示):

```
R1(Area10) --e0/0---e0/0-- R2(ABR) --e0/1---e0/0-- Ra(Area0)  Lo×4: 2001:DB8:h:h::/64
                            +--e0/2---e0/0-- R3(Area20)       (h=seed抽選・第3=第4同値)
```

- Ra の Lo 4本が主役プレフィックス群。**第3ヘクステット h は seed で抽選**:
  - 基本族: /44ブロック内の連続4値(例 9,A,B,C / 8,9,A,B / A,B,C,D)
  - 上級族(hard): **F→10 跨ぎ**(例 E,F,10,11。/45〜/47 では両側を1本で括れない)
- R1 e0/0 セカンダリ 2:2::/64 = intra-area 免疫・「1IF設定で複数プレフィックス広告」素材。
- リンク網(1:1 / 0:A / 3:3)は主役 /45 の外に置き、permit単独リストの暗黙deny巻き添え素材。
- 経路表の書式・メトリックは実測に忠実: Lo=OI [110/21] / リンク網=OI [110/20] /
  range集約=OI [110/21]・ABR自身に O .../45 via Null0。

## 反転軸(要件世界) — 制約が正解を反転させる

被覆エンジンは BL-081/BL-095 方式(works/complies プロファイルで一意性を機械検証)。

| 世界 | 要件+制約 | 正解の手段(他候補が死ぬ理由) |
|---|---|---|
| W1 | Area10 には指定2本だけ届ける・**Area20 への影響不可** | `area 10 filter-list in`(area 0 out 案は P1 で Area20 を巻き込み死) |
| W2 | 指定1本を**全非バックボーンエリア**から隠す・1行で | `area 0 filter-list out`(area N in 案はエリア毎に必要で制約違反) |
| W3 | R1 の**RIBからのみ**除外・LSDB/他ルータ影響不可 | R1 で distribute-list in(filter-list 案は他ルータへ波及・ABR適用案は P4 で波及死) |
| W4 | Area10 へは**集約1本**で届ける(明細抑止) | `area 0 range .../45`(filter-list 案は集約を作れない) |
| W5 | 4本とも**どこにも広告しない**(RIBでなくLSA層で) | `area 0 range not-advertise`(distribute-list 案は内部ルータでは LSDB 残で違反) |

各世界の中でさらに prefix-list 本体の正解が動く: マスク長(/44〜/47)・ge/le の要否・
permit/deny 構成・seq 順序。「適用コマンドは合っているがリストの被覆が1bit違い」を
標準の誤答面として常備する。

## 選択肢(錯乱肢)設計 — コマンド選択式

恒久規約踏襲: Cisco語文体 / 選択肢に因果・解説を書かない(コマンド列のみ) / --exam 対応。
1択の正解 + 3錯乱肢を以下の分類から seed 抽選(各問で系統の異なる3種を混ぜる):

| 系統 | 例 |
|---|---|
| D1 マスク1bit違い | /45↔/46(C:C が入る/外れる)・/47 で2本欠け |
| D2 ge/le 誤用 | `le 64` 欠落(=/45ちょうどのみマッチ→空振り全滅)・**`le 63` vs `le 64`(1-off・/64を拾えず空振り)**・**`ge 64 le 64`(ちょうど/64のみ=リンク網/集約の巻き添え有無が変わる)**・`::/0`↔`::/0 le 128`↔`::/0 ge 1`(↔`::/0 le 0`=正規化で::/0と同値) |
| D3 方向・場所違い | in↔out 入れ替え(W1で Area20 巻き添え)・適用エリア番号違い |
| D4 手段違い | filter-list↔distribute-list↔area range(世界の制約で死ぬ側を配置) |
| D5 構文不正 | `ge 45` / `le 45`(=len同値・**そもそも受理されない**。P8 のエラー文言は解説にのみ使用) |
| D6 seq 影 | 広い permit が先で狭い deny が死に文(見た目は「遮断してそう」) |

- deny+permit-all 形(手組ラボ PL01 型)と permit-only+暗黙deny 形(PL02 型)を seed で出し分け。
- デコイ(リスト乱立)は leakmap 仕様踏襲: 未参照リスト・typo参照(PL01/PLO1)・
  類似名 2〜4本。生きている参照は1本だけ。hard で増量+seq影追加。

## 両掛け(dual_select)世界 — 2026-08-08 追補(★ユーザ指摘: これが本来の主題)

手組ラボの本題は「in/out の**二重掛け**で必要経路を選別する」だった(PL01 out+PL02 in)。
P1 の単発分解は主題外しだったため、当日中に world=dual_select として追実装:

- 構図: **in=配布の限定**(permit形: pair/47+リンク網を area a1 in) ×
  **out=特定ルートの全域停止**(deny形: pair内の1本を area 0 out)。停止対象は
  pair の内側に取る(=R1 の表に両フィルタの効果が同時に現れ、read 形が成立する)。
- 要件: ①a1 へは pair のみ配布 ②対象1本は全エリア停止 ③a2 は対象以外無影響
  ④エリア単位の等適用 → in_only は②違反 / out_only は①違反 / 役割逆転は③違反
  (out の permit 形が a2 を巻き込む) / in マスク広げは①違反。works だけで一意。
- kind: none(構築) / mask_off・le_missing・le_off(in 側の欠陥) / seq_shadow(out 側死に文)。
- モデル: st["fl"] を単発→リストへ拡張(直列合成)。実機2ケース突き合わせ済
  (mask_off/dual・seq_shadow/dual)。
- 同日追加: **リンク網プレフィックスの毎回抽選**(第3ヘクステット 0..7 帯・4本相互重複なし・
  ユーザ要望)と **range 被覆の実機忠実化**(Area 0 のリンク網も範囲に畳まれる)。

## patch 形(両掛けTS) — 2026-08-08 第2追補(★ユーザ要望の最終形)

「同じエリアへのフィルタを in/out 両方使って構成済み・現在は理想でない → **直すとしたら
どのコマンド?**」の最小修正選択形。解答者の作業= ①要件から理想の表を導く ②2枚のリストを
直列に読んで現状を再現 ③**どちらの層のどのエントリが原因かを切り分け** ④それだけを直す。

- 対象盤面: dual_select × kind∈{mask_off, le_missing, le_off, block_off, mask_narrow,
  seq_shadow, dual_swap}(kind=none は構築問なので除外)。
- 選択肢=最小差分のコマンドブロック4択: 正解(壊れたエントリの書き換え/再シーケンス/
  方向の掛け直し) + **健全な側を触る**(切り分けミス) + 惜しい誤値(le 63 等) +
  適用ごと削除(症状は変わるが要件違反)。一意性は delta 適用→モデル評価で機械検証。
- 新kind(誤設定バリエーション・ユーザ指定): block_off=範囲ずれ(隣の /47 ブロック・
  16進読み違い) / mask_narrow=狭すぎ(/48 で片割れ欠け) / dual_swap=方向逆
  (2枚の適用先取り違え)。fix/read 形にも合流(area10_only にも block_off/mask_narrow)。
- P2 残: 単発盤面(hide_all 等)への patch 拡張(世界制約と最小修正の整合を要設計)。

## 出題形状

- S1 **fix(構築選択)**: 要件世界+制約 → 4つのコマンド群からどれで満たすか。
  複数行選択肢(prefix-list 定義+AF配下適用のブロック)。状態収束形(既存設定の削除込み)。
- S2 **read(逆引き読解)**: R2 設定エキシビット(デコイ込み) → 「R1 の show ipv6 route ospf
  はどれか」経路表4択(書式・メトリック実測忠実)。中間マスクの包含判定が主戦場。
- S3 **cause(紙面TS)**: 症状(C:C だけ無い/全部無い/R3 にも消えた) → 原因の設定行 or
  「どの1修正で要件回復か」。P4(ABR distribute-list の波及)・P9(::/0 全滅)が目玉症状。
