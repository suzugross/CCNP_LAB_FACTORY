# PAPER-PBR-WILDCARD — PBR×ワイルドカードACL 机上4択ファミリ (BL-081)

2026-08-02 ユーザ発案。手組みラボ「CCNPラボPBR」(CML稼働中・**温存**・4 IOL)を雛型に、
BL-080 の紙面化枠(gen_paper_mcq.py)へ **shape=pbr** として追加する分野拡張第1弾。
ユーザ要望=「いやらしい範囲指定」のワイルドカード計算＋「しょうもないTS」
(prefix-list を指定して効かない等)を、もっと難しく・煩雑に。

## 雛型ラボの読解(2026-08-02 ダンプ・scratchpad/pbr_dump.md)

- iol-1=ハブ: E0/0→iol-0(192.168.0.0/30)・E0/1→192.168.10.0/24(iol-2)・
  E0/2→192.168.11.0/24(iol-3)。E0/1 に MAP01/PBR01=`172.16.0.0 0.0.3.255`
  (**{0..3}のみ=.7 取りこぼしの故障版**)、E0/2 に MAP02/PBR02=`0.0.7.255`({0..7}=正)。
- iol-0: Lo0〜3 = 172.16.{0,7,8,16}.1/24(該当させたい {0,7} / させない {8,16})。
- ★IGP なし・ハブは 172.16.x への経路を持たない → **PBR が当たらなければ到達不能**
  = ACL の当たり外れが到達性に直結する判定装置。正解/故障ペアが1台に同居する良い雛型。

## ワイルドカード素材(ビット計算の核)

- 0.0.3.255={0..3} / 0.0.7.255={0..7} / 0.0.15.255={0..15・.8巻き込み} /
  **0.0.16.255={0,16}のみ(非連続)** / 0.0.8.255={0,8} / ベースずらし(172.16.8.0
  0.0.7.255={8..15}) 等。選択肢を全部この兄弟にすれば毎回ビット展開の計算になる。
- 宛先 Lo の第3オクテット集合を seed 抽選: {0,7,8,16}型・{32,40,48,63}型・
  {64,68,72,96}型など「単発ワイルドカードで書ける/書けない」境界を系統生成。

## 設計

- トポロジ: ハブ(PBR)+出口2系統(正/迂回)+クライアントLAN2〜3+多Lo宛先。IOL 5〜6台。
- 故障タクソノミ(初期8種・各1周実機検証):
  wc_narrow(狭すぎ=雛型の0.0.3.255) / wc_wide(除外対象を巻き込み) /
  wc_bits(非連続{0,16}の怪) / acl_dir(extended の src/dst 逆) /
  rm_no_match(match無しseq=全吸引) / policy_wrong_if(適用IF違い) /
  match_prefix_list(PBRでは不一致=「しょうもないTS」) / next_hop誤り。
- 証拠セット: クライアント発 ping 成否表(!!!!! / .....)・traceroute(出口識別)・
  **show access-lists / show route-map のマッチカウンタ(収集前に ping で温める)**・
  ハブ+周辺 config。赤ニシン(未適用ACL/RM)・拠点語彙・要件ランダム化は既存枠を継承。
- ★選択肢設計(2026-08-02 ユーザ発案で確定): **6〜8択。うち2〜3個は「到達性だけなら直る」
  候補**(1行ワイルドカード解 / 厳密2行解 / deny先行3行解)を意図的に併置し、
  **抽選された要件軸だけが正解を一意化する**:
  「1エントリで全対象をまかなう」→1行解が正 / 「対象外を1つも含めない(厳密一致)」→
  複数行解が正 / 「既存エントリ編集禁止・追記のみ」→シーケンス挿入解が正。
  残りは常設ハズレ(狭すぎ・巻き込み・非連続 0.0.16.255・prefix-list 案)。
  ★各候補の被覆(第3オクテット集合)は生成器が厳密計算できるため、
  「症状を直す候補≥2・要件適合はちょうど1」を **seed ごとに機械検証してから出題**する
  (複数正解の事故を構造的に排除)。正解位置ガードの regex は択数拡張([A-H])に合わせる。
- 選択肢: 恒久規約(事実・操作のみ・因果説明なし)。cause形=同ジャンル偽原因
  (逆向き/未適用/IF違い/prefix-list)混在。
- **要PoC(実装前に IOL 17.15 で1周)**: ①PBR の `match ip address prefix-list` の実挙動
  (受理されるが policy 不一致のはず) ②ACL/route-map カウンタの温め方(ping 回数と反映) ③
  ping 不達時の応答(経路なし=U/タイムアウトの見え方)。
- 運用: BL-080 と同じ(PAPER-RD- パック使い捨て・questions/answers・冪等・雛型ラボは触らない)。
