# PAPER-TIMELIMIT — 紙面の動的制限時間モード(BL-149)

2026-08-27 設計確定(ユーザ発案・同日パラメータ決定)。実装は未着手。
関連: BL-145(速筋スプリント・時間圧訓練)・BL-114(ノルマ)。

## 目的

時間圧を「目安」でなく**本当の制約**として扱う。本試験(2026-08-01 不合格)の
自己分析「時間圧で真っ白・モデル完成/自動化未訓練」への直接対策。

## 決定事項(2026-08-27 ユーザ決定)

| 項目 | 決定 |
|------|------|
| 目安時間 | **shape 別の所要時間の中央値**(過去パック `packs/*/解答.md` の自動計測「所要」) |
| 統計窓 | **直近 10 サンプル**(実力向上に追随。全期間平均は使わない) |
| 制限時間 | **`max(中央値×1.25, 中央値+30秒)`** |
| 単位 | **問題単位ロック**(モード(a))を先行実装。パック総持ち時間制(モード(b)=本番シミュレーション)は後段 |
| 少サンプル時 | shape のサンプルが 3 未満なら **本試験ペース 1.5分/問 × 難度係数**(難3=1.0 / 難4=1.5 / 難5=2.0 目安)にフォールバック |
| 超過時挙動 | **その時点の解答で強制ロック=確定**。未選択なら未解答=不正解(本試験と同じ) |

## 実装方針(サーバ権威)

- **pack_server.py 側で強制する**(クライアント JS のカウントダウンは表示のみ)。
  - 問題ページの**初回表示時刻をサーバが記録**(`packs/<ID>/timelimits.json` 等)。
  - 期限超過後の解答保存 API を**サーバが拒否**(最後に保存済みの解答で確定)。
  - リロード・別タブ・ブラウザ再起動では期限はリセットされない(初回表示時刻が権威)。
- 制限時間の算出はパック生成時(gen_pack)に shape 別統計を引いて
  manifest に焼き込む(採点時でなく出題時に確定)。
- 表示: 問題ページに目安時間・残り時間カウントダウン・残り30秒警告。
  ロック後は解答欄を読み取り専用にし「制限時間超過により確定」を明示。
- 採点(pack grade)はロック時点の解答を使用。所要欄はロック時刻で記録し
  `(強制)` マーカーを付ける(統計側はロック標本を**中央値算入から除外**する
  — 締切で打ち切られた所要は真の所要でないため)。

## 統計の実装メモ

- ソース: `packs/*/解答.md` の `所要: M:SS` 行(serve 経由の自動計測)。
  問題ID→shape の突合は `answers/<ID>.md` の `種別:` 行。
  ※mixed の解答md は sub-kind(no_seed 等)が載ることがある→ **gen 時の shape 名へ正規化**が必要
  (現行パーサの既知の取りこぼし)。
- 手計測(「(自)」なし)のサンプルも同列に扱ってよい(2026-08-27 時点 総45サンプル)。
- 将来は attempts.jsonl に duration フィールドを足して一元化するのが素直(任意)。
