# STP パズル(BL-268)— ポートの役割と状態を埋めるゲーム

2026-11-11 ユーザ依頼:「紙面の STP 経路当てと似た雰囲気で、ポートのロールと状態を穴埋めする。スマホでも遊びやすく。
リンクのコスト・ポート プライオリティ・速度・ブリッジ ID を手がかりに、図のポートを解いていく。最初は VLAN 1 個の
単純な盤面、最後は MST。ゲーム仕立てで、新しいステージに入るたびに用語と考え方の軽い説明(チュートリアル)を挟む」。

| 論点 | 決定 |

| 言語 | 英語と日本語をボタンで切り替え(教材と同じ・既定は英語・選んだ言語は端末に覚える) |

## 2. ステージ

各ステージ 5 問。全ポート(＋ルート ブリッジ)が合えばクリア。前のステージを 1 問以上クリアすると次が開く…ではなく、
**前のステージを全問クリアで次が開く**(ゲームとして順に進める)。星= 1 回目の答え合わせで正解 3・2 回目 2・それ以降 1・
答えを見たら 0(クリア扱いにはするが星なし)。

| # | 名前 | 盤面 | 学ぶこと(チュートリアル) | PoC |
|---|---|---|---|---|
| 1 | Root Bridge | 3 台の三角形・全 1G | STP の目的・BID(priority + MAC)・ルート ブリッジ・4 つの手順・役割と状態 | 不要 |
| 2 | Path Cost | 3〜4 台・速度が混在 | パス コストの表(short)・受信側で足す・直結が最良とは限らない | 不要 |
| 3 | Tie-Breakers | 並行リンク・ひし形 | 同じコストのとき= 送信元 BID → 送信元ポート ID・port-priority は上流で効く | 不要 |
| 4 | Tuning | 4〜6 台・形いろいろ | `spanning-tree vlan N cost`・port-priority・long 方式・代替の数の検算 | 不要 |
| 5 | Per-VLAN | 3〜4 台 × VLAN 2 つ | Rapid PVST+= VLAN ごとに別の木・sys-id-ext・VLAN ごとの priority | 不要 |
| 6 | Campus | ラボの 2 層/3 層盤面＋端末 | 設計どおりの盤面・エッジ ポート(Desg FWD) | 不要 |
| 7 | MST Region | 1 リージョン・インスタンス 2〜3 | MST・インスタンス・IST・インスタンスごとの priority/cost | **要**(計算器を MST に広げて実機と全ポート照合) |
| 8 | MST Boundary | リージョン違い・PVST+ との境界 | CIST・リージョナル ルート・Master・境界ポート | **要** |
| 9 | Bonus | 共有セグメント・ガード | Backup ポート・root guard の BKN・err-disabled(状態が役割と食い違う) | **要**(Backup は CML の unmanaged switch が BPDU を通すか) |

1〜6 を先に作る(実機での確認は済み: poc/stp/README.md 第2回・第3回・第6回、stp_model の selftest)。7〜9 は PoC の後。

### 生成の決まり(ステージごと)

- 1: 3 台の三角形。level 1〜2= priority で決まる(1 台だけ低い)/ level 3= 全員 32768(MAC で決まる)/ 4〜5= 混在。
- 2: 少なくとも 1 台のルート ポートが「ルートへの直結でない側」(回り道の方が安い)になる盤面だけ。level 1〜2 はリンクにコストも書く。
- 3: コストが同じ候補を BID かポート ID の比較で決める判定が 1 つ以上。並行リンクがあれば上流の port-priority を時々変える。
- 4: 4〜6 台(環＋弦・4 台メッシュ・はしご・ちょう結び・三角＋1)・コストの手設定 1〜2 か所・short/long。代替 2 以上。
- 5: 盤面 1 つに VLAN 2 つ。VLAN ごとに priority を振り、ルートが VLAN で別になる。VLAN ごとの cost 設定が時々入る。
- 6: ラボの 2 層/3 層の配線(`gen_stp.LINKS`/`gen_stp_3tier.LINKS`)を s_rolemap と同じ方法で振る(崩しも含む)。アクセスに端末(エッジ)。

どの盤面も、解くのに要る値(priority・MAC・速度・ポート番号・既定から変えた設定)はすべて画面に出す。MAC はすべて別の値なので答えは 1 つに決まる。

## 3. 画面(スマホ優先)

- ホーム: ステージの一覧(星・鍵)・言語の切替・進み具合のリセット(全体／ステージ)。
- チュートリアル: ステージに初めて入ると、カード 3〜5 枚(用語 → 考え方 → 小さな例)。「?」でいつでも読み直せる。
- 盤面: SVG。ポートは丸い印(役割の頭文字・FWD は塗り、BLK は白抜き＋斜線)。印を押すと下から操作の枠
  (役割のボタン・状態のボタン・前後のポートへ)。スイッチを押すとルート ブリッジの印(王冠)。
- Check: 全部埋めると押せる。間違った印は赤、合った印は緑。正解なら星と解説(ルート ブリッジ → 各スイッチのルート ポート →
  各リンクの指定ポート → 残りが代替)。2 回目からは「答えを見る」も出す。

## 7. 試験のしかた(①の時点)

- `python3 topologies/stp_puzzle.py selftest` … 6 ステージ × 5 level × 150 seed の生成条件・正解の形・解説の 4 節・決定性・進み具合の保存とリセット・API の拒否。
- 画面(ポータルを起動して): `/_stp/?autotest=20` … 各 level を 20 通りの seed で作り、正解での一致・1 か所の誤りの数え方・
  印どうし/印と箱/ラベルどうし/ラベルと箱の重なり・はみ出しを検査(600 盤面で NG 0)。`/_stp/?uitest=1` … チュートリアル送り →
  ルートの印 → 操作枠で全ポート → 間違い 1 か所が赤 → 直してクリア(星 2)→ 次のレベル → 答えを見る → VLAN のタブ → 言語。
  どちらもサーバへ記録しない。見た目は `?demo=fill|check|wrong|sheet`(記録しない・鍵を無視)とヘッドレス Chrome の
  スクリーンショット(幅 390)で確かめた。
- 盤面の図はページの中で描く(座標はサーバ、印とラベルの置き場所は JS の geom())。ラベルは候補の位置を順に試し、箱・印・
  他のラベル・速度の表示にぶつからない所に置く。
