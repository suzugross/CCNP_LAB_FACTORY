## 1. 体感させたいこと（実測の土台= poc/acl/README.md §3・§4）

| # | 事実 | 見え方 |
|---|---|---|
| K1 | 標準 ACL は**ネットワークアドレス**だけを見る。長さは見ない | `permit 10.50.0.0` で /24 も /28 も /22 も残る |
| K2 | 拡張 ACL を直接指定= **src は広告してきた隣接ルータ・dst はネットワークアドレス**。長さは見ない | src に経路のアドレスを書くと全部消える／src に隣接の IP で「その隣接から来た経路」だけ |
| K3 | 広告元は**直接の隣接**。経路を作ったルータではない | RT04 の経路は RT02 経由= src に RT04 を書いても当たらない |
| K4 | route-map 経由の拡張 ACL= **src はネットワーク・dst はマスク** | `host 255.255.255.0` で /24 ちょうどだけ |
| K5 | prefix-list は**アドレスと長さを別々に**指定（ge/le） | `/16 ge 24 le 24` で /24 だけ |
| K6 | ワイルドカードは**ビット一致**（連続した範囲とは限らない） | `10.50.0.0 0.0.2.255` で 0.x と 2.x だけ（1.x・3.x は落ちる） |

## 2. 盤面（IOL 4 台・EIGRP AS 100）

```
            RT04 ── 10.60.x（RT04 が作った経路）
             │ e0/0
             │ e0/1
RT03 ──── RT01（被験・作業はここだけ）──── RT02
  e0/0   e0/1                     e0/0   e0/0
```

- 経路は各ルータの `ip route … Null0` ＋ `redistribute static`（同じルータに同アドレス・異長の経路を置けるように）。
- RT02 と RT03 が**アドレスは同じで長さが違う**経路を広告。RT04 の経路は RT02 が中継。

## 4. PoC 結果（2026-09-21・poc/dlist/README.md）

K1〜K6 はすべて実機どおり。追加で確定した設計上の事実:
- **全体と IF 単位の distribute-list は両方効く（AND）**。
- **同じ IF には in 方向のフィルタを 1 つしか持てない**（2 つ目は `%EIGRP: Access-list filter exists, de-config first`）。
- route-map 経由の dst にマスクのワイルドカード（`255.255.255.0 0.0.0.255`）= マスク値の範囲（/24〜/32）として効く。
- 反映は clear 不要・約 10 秒。ログに `… is resync: route configuration changed`。

## 5. 生成器の設計（gen_dojo_dlist.py → GEN-DOJO-DLIST-<seed>）

盤面= IOL 6 台。RT01（被験）の e0/0=RT02（奥に RT04）・e0/1=RT03・e0/2=RT05・e1/0=RT06。第 2 オクテット A/B/C/D を seed で抽選。

- **第 1 部（観察の提出・32 点）**: 全体（`router eigrp` 直下）に 4 つのフィルタを 1 つずつ掛けて観察し、残った経路を
  prefix-list `PRED-1〜4` に **1 経路 1 行・ge/le なし**で書く（残らないときは `deny 0.0.0.0/0 le 32` の 1 行）。
  形は 8 種のプールから 4 つ（拡張直接と route-map 経由を必ず含む）。採点= 期待集合の各行 regex ＋ 残りの battery の not_regex。
- **第 2 部（本番・64 点）**: IF ごとに方式指定のタスク 1 つ（効果 12 ＋ 方式の指紋 4）。
  - e0/0（RT02＋RT04）: 拡張 ACL を直接指定で「RT04 が作った経路（10.B.x）だけ受け取らない」（src に RT04 は効かない→ dst で絞る）
  - e0/1（RT03）: prefix-list で「長さが /24 のものだけ」等（ge/le）
  - e0/2（RT05）: 標準 ACL **1 行**で「10.C.0.x と 10.C.2.x の網だけ（長さ問わず）」等（非連続ワイルドカード）
  - e1/0（RT06）: route-map 経由・prefix-list 禁止で「10.D.0.0/24 ちょうどだけ拒否」等（dst= マスク）
- **最終状態に全体の distribute-list を残さない**（4 点）。
- 故障注入は無し（道場= 何も無い状態から組む）。E2E= 初期 4 点 → 模範解 100。

## 6. 実装・E2E（2026-09-21）

- `topologies/gen_dojo_dlist.py`（selftest= 300 seed ＋ PoC と同じ値の固定値チェック）。第 1 部の形は 9 種プールから 4 つ（標準・拡張直接・route-map 経由を必ず含む）。
- 第 2 部の変種: T1 {RT04 の経路すべて / 網 10.B.0.0 だけ} × T2 {/24 だけ / /24 以下} × T3 {0.x と 2.x / 1.x と 3.x} × T4 {/24 ちょうどだけ拒否 / /25 以上を拒否}。
- E2E（GEN-DOJO-DLIST-3131）: 初期 4 → 模範 100。第 1 部の 4 フィルタを実機で 1 つずつ掛け、期待集合と**全一致**。
  誤答: T1 に `deny ip host 10.0.24.4 any`（RT04 を src に）→ RT04 の経路が残り −12（カウンタは deny 0 件・permit 12 件）／T3 を 2 行 → −2。
- 採点の罠: `show ip route <prefix>` の詳細表示の next-hop は `10.0.12.2, from 10.0.12.2, … via Ethernet0/0`（`via <IP>` は一覧表示だけ）。
