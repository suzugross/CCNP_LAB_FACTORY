# ルーティング経路づくり(BL-271)— 経路を足して、お題のルータを通すゲーム

2026-11-12 ユーザ構想:「STP の経路選択パズル(BL-270)がそこそこいい出来だったので、L3 が絡んだゲームも作りたい。
まずは static route を題材に、どのルータを通過して到達する、というルーティングをゲーム化したい。ロンゲストマッチや
デフォルトルートなどで罠を作るのが良さそう」。案(作る型・往復・消せない経路・編を足していく形)を示し、
「大体推奨案で大丈夫。編はどんどん追加される形式で。盤面のデザインも L3 らしい、ほかのネットワークを繋いでいる感が
出たら嬉しい」で了承。

STP 経路づくり([STP-PATH.design.md](STP-PATH.design.md))の L3 版。あちらは「つまみを変えて STP の木を組み替える」、
こちらは「経路表に static route を足す・消す・変えて、パケットの通り道を組み立てる」。

## 1. 決めたこと

| 論点 | 決定 |
|---|---|
| 形 | **作る型**(お題の経路になるよう経路を組み立てる)。読む型(経路表を見て次の行き先を当てる)は別に作らず、変えるたびにパケットが流れて「当てはまった行」が光る形で中に含める(ユーザ了承) |
| 往復 | ステージ 2 から**往復が標準**(ping は戻りの道も要る)。ステージ 1 だけ片道(ユーザ了承) |
| 縛り | **🔒 消せない経路**(理由つき: 他部署の管理など)と**触れないルータ**(他社・ISP)を使う。ロンゲストマッチの罠の主な仕掛け(ユーザ了承) |
| 編 | **1 つのゲームに編をどんどん足す**(ユーザ決定)。Static 編 → 以後 PBR・ACL・OSPF・IPv6・track などを編として追加(§8) |
| 盤面 | **L3 らしく、ほかのネットワークを繋いでいる感**を出す(ユーザ要望・§3) |
| 用語と数値 | STP 経路づくりと同じく**本物**。`ip route`・next-hop・AD・`show ip route` の表示・IP アドレスはそのまま使う |
| 手数 | **変更した設定の行数**(`ip route …` と `no ip route …` の数)。同じ宛先・同じ次の行き先の AD を変えるのは 1 行(IOS は上書き)。元に戻せば減る(§2) |
| 遊ぶ場所・保存・言語・ノルマ | STP のゲームと同じ(ポータルの Games・スマホは LAN 経由・進み具合はサーバ保存でリセット可・日英切替で既定は英語・ノルマに数えない) |
| 見せ方 | STP 経路づくりの §9〜§11 と同じ([[feedback-game-compact]]): 盤面に出すものはステージごとに増やす・お題は文＋今の状態・ルールはいつでも 1 枚・解説は押すと開く・チュートリアルは 1 枚 1 つの話で丁寧に |

## 2. 遊び方

1. 盤面: ルータ・拠点の LAN(端末つき)・ルータ間のリンク(それぞれがネットワーク)・外のネットワーク(雲)。
2. お題: 「PC1 → SRV1 の通信を R1 → R2 → R4 の順に通す」「戻りも届くこと」など(§5)。目標の経路を色の帯で描き、文でも示す。
3. 操作: ルータを押すと経路表(下から出る枠)が開く。
   - 「＋経路」→ 宛先をチップから選ぶ(盤面の LAN・拠点のまとまり・端末の /32・0.0.0.0/0。ステージで開放)→
     次の行き先を選ぶ(隣のルータ= その向こう端の IP・Null0)→(ステージ 6 から)AD。
   - 既存の行を押すと「消す」・「AD を変える」。🔒 の行は理由が出るだけ。
   - 触れないルータは経路表を見るだけ。
4. 変えるたびにサーバで経路表を作り直し、パケットを流す。各ルータで「宛先に当てはまる行」が光り、一番長いものが選ばれる。
   落ちたらその場所に ✖ と理由(経路なし・Null0・TTL 切れ(ループ))。
5. すべてのお題を満たしたら「開通」。手数で星を付ける(STP 経路づくりと同じ: ★3= 最少・★2= 最少 + 1・★1= 上限以内。上限= 最少 + 2、
   序盤は + 3)。「答えを見る」は 2 回目の失敗から。
6. 画面の隅に「変更した設定」を IOS のコマンドで並べる:

```
R1: ip route 10.4.1.0 255.255.255.0 172.16.12.2
R2: ip route 10.4.0.0 255.255.0.0 172.16.24.2
R3: no ip route 0.0.0.0 0.0.0.0 172.16.13.1
R2: ip route 10.4.1.0 255.255.255.0 172.16.23.2 200
```

### 手数の数え方

- 行の鍵 = (ルータ, 宛先, 次の行き先)。鍵が増えた= `ip route` 1 行、減った= `no ip route` 1 行、同じ鍵で AD だけ違う= `ip route … <AD>` 1 行。
- 次の行き先を変える= 消して足す= 2 行(IOS でも 2 行要る)。画面に「変える」は置かず、消すと足すを別々に数える。
- 初期状態との差分で数えるので、元に戻せば減る(STP 経路づくりの「変わっているつまみの数」と同じ考え)。

## 3. 盤面のデザイン — 「ネットワークを繋いでいる」地図

STP のゲームは箱(スイッチ)と線(リンク)の図だった。こちらは**ネットワークが主役**の地図にする。ルータは
ネットワークとネットワークの継ぎ目、という L3 の見え方を絵で伝える。

| 物 | 描き方 | ねらい |
|---|---|---|
| 拠点(サイト) | ルータとその LAN を、色つきの淡い領域で囲む(拠点ごとに色相を変える・名前の札「Site 4」など) | 別々のネットワークが並んでいる感。/16 のまとまりを「領域」として見せる |
| LAN | 領域の中の横長の札(イーサネットのバス線)に `10.4.1.0/24`。端末(PC・SRV)が線からぶら下がり、`.10` などのホスト部を添える | 宛先が「ネットワーク」と「その中のホスト」の 2 段であること |
| ルータ | 丸いルータの記号(Cisco の図記号ふう・矢印 4 本)＋名前。拠点の領域の縁に置き、中央の WAN 側を向く | ルータは拠点の出入り口 |
| リンク | ルータ間の線は WAN の領域(中央・無地)を通る。線の中ほどにサブネット `172.16.12.0/30`、両端にホスト部 `.1`・`.2` | リンクもネットワーク。next-hop の IP がどちらのルータかが読める |
| 外のネットワーク | 雲の形(Internet・Partner)。中の端末(WEB など)と、触れないルータ(ISP・Partner の箱に 🔒) | 自分の管理外のネットワークとつながっている感 |
| パケット | 宛先を書いた小さな封筒(`→ 10.4.1.10`)がリンクを流れる。行きと帰りで色を変える | 1 ホップずつ運ばれる様子 |
| 当てはまった行 | パケットがルータにいる間、吹き出しで選ばれた行(`10.4.1.0/24 → R4`)。経路表の枠では、当てはまる行がすべて光り、一番長い行に印 | ロンゲストマッチを目で見る |
| **宛先の範囲** | 経路表の行(またはチップ)を押すと、その宛先が覆う範囲が地図の上で光る: /32= 端末 1 台・/24= LAN 1 つ・/16= 拠点の領域・0.0.0.0/0= 地図全体 | **プレフィックス = 地図の上の範囲**。長いほど狭い範囲を指す、を体で覚える |

色の決まり: 拠点の色は LAN の札・経路表の宛先のチップにも使う(`10.4.x.x` のチップは Site 4 の色)。経路表を見ただけで
「どの拠点へ向かう行か」がわかる。

アドレスの決まり(読みやすさ優先・本物の形):

- 拠点 N の LAN: `10.N.k.0/24`(k = 1, 2)。拠点ごとに `10.N.0.0/16` でまとめられる(集約の罠に使う)。
- 端末: PC は `.10`、サーバは `.100`(例 PC1 = `10.1.1.10`、SRV1 = `10.4.1.100`)。既定ゲートウェイは LAN のルータの `.1`。
- リンク: R*X*–R*Y*(X < Y)は `172.16.XY.0/30`、X 側が `.1`、Y 側が `.2`。next-hop が `172.16.24.2` なら R4、と読める。
  ★この番号の振り方は**画面・チュートリアルで決まりとして説明しない**(2026-11-12 ユーザ指摘「初心者はそういうネットワークのルールが
  あるんだと勘違いするかもしれない」)。チュートリアルは「リンクにどのアドレスを使うかはネットワークを作る人が決める(決まった番号は
  無い)。相手のアドレスは地図で読む」と書く。
- 外: ISP とのリンクは `203.0.113.0/30`、Internet の WEB は `198.51.100.10`(どちらも文書用のアドレス)。
  Partner は `192.168.50.0/24`。ISP・Partner のルータは触れない(経路は固定・NAT は省く、とルールの枠に 1 行)。
- インターフェース名: `Gi0/0`= LAN、`Gi0/1`〜= リンクの順。`show ip route` の connected の行で使う。
- ループバック(ステージ 7 から): `10.255.0.N/32`。

盤面の大きさ: 幅 400(STP のゲームと同じ SVG 座標)。ルータ 4〜6 台。拠点の領域は外向き、WAN は中央。形は四角・四角＋対角線・
ひし形・5 台の家形・はしご(6 台)を候補にし、実装で重なりを見て決める(STP 経路づくりの「5 角形＋弦・6 角形は使わない」の教訓)。

### 見本で決めた描き方(2026-11-12・見本 A= 4 拠点の四角＋対角線、B= Internet・ISP・コアの家形)

- 拠点の領域は角(上の段・下の段)に置き、ルータは領域のすぐ外(WAN 側)に置いて、LAN へは Gi0/0 の線を領域の中へ引く。
  ルータを領域の縁にまたがせると、ルータ間のリンクが領域の縁に沿って走り見づらい。
- 拠点の名前と /16 は、ルータから遠い側の縁(上の段は上・下の段は下)。ルータの名前は盤面の外側(左の列は左・右の列は右)。
- LAN は端末を入れた札(上に拠点の色の帯とサブネット)。イーサネットのバス線は、2 つの LAN を持つ拠点で線が交わるので使わない。
  2 つの LAN は横に並べる(幅 83 ずつ)。
- リンクの札(サブネット)は線の中ほどに白い丸角の札で載せ、両端のホスト部(`.1`・`.2`)はルータの中心から 31 離れた所、
  線の上側(縦の線は左側)に 9 ずらす。縦のリンクは長さ 100 以上(短いと札とホスト部が重なる)。
- 交わる対角線は札の位置を中ほどからずらす(見本 A は 0.42)。
- パケットは封筒に宛先の札(行きは赤・帰りは青緑)。札は線の上か横に出し、リンクの札と重ねない。
- 盤面ごとに座標を手で決めた型(テンプレート)を持ち、生成はその型に拠点・端末・経路を割り当てる(自動配置はしない)。
- 見本: `/tmp/…/scratchpad/mock/board-mock.html`(この会話の一時置き場)。画面の部品は §9 の index.html に移す。

## 4. 経路の計算(`route_model.py`)— IOS の決まりどおり

計算はサーバだけで行う(STP と同じ。画面は変えるたびに `POST /_api/route_path/eval`)。

- 経路表: up のインターフェースの connected(C・AD 0)と local(L・/32)＋ static(S・既定 AD 1)。
  - static は**次の行き先が解決できるときだけ**表に入る(next-hop を経路表で引き、connected に行き着く)。Null0 宛ては常に入る。
  - 同じ宛先に複数の static: AD の小さいものだけが入る(フローティング static)。同じ AD なら全部入る(ECMP)。
  - 同じ宛先の connected と static: connected が勝つ(AD 0)。
- 転送: 宛先 IP に当てはまる行のうち**プレフィックスが一番長いもの**(AD は同じ宛先の中でだけ比べる。長さが先)。
  - connected の LAN に当たれば端末へ届ける(その IP の端末が無ければ ARP が返らず落ちる)。
  - 当たる行が無い= 落ちる(経路なし)。Null0 = 落ちる。同じルータへ戻った= ループ(TTL が尽きて落ちる)。
  - ECMP は両方へ分かれる線で描き、お題の「この経路」は満たさない扱い(CEF のハッシュは読めないので、どちらへ行くかは当てさせない)。
- 端末の既定ゲートウェイは LAN のルータで固定(変えるつまみは後の編)。
- 障害: リンクを落とすとそのインターフェースが down → connected が消える → その IP を次の行き先にした static が外れる →
  フローティングが表に入る。

### 実機で確かめること(PoC・ステージに使う前に)

| # | 論点 | 使うステージ | 状態 |
|---|---|---|---|
| 1 | 基本: connected/static・ロンゲストマッチ・AD は同じ宛先の中だけ・解決できない static は表に入らない・リンク断でフローティングへ | 1〜7 | **済・一致**(2026-11-12)。両端 shutdown で 6 秒以内に AD 5 へ。片側だけ shutdown は相手側が up/up のまま AD 1 が残りブラックホール(ゲームは「リンク断 = 両端 down」で正しい。track の編の材料) |
| 2 | 再帰: 隣でない next-hop の解決・**デフォルト経路を使って解決するか**・自分で自分を解決する static | 8 | **済**(2026-11-12)。/32 や /16 での再帰は一致・自分で自分は入らない。**デフォルト経路だけでは解決しない**(`show ip static route` で `[N]`・70 秒待っても・`install-routes-recurse-via-nexthop` でも同じ)→ `VIA_DEFAULT = False`。**Null0 の行を通る再帰は表に入り、Null0 で捨てる**(CEF `nexthop … Null0`)→ 計算器を直した |
| 3 | static の ECMP(同じ AD・別の next-hop)が両方入るか・traceroute の見え方 | (当面お題に使わない) | **済**。両方入る。via は設定の順でなく next-hop の IP の降順(3 例)→ 計算器の並びを合わせた |
| 4 | 出口インターフェースだけの static(Ethernet では proxy ARP 頼み) | 使わない(next-hop 指定だけにする) | — |
| 5 | /32 の static が connected の /24 より長いので勝つ(LAN の中の 1 台だけ横取り) | 5 | **済・一致** |
| 6 | next-hop の選び方(自分の IP・隣でない IP・/30 のブロードキャストとネットワーク アドレス) | 2〜 | **済**(2026-11-12 追加 PoC)。自分の IP は `%Invalid next hop address (it's this router)` で設定に入らない。隣でない IP はエラーなく設定に入るが表に入らない(`[N]`)。ブロードキャスト・ネットワーク アドレスは表に入るが CEF は receive で R1 で止まる(画面の候補には出さない) |

照合のしかた: 盤面を IOL のルータ 4〜6 台に config として流し、`show ip route` と traceroute を集めて計算器と突き合わせる。
既存の `topologies/netmodel.py` の `parse_rib_text`・`forward_paths`(ロンゲストマッチの転送シミュレータ)で実機の経路表から
道を引き、計算器の道と比べる。公式の裏どり: IOS の IP Routing: Static Configuration Guide(static の導入条件・フローティング)・
CEF の決まり(ロンゲストマッチ)。

## 5. お題の種類

| 種類 | 文の例 | 判定 |
|---|---|---|
| 経路 | PC1 → SRV1 の通信を R1 → R2 → R4 の順に通す | 行きの道がちょうどその列 |
| 経由 | PC1 → SRV1 の通信が R3 を通る | 行きの道に R3 がある |
| 往復 | 戻り(SRV1 → PC1)も届く | 戻りの道が届く(道は問わない)。「戻りも同じ道」の形もある |
| 壊さない | PC2 → SRV1 の通信は今のまま届く | 届く(道は問わない) |
| 障害時 | R1–R2 が切れたら PC1 → SRV1 は R3 を通る | リンクを落とした状態でも計算し、その道で判定 |
| 届かせない | 存在しない宛先 10.4.9.9 がループしない(Null0 で捨てる) | ループせずに落ちる |

満たしていない間は今の状態を添える(「今: R1 → R3 → R4」「今: R2 で落ちる(経路なし)」)。

## 6. ステージ(Static 編)

各ステージ 5 問(level 1〜5)。前のステージを全問開通で次が開く。盤面に出すものはステージごとに増やす(隠すのは表示だけ・
まだ見せていない値で答えが決まる盤面は出さない)。2026-11-12 ユーザ指示「一番最初の盤面はすごくシンプルに。画面に出す
パラメータも最小限にして、初心者が面食らわないように」「直接接続のところから進めてもいいかも」で、ステージ 1 を
connected(ルータ 1 台)にし、static はステージ 2 から(§11)。

| # | 名前 | 増えるつまみ | お題 | 罠・学ぶこと | 盤面に新しく出るもの(`SHOW_FROM`) |
|---|---|---|---|---|---|
| 1 | つながっているネットワーク | インターフェースの有効化(`no shutdown`)・インターフェースの IP | 片道 1 本(ルータ 1 台) | ルータは IP を付けて up にしたインターフェースのネットワークを最初から知っている(C)。設定は要らない。端末は自分の LAN の外へは既定ゲートウェイ(`.1`)へ渡す | ルータ・LAN の札(サブネット・端末の IP と GW)・ルータの LAN 側の IP と up/down・経路表(C の行だけ・宛先 → つながっている IF)・パケット・落ちた理由・変更した設定 |
| 2 | 道をつなぐ | 経路を足す(LAN の宛先・次のルータ= 相手の IP) | 片道 1 本(ルータ 2〜4 台) | 知らないネットワークへの道は教える(static)。`ip route` は次の行き先を相手の IP で書く。リンクもネットワーク | リンクのサブネットと `.1`・`.2`・next-hop の IP・経路表の C/S |
| 3 | 行きと帰り | — | 往復 | 戻りの経路が無いと ping は通らない | 戻りのパケット(2 色目) |
| 4 | デフォルトルート | 0.0.0.0/0・初めからある経路を消す | 往復＋ Internet | 手数を減らす。デフォルトどうしの向け合いでループ(TTL 切れ) | Internet の雲と ISP(🔒 触れない) |
| 5 | ロンゲストマッチ | 宛先の長さ(/8・/16・/24・/32・§17) | 往復 | 🔒 消せない細かい経路が通信の一部を横取り → もっと長い経路で上書き。同じ長さ・同じ AD は等コストで分かれる。/32 は connected の /24 にも勝つ | 拠点の領域と /16・宛先の範囲の光り・🔒 の経路 |
| 6 | 集約と巻き添え | — | 往復＋壊さない | /16 にまとめると手数は減るが、別の通信を連れていく → 例外を長い経路で。**集約の計算は目で見て学べ、選べる形に(§15)** | 2 本目のお題・Partner の雲 |
| 7 | 予備の経路 | AD | 往復＋障害時 | フローティング static は平常時は表に出ない。**AD より長さが先**(/24 の AD 250 は /16 の AD 1 に勝つ) | `[AD/metric]`・障害の切り替えボタン |

## 7. 生成と最少手数

- 盤面: 形(§3)を選び、拠点・LAN・端末・アドレスを決める → 初期の経路(ステージの罠を含む)→ お題 → 最少手数を求める →
  初期がお題を満たさず、最少手数が level の範囲に入る盤面だけを採る。同じ seed なら同じ盤面。
- **最少手数の求め方(ルータごとに分けて解く)**: 各ルータの転送の判断(関係する宛先 IP × 障害の有無 → 届ける・どの隣へ・落とす)は
  そのルータの経路表だけで決まり、手数(行の差分)もルータごとの和になる。そこで
  1. ルータごとに、変更の組(足す・消す・AD を変える。宛先はお題の端末を含むチップだけ・次の行き先は隣と Null0)を 3 行まで総当たりし、
     「判断の組 → 最少の行数」の表を作る。
  2. お題ごとに、満たす道の候補を列挙する(経路= 1 本・経由/壊さない= 単純な道すべて・届かせない= どこかで落ちる道)。
  3. 道の候補の組み合わせごとに、各ルータが取るべき判断を出し(食い違えば捨てる)、ルータごとの表から最少の行数を引いて足す。最小が答え。
  - AD の候補は、同じ宛先に 2 本以上が並ぶときだけ試す(1 本なら AD は結果を変えない)。
  - selftest で、小さい盤面は全体の総当たり(ルータを分けない)と突き合わせる。
- 最少の解の一例を覚えておき、「答えを見る」と「解説」に使う。

### 実装で決めたこと(2026-11-12)

- **盤面の型**(`route_path.TPL`): one2・one3(ステージ 1)・line2・line3・tri・sq・sqx(ステージ 2〜3)・house・sqi(ステージ 4・Internet と ISP)。

- **表示の出し分け**: `SHOW_FROM` は累積(そのステージ以降ずっと出る)。インターフェースの札・端末の完全な IP・GW は
  「インターフェースがつまみのステージ」(1)だけに出す(画面は `knob(pz,'if')` で判定)。ステージ 2 からはホスト部(`.10`)だけ。
- **宛先のチップ**: 盤面の LAN の /24 と(ステージ 4 から)0.0.0.0/0。Internet の 198.51.100.0/24 は出さない
  (書き出せない宛先はデフォルトで指す、がステージ 4 の題材。出すと最少の解が /24 になってしまう)。
- **最少手数**: ルータごとの「変更の組 → 判断の組」の表(1 ルータ 3〜4 行まで)＋お題を満たす道の組み合わせを枝刈りで探す。
  selftest で小さい盤面(最少 3 手まで)はルータを分けない総当たりと照合。
- **パケットは「送ってみる」で 1 回だけ流す**(2026-11-12 ユーザ指摘「ずっと動いているとうざい。最後に届くか試してみるボタンを押すと
  動いて、動作確認ができて Pass 判定」)。設定を変えている間は封筒を送る側の LAN の線の上に置いておくだけで、道も ✓/✗ も出さない。
  (送る前の封筒は出さない= 2026-11-12 ユーザ指摘)。押すと封筒(札= 宛先 IP)がお題の順(行き → 帰り)に実際の道を 1 ホップずつ進み(ルータで一瞬止まる・ループはもう 1 周まわる・ECMP は同時)、
  流し終わったら道(点線)・届いた所の ✓・落ちた所の ✖ と理由・お題の各行の ✓/✗ と「結果: …」を出す。すべて満たせば開通(星)、
  だめなら「まだ開通していません」。設定を変えると結果は消える(もう一度送って確かめる)。「答えを見る」も答えの設定で送ってみせる。
  動きを減らす設定(prefers-reduced-motion)なら動かさずに結果を出す。落ちた印の位置はほかの札と重ならない所を候補から選ぶ。
- **経路表を引く小窓**(2026-11-12 ユーザ要望「ルータに着くたびにルーティングテーブルを引いているアニメ。実際に登録されているテーブルから
  選択されるのが見えるのがいい」): 送っている間、封筒がルータに着くたびに、そのルータの経路表(そのとき表に入っている行。表示の出し分けは
  ルータの枠と同じ)の小窓をそばに出す。行は**プレフィックスの長い順**に並べ替え(小窓の中だけ)、上から 1 行ずつゆっくり照らして、外れた行は
  ×・薄く、**最初に当てはまった行で止まって「◀ ここで決まり」**(2026-11-12 ユーザ要望「上から順にゆっくり検討して、引っかかったらそこで
  引っかかってほしい」。show ip route の並び= アドレス順のまま最初の一致で止めると 0.0.0.0/0 で止まり、ロンゲストマッチと食い違う(ACL の
  上から順の誤解になる)ので、長い順に並べて「最初の一致 = 一番長い行」にした。小窓に「長い順に並べて上から照らす」と添える)。決めたこと(「→ R4(172.16.24.2)へ送る」「つながっている(Gi0/1)→ SRV1 に届ける」
  「当てはまる行なし → 捨てる」「Null0 → 捨てる」)を出してから先へ進む。端末を出る時は「宛先は自分のネットワークの外 → GW に渡す」。
  同じ流れで 2 度目に着いたルータ(ループ)と ECMP の 2 本目は引かない。送っている間はボタンが「早送り」になり、押すと残りの小窓を飛ばして速く流す。
- **チュートリアルの例の盤面にも「▶ パケットを送ってみる」**(2026-11-12 ユーザ指摘「チュートリアルの封筒完全廃止はだめ。ボタンを押したら
  パケットの動きを見られるように」): 例は結果(道・✓/✖・番号の札)を描いた状態で開き、ボタンで遊ぶ画面と同じ動き(封筒・経路表の小窓)を
  1 回流して、終わったら結果と番号の札に戻す。
- **速さとコマ送り**(2026-11-12 ユーザ指示「送る時の速さを 5 割くらい遅く」「コマ送りできないか。ステップごとにしっかり確認したい」):
  移動は毎秒 75・照らす 1 行 0.57 秒・決まったあと 1.8 秒。盤面の下(チュートリアルは例の下)に「コマ送り(1 歩ずつ止める)」の
  スイッチ(ブラウザが覚える)。オンで送ると、端末の「GW に渡す」・経路表の 1 行ごと(× / 当てはまった)・決めたこと・流れと流れの間
  (行きが着いて帰りを送る前)で止まり、送るボタンが「次へ ▶」、隣に「残りを流す ▶▶」(以後は止まらない)。移動そのものは動く。
- **ルータの枠**: 経路表(行を並べるだけ。当てはまる行の色付けや「使う」の印は、作っている間は邪魔なので出さない= 2026-11-12 ユーザ指摘)・
  表に入っていない設定(理由つき)・インターフェースの一覧(ステージ 1。1 行ずつ: 名前・IP・up/down/shutdown・どの LAN 側)・先頭に「＋ 経路を足す(地図で選ぶ)」。
  ステージ 1 でインターフェースの札(地図)か一覧の行を押すと、**その IF の設定だけ**の枠(「R1 · Gi0/1」・IP の候補・有効/無効・一覧へ戻る)に
  なり、地図の札も橙で囲む(2026-11-12 ユーザ指摘「選んだインターフェースのパラメータだけ表示できないか」)。重なる IP は選べず理由を出す。
- **経路は地図の上で足す**(2026-11-12 ユーザに 3 案を示し「地図の上で選ぶ」を選択): 「＋ 経路を足す」で枠を閉じて盤面に戻り、下の帯に手順を出す。
  ① 宛先の LAN の札を押す(選べる札に橙の点線。自分につながる LAN は選べず「経路は要りません」。デフォルトのステージは Internet の雲か帯の
  「0.0.0.0/0」)→ ② 印の付いた隣のルータを押すと、その場で足す(ボタン不要。AD のステージは ③ AD を選んで「足す」)。元のルータを押すか
  「やめる」で取り消し、「宛先を選び直す」で ① へ。足したら上に「足しました: R1(config)# ip route …」。
  足した経路は、ルータから次の行き先の隣へ向かう小さな矢印(色= 宛先の LAN・表に入っていない経路は白抜き)で盤面に残る。

## 11. 最初の盤面はすごくシンプルに・直接接続から(2026-11-12 ユーザ指示)

指示:「一番最初の盤面はすごくシンプルにしてほしい。画面に出すパラメータも最小限にして、初心者が面食らわないように」→
続けて「直接接続のところから進めてもいいかも」。[[feedback-game-compact]] の「最初は最小限・順に出す」をこのゲームでも最初から守る。

- **ステージ 1 = connected(ルータ 1 台)**: ルータ 1 台に LAN が 2〜3 つ。PC1 → SRV1 が届かない原因は、SRV1 側の
  インターフェースが shutdown・IP が無い・別のサブネットの IP・(送る側の)ゲートウェイと違う IP(`.254`)のどれか。
  つまみは**インターフェースの有効化**と**インターフェースの IP**(候補から選ぶ)の 2 つだけ。経路を足す操作はまだ無い。
  - level 1= shutdown を戻す(1 手)/ 2= IP を付ける(1 手)/ 3= LAN 3 つで 2 か所(2 手)/ 4= 別のサブネットの IP(1〜2 手)/
    5= 送る側の IP が `.254` でゲートウェイ(`.1`)と合わない＋もう 1 か所(2 手)。
  - 学ぶこと: IP を付けて up にすると、そのネットワークが経路表に C で載る(設定は要らない)。端末は LAN の外へは既定
    ゲートウェイに渡す。ゲートウェイの IP がルータに無いと最初の 1 歩で落ちる。
  - 重なる IP(2 つのインターフェースに同じサブネット)は IOS が受け付けないので、画面でも選べなくする(理由を出す)。
- **ステージ 1 で画面に出すもの**: ルータの名前・LAN の札(サブネット・端末の名前と IP・GW)・ルータの LAN 側のインターフェース
  (札に名前・IP・up/down)・封筒(宛先 IP)・落ちた所の ✖ と理由・経路表は C の行だけの 2 列(宛先 → つながっている IF)・
  変更した設定(`interface Gi0/1` / `ip address …` / `no shutdown`)。
- **ステージ 2 = static の入口(ルータ 2〜4 台)**: level 1= 2 台で 1 手・level 2= 3 台の一列で 2 手・level 3= 三角で「R2 を通って」・
  level 4〜5= 四角で経路を指定。リンクのサブネットと `.1`・`.2` をここで出す(ステージ 1 で「インターフェースの IP =
  そのネットワークの一員」を覚えた後なので、リンクもネットワーク、がつながる)。経路を足す操作は 2 段(宛先の LAN を選ぶ →
  次のルータを押す。札には相手の IP が出る)。
- **出さないもの(裏では回す)**: L の行・AD・拠点の領域・Internet。
- お題: ステージ 1〜2 の level 1〜2 は「PC1 から SRV1 へ届ける」だけ。ステージ 2 の level 3〜5 で「R2 を通って」「R1 → R3 → R4 の順に」。
- 計算器に足すもの: インターフェースの設定(IP・shutdown)を設定の側に持つ・端末の既定ゲートウェイ(同じ LAN の宛先は直接・
  ゲートウェイが LAN に無ければ最初の 1 歩で落ちる)・届けるのは端末のいる LAN に向いたインターフェースの C に当たったときだけ。

## 12. トランジットのサブネットとインターフェースを意識させる(2026-11-12 ユーザ指示)

指摘:「ルータ間のトランジットのサブネットやインターフェースを意識させるゲームデザインにしたい。今の経路作成だと、とりあえず隣のルータを
選ぶだけで運ばれている感じ」→ 4 案を示し、A・B・C を選択(D= インターフェースの一覧は見送り)。

- **A. 次の行き先は IP を押す**: 地図で選ぶ ② では、隣のルータでなく、地図の上の IP(リンクの両端に札で出す)を押す。下の帯に元のルータの
  インターフェース(`Gi0/1 10.0.0.121/30`)を並べる。② の間はリンクのサブネットの札を出さない(IP の札と並ぶと邪魔= 2026-11-12 ユーザ指摘)。
  - 盤面のどのリンクの IP でも選べる。自分の IP は IOS の原文 `%Invalid next hop address (it's this router)` を出して足さない(PoC #6)。
    隣でない IP は足せるが「経路表に入りません」と知らせる(表の「表に入っていない設定」に理由つきで出る= IOS の `[N]`)。
  - 札の置き場所は、リンクに沿った距離 × 線の両側 × 線からの離れ方の候補から、ほかの札・ルータ・LAN の札・先に置いた札と重ならない所。
    札と線の端を細い線で結ぶ。画面の autotest は各ルータの ② の盤面も描いて重なりを検査する。
  - 最少手数の探索は今までどおり隣の IP だけを候補にする(隣でない IP はステージ 8 の再帰までは手数を減らさない)。サーバは盤面の
    リンクの IP なら受け付け、自分の IP は断る。
- **B. 出口と受け口を見せる**: 経路表の小窓の見出しに受け口(「R4 の経路表(Gi0/0 で受信)」= 前のホップに向いた IF・最初のルータは送り元の
  LAN 側)、決めたことに出口(「→ 10.0.0.194(R3)へ・Gi0/2 から出す」)。解説の文にも出口を足した。
- **C. リンクのアドレスを盤面ごとにバラバラに**: ステージ 2 の Lv 1・2 だけ 172.16.XY の決まり、Lv 3 以降とステージ 3 からは、1 つの /24
  (10.0.0.0・10.0.1.0・172.31.0.0・192.168.0.0 のどれか)から /30 を乱数の位置で取り、どちらの端が小さい方かも乱数(`route_path._link_blocks`)。
  札が長くなりすぎる桁(192.168.100.x)は対角線の札と重なるので使わない。チュートリアル(ステージ 2 の 2 枚目・遊び方)とルールの枠を合わせた。

## 14. 経路は穴埋めで書く(2026-11-12 ユーザ指示)

指示:「経路作成は穴埋めにしたい。宛先・マスク・ゲートウェイ・管理距離の欄。選ぶのは簡単すぎる。途中のレベルからはマップで選ぶの廃止でも
いい」→ §12 A の「地図で選ぶ(① 宛先の LAN → ② 次の行き先の IP)」をやめ、`ip route` に続く 4 つの欄を書く形にした。

- **欄**: ルータの枠の「＋ 経路を足す」で、下の帯に `R1(config)# ip route` と 4 つの欄(宛先・マスク・ゲートウェイ・管理距離)が出る。
  管理距離は空けると 1(欄の薄い字 `1`)。Enter で「足す」、Esc で「やめる」。欄を開いたままルータを押すと、書く先のルータが替わる
  (書いた値はそのまま= 同じ経路を何台にも書くとき用)。足すと帯が閉じ、`足しました: R1(config)# ip route …` を出す。
- **地図の補助はステージ 2 の Lv 1・2 だけ**(`route_path.map_assist`= リンクのアドレスが 172.16.XY の決まりのレベルと同じ境目):
  LAN の札を押すと宛先とマスクが入り(/24 → 255.255.255.0 の書き換えを見せる)、リンクの端の IP の札を押すとゲートウェイが入る。
  Lv 3 からは札は押せず IP の札も出ない。地図のサブネットの札と端の `.x` を読んで自分で書く。
- **IOS が断る形は IOS の応答の文で断る**(PoC input_form・[poc/route/README.md](../../poc/route/README.md) の「穴埋めの入れ間違い」):
  形が崩れた IP・`/24` のマスク・AD 0 や 256 は `% Invalid input detected at '^' marker.`(打ったコマンドと ^ を添える。^ は間違えた欄の頭=
  実機は数の途中を指すこともあるので近似)、1 が続かないマスク・ホスト部が 0 でない宛先は `%Inconsistent address and mask`、ゲートウェイ
  0.0.0.0 は `%Invalid next hop, looping back to the network`、127/8・224 以上は `%Invalid next hop address`、自分の IP は
  `… (it's this router)`。どれも下に日本語で 1 文の理由。誤った欄は赤枠。
- **IOS が受け付ける形は受け付けて、計算器どおりに扱う**: 隣でない IP・持ち主のいない IP(リンクのブロードキャストなど)は足せて、
  前者は表に入らない(unresolved)、後者は表に入るが先へ送れない(nohost)。AD 255 は設定に入るが表に入らない(計算器に `ad255` を足した)。
  同じ宛先・同じゲートウェイを書き直すと管理距離が置き換わる(1 行= 1 手)。前の「隣でない IP です」の知らせは出さない(送ってみて気づく)。
- **ゲームの決まり**: 長さを選ぶステージ(つまみ `len`= ステージ 5〜)より前は、宛先は地図の LAN(ステージ 4 からデフォルトも)だけ。
  最少手数の探索の範囲(LAN の札とデフォルト)と合わせるため(/32 や集約で探索より少ない手数が出るのを防ぐ。ステージ 5 で `len` を開く時に
  探索の候補に長さ違いを足す)。この断りには IOS の文を出さない(IOS は受け付けるので)。Internet の宛先を書いたら「デフォルト ルートで指す」。
- **管理距離の欄はステージ 2 から出す**(ユーザの見本どおり)。ステージ 2〜4 では AD を変えても最少手数は変わらない(初めからある経路は AD 1・
  消す操作と同じ手数)ので、探索はそのまま。
- チュートリアル: ステージ 2 に「経路は 4 つの欄に書く」を足し(宛先・マスクの書き方・ゲートウェイ・管理距離・IOS と同じ応答で断る)、
  「遊び方」を書き直した。ルールの枠の static route の行に `[管理距離]` とマスクの書き方を足した。
- **欄は候補のチップで埋める**(2026-11-12 ユーザ指摘「スマホだとキーボードが画面の半分を使い、盤面を見たいとき入力欄が見えず、逆もまた
  しかり」→ 3 案(候補のチップ・プルダウン・画面内の小さな数字キー)からチップを選択)。欄を押すと、帯の中にその欄の候補が並び、押すと入って
  次の欄へ進む。スマホ(`pointer: fine` でない端末)は欄を readonly にして OS のキーボードを出さない。PC は打っても選んでもよい。
  候補は盤面の値を**全部**並べる= 選ぶだけでは解けない: 宛先= 地図のネットワーク全部(LAN・リンク・Internet、ステージ 4 から 0.0.0.0)、
  マスク= 0.0.0.0・255.0.0.0・255.255.0.0・255.255.255.0・255.255.255.252・255.255.255.255、ゲートウェイ= 盤面のインターフェースの IP 全部
  (自分の IP・遠いルータ・ISP も)、管理距離= 1・5・10・200・250・255。宛先とマスクの組み合わせ違い(`10.2.1.0` と `255.255.0.0` など)は
  チップでも `%Inconsistent address and mask` になる。帯は 1 行目にコマンドの頭と「やめる」「足す」、2x2 の欄、候補の順(高さはスマホで
  約 240px)。開くと盤面が帯の上に収まるようにずらす。Android の Chrome で固定の帯がキーボードの裏に隠れる件は、viewport に
  `interactive-widget=resizes-content` を足した(PC 以外でキーボードを出さないので、今は念のため)。
- 試験: route_path の selftest に受け付け/断りの 9 件、uitest に穴埋めの 30 件近く(補助・各エラー・^ の位置・ルータの切り替え・AD 255・
  AD の置き換え・Lv 3 の補助なし)を足した。

## 15. 経路集約は「計算を目で見て学べ、選べる」形に(2026-11-12 ユーザ構想・未着手)

ユーザ:「将来的に経路集約も題材に考えている。ただ集約の計算は、慣れていない人でもある程度視覚的に分かりやすく学べ、かつ選べるようにしたい」。
§6 のステージ 6「集約と巻き添え」で扱う(作る時に見本を見せて決める。下は案の段階)。

- **要件**: ① 集約の計算(共通のビット → プレフィックス長 → マスク)が、2 進に慣れていない人にも目で追える。② 書けなくても**選んで**
  集約を作れる(§14 の穴埋めと同じ段階づけ= 前半のレベルは選ぶと欄に入る補助、後半は自分で書く)。③ 遊ぶ画面は詰める
  ([[feedback-game-compact]]。計算の図は押すと開く・説明はチュートリアルで丁寧に)。
- **案 A ビットの帯**: まとめたい LAN を選ぶと、アドレスを縦に並べ、変わるオクテットだけ 2 進に開く(ほかは 10 進のまま)。左から同じ
  ビットを色で塗り、違い始める所に縦線 → 「ここまでが共通 = /22」→ マスク `255.255.252.0` が並んで出る。
- **案 B アドレスの升目**: 例 `10.1.0.0`〜`10.1.7.255` を /24 の升で並べ、/23・/22・/21 の枠を重ねる。枠を選ぶと、入る LAN が地図で光り、
  **巻き添え**(使っていない升・別の拠点の LAN)は赤で見える。枠は 2 の累乗の境目にしか置けない =「集約は境目にそろう」を目で見る。
  境目にそろわない書き方は IOS が `%Inconsistent address and mask` で断る(PoC input_form #1)ことともつながる。
- **選ぶ形**: 候補を少数のカードで並べる(最小の集約・1 段大きい集約・境目にそろわない案 など)。選ぶと宛先とマスクの欄に入り、
  升目で巻き添えが見える。後半のレベルは補助なしで書く。
- **送ってみる時**: 経路表の小窓で集約の行に当たったとき、宛先がその行のどの升に入ったかを示す(ロンゲストマッチとのつながり)。
- **作る時の宿題**: 最少手数の探索に長さ違い・集約の候補を足す(§14 の `len` の宿題と同じ)。集約先に無い宛先のループと Null0 は
  ステージ 8(PoC #3d・#6b)とつなぐ。

## 16. Internet の宛先は 3 つ・1 つずつ書くと手数の上限を超える(2026-11-12 ユーザ提案)

ユーザ:「インターネットのアドレスが 1 つだけだと、インターネット宛てはデフォルト ルート、という説得力に欠ける。3 つぐらいあって、全部書くと
手数が増えてノルマを達成できない形にすると、自分でデフォルト ルートを選んで書く理解と達成が得られる」→ そのとおりに変えた。

- **雲の中に 3 台**: WEB `198.51.100.10`(198.51.100.0/24)・DNS `192.0.2.53`(192.0.2.0/24)・MAIL `203.0.113.25`(203.0.113.0/24)。
  文書用のアドレス 3 つ(RFC 5737)。ISP は LAN 側のインターフェースを 3 つ持つ(画面の雲は 1 つ・線も 1 本)。203.0.113.0/24 を宛先に
  使うので、ISP とのリンクは 100.64.0.0/30・100.64.0.4/30(RFC 6598 の共有アドレス= ISP とお客さまの間で使う範囲)に移した。
- **3 つとも書ける宛先**: 前の「Internet は書けない(デフォルトで指す)」というゲームの決まりは外した。宛先の候補にも 3 つが並ぶ。
- **上限の決め方**(`route_path._cap_nodef`): デフォルト ルートを足さずに解く最少手数(= Internet を 1 つずつ書く解)を探索し、
  上限 = min(最少 + 余裕, デフォルトなしの最少 − 1)。デフォルトなしでも最少で解ける盤面は使わない。例: ステージ 4 Lv 1= 最少 1・
  デフォルトなし 3 → 上限 2(1 つずつ書くと 3 本目で「手数の上限」)。上限が最少と同じになる盤面は ★★ の表示を出さない。
- **お題**: Internet の 3 台へ届ける(内部は 3 本・`grp: "inet"`)＋ WEB からの戻り(戻りの道はどの台からでも同じなので 1 本)。
  画面ではまとめて 1 行「PC1 から WEB・DNS・MAIL へ届ける」、色も 1 つ、✓ は 3 台とも届いたとき。結果は同じ落ち方を宛先ごとにまとめる
  (「WEB・DNS・MAIL: R1 で落ちる(経路なし)」)。
- チュートリアル(ステージ 4 の 1 枚目)を「3 台は別々のネットワーク → 1 つずつ書くと手数の上限を超える → 0.0.0.0/0 の 1 行で 3 台すべて」に
  書き直し、例の盤面も 3 台へ送る形にした。
- 生成は 1 盤面 2 秒以内(探索を 2 回= デフォルトあり・なし)。selftest 320 盤面・autotest・uitest(3 本目で上限になることを含む)NG 0。

## 17. ステージ 5 ロンゲストマッチ(2026-11-13 実装)

ユーザ:「ステージ 5 ロンゲストマッチから進めたい」(確かめた 4 点は返事がなかったので推奨どおり: 範囲の光りは全レベル・Lv の流れは案のとおり)。

- **盤面**: ひし形 `dia`(上 R1= 拠点 1 の PC1・左右 R2/R3・下 R4= 拠点 4 に LAN 2 つ `10.4.1.0/24`・`10.4.2.0/24`)。Lv 5 は
  R2–R3 を足した `diax`。拠点の囲みと `10.n.0.0/16` はステージ 5 から(`SHOW_FROM["sites"]`)。
- **Lv の流れ**(x= 🔒 が向く側・y= お題の道。左右は乱数):

  | Lv | 盤面 | 最少 |
  |---|---|---|
  | 1 | R1 に 🔒 `10.4.0.0/16 → x`。SRV1 を R1 → y → R4 で(往復) | 1(/24 を足す) |
  | 2 | R1 に 🔒 `10.4.1.0/24 → x`。SRV1 は y・同じ LAN の SRV2 は x のまま(`via`) | 1(SRV1 の /32。同じ /24 は等コストで分かれる) |
  | 3 | R1 に 🔒 /16 と、残っていた `PC1/32 → x`(connected の /24 に勝ち、戻りがループ)。戻りは同じ道 | 2(/32 を消す＋/24) |
  | 4 | 🔒 /16 ＋乱数の経路(長さいろいろ・0.12)。SRV1 は y・SRV2 は x の道・往復 | 2〜4 |
  | 5 | `diax`・🔒 2 本(2 本目は真ん中か R4 に /24 か /32)＋乱数(0.15)。道は 3〜4 台・戻りは同じ道 | 3〜5 |

  Lv 4・5 は、最少の解が 🔒 の行の中の一部(もっと長い行)を足す盤面だけを採る(`_uses_override`)。
- **書ける宛先**(ゲームの決まり・`route_path.dst_rule`/画面の `dstRule`): 長さは `LENS` = /0・/8・/16・/24・/32(オクテットの
  切れ目)だけ、かつ中に端末がいる範囲(拠点・LAN・端末 1 台。0.0.0.0/0 は別)。ほかの長さは集約のステージ 6 で開く。
  - 長さを絞る理由: この中なら「宛先 IP x を含む長さ L の宛先」は x を L で切ったものしかないので、最少手数の探索は「お題の宛先 IP × 5 つの
    長さ」で尽くせる。
  - 端末のいない範囲を除く理由: リンクの IP の /32(端末を含まない)を足すと、その隣を next-hop にした経路の解決をまとめて横取りでき、
    1 行で何本もの経路の向きを変えられる(探索の外の手)。端末を含む範囲は /30 の connected より短いか端末の /32 なので、next-hop の解決は
    変わらない。
  - 断りの文は IOS の文ではなくゲームの決まりとして出す(`lenRule`・`noHostIn`)。
- **探索**(`_add_dsts`): 足す宛先の候補= お題の宛先 IP を LENS で切ったもの。同じ宛先 IP の組を覆い、そのルータに初めからある行
  (connected と static)に対する長さの順位も同じものは判断が必ず同じなので、代表 1 つだけを試す(ほかに足す行は、覆う組が違えば覆う範囲で
  長さの大小が決まり、間に入らない)。代表と試す順は /24 → /16 → /32 → /0 → /8(答えの一例に見慣れた形が出る)。同じ宛先・同じ AD の行を
  2 本足す組は等コストになるだけ(お題の判断= 次は 1 台に合わない)なので試さない。selftest で、間引かない候補で解き直して最少手数が同じこと、
  2 手までの盤面は総当たりと同じことを確かめる。計算器の `addr`・`net` に覚え(lru_cache)を付けた。生成は既定の盤面で Lv 5 が約 1.8 秒
  (ほかは 0.2 秒以内・サーバが覚えるので遅いのは再起動後の初回だけ)。
- **画面**: 宛先の候補に拠点(`10.n.0.0`)と端末の IP を足す。**範囲の光り**= 欄の宛先とマスクが形になった時点で、覆う拠点の囲み・LAN の札・
  リンクの線・端末が黄色く光る。経路表の宛先の札を押しても光る(もう一度押すと消える)。経路表の小窓の 🔒 の行に印。ルールの枠に拠点・
  ロンゲストマッチ・同じ長さの 2 本・/32 と connected・🔒・書ける宛先の 6 行。
- **チュートリアル**(4 枚): 長い行が勝つ(`ex_dia_lpm`)・🔒 と同じ長さの行は分かれる → /32(`ex_dia_ecmp`)・/32 は自分の LAN にも勝つ
  (`ex_dia_conn`)・このステージで書ける宛先。事実の裏どり= PoC 1b(長さが AD より先)・1d(/32 は connected の /24 に勝つ)・ECMP の照合。
- 試験: selftest(ステージ 5 の宛先の決まり 8 件・同じ /24 で分かれる・/32 で開通・/32 が connected に勝つ・間引かない候補との照合)、
  uitest(🔒・光り(リンクだけ/拠点)・候補・/25・/30・端末のいない範囲・小窓の 🔒・分かれる → /32 で開通・Lv 3 の /32 を消す)。
