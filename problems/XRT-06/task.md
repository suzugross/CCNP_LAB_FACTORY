# XR Track 06 — 高可用性

このラボは、XR トラックの単元 **M7 高可用性** の実践編です。先に単元のページ「M7 — 高可用性」を読んでから、
ここで課題に順番に取り組みます。各課題は前の課題の上に積み上げます。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01 と RT02 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。IS-IS が変更をフラッディングしてルートを再計算するには数秒かかります。
  壊れた隣接がタイムアウトするまでには最大 30 秒かかります。
- 一部の Check は、一時的に障害を起こしてから元に戻します。M7-2 の Check は RT01 のポートを 1 つシャットダウンし、
  M7-4 の Check は 1 本のリンクのパケットを廃棄し、M7-5 の Check は XR01 のプロセスを再起動します。このような Check には
  1〜2 分かかります。実行中は設定を変更しないでください。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は **IOS XRv 9000** 26.1.1(IOS XR ルータの仮想版)で動作しています。ハードウェアのルータと同じようにトラフィックを
  転送し、BFD も動作します。これまでのラボで使った IOS XRd は BFD を動作させません。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング |
|---|---|---|---|
| BUNDLE | Bundle-Ether1 = GigabitEthernet0/0/0/0 と GigabitEthernet0/0/0/1 | RT01 Port-channel1 = GigabitEthernet1 と GigabitEthernet2 | 10.0.1.0/24(XR01 .1、RT01 .11) |
| PRIMARY | GigabitEthernet0/0/0/2 | RT02 Ethernet0/0(スイッチ SW01 経由) | 10.0.2.0/24(XR01 .1、RT02 .12) |
| BACKUP | — | RT01 GigabitEthernet3 ─ RT02 Ethernet0/2 | 10.0.12.0/24(RT01 .11、RT02 .12) |

| ルータ | プラットフォーム | Loopback0 | その他のネットワーク |
|---|---|---|---|
| XR01 | IOS XRv 9000 26.1.1 | 10.255.0.1/32 | プラットフォーム 10.30.0.0/16(Loopback10、BGP にのみ載せている) |
| RT01 | Catalyst 8000V、IOS XE 17.15 | 10.255.0.11/32 | ユーザ 10.10.0.0/16 |
| RT02 | IOS XE 17.15 | 10.255.0.12/32 | サービス 10.20.0.0/16 |

- 3 台のルータは、IPv4 で IS-IS インスタンス `CORE` を実行しています。エリア 49.0001、レベル 2 のみ、ワイド メトリック、
  ポイントツーポイントの回線です。BACKUP のメトリックは両方向とも 1000 で、その他のリンクは既定のメトリックです。
- XR01 と RT02 は、ループバック間で AS 65000 の iBGP を実行しています。XR01 は 10.30.0.0/16 を、RT02 は 10.20.0.0/16 を
  アドバタイズしています。
- RT01 は、Port-channel1 の両方のメンバーで LACP をアクティブ モードで実行しています。
- RT02 は Ethernet0/0 で BFD(100 ms、乗数 3)を設定し、そこで IS-IS に対して有効にしています。RT02 では BGP の
  グレースフル リスタートが有効になっています。

## M7 — 高可用性

### 課題 M7-1

BUNDLE リンクは、先週、変更 CHG-0917 で構築されました。XR01 では Bundle-Ether1 がアップと表示されますが、XR01 と RT01 は
このリンクを介してトラフィックを交換できず、IS-IS はこのリンクで隣接を確立していません。RT01 の設定は正しいものとします。

- Bundle-Ether1 が XR01 と RT01 の間のトラフィックを運ぶようにしてください。両方のメンバーで LACP を動作させ、両方のメンバーを
  使用すること。
- Bundle-Ether1 で RT01 との IS-IS の隣接を確立してください。
- 1500 バイトの IP パケットが、両方向ともフラグメンテーションされずにバンドルを通過すること。

### 課題 M7-2

運用チームは、バンドルについて 2 つのルールを定めました。

- Bundle-Ether1 は、1 つのメンバーだけでトラフィックを運んではなりません。使用中のメンバーが 2 つ未満になった場合、
  トラフィックはバックアップ パスを通ること。
- 動作しなくなったメンバーは、そのポートがアップのままであっても、5 秒以内にバンドルから外れること。Check は RT01 の
  GigabitEthernet2 を数秒間シャットダウンし(XR01 はこれをリンク障害として認識しません)、その後元に戻します。

### 課題 M7-3

バンドルが動作するようになった今も、RT01 のユーザと RT02 のサービスの間のトラフィックは XR01 を通らず、バックアップ リンクを
通っているとユーザから報告がありました。XR01 では 2 週間前に、変更 CHG-0903 でメンテナンスが行われています。

- RT01 と RT02 の間のトラフィックが、再び XR01 を通るパスを使用するようにしてください。
- そのメンテナンスで設けた保護を 1 つ残してください。XR01 が起動するたびに、その BGP が収束するまで、他のルータが XR01 を
  経由して通過トラフィックを送らないこと。

### 課題 M7-4

PRIMARY リンクはスイッチを経由しています。遠端側で障害が発生しても XR01 のポートはアップのままで、RT02 がいなくなったことに
IS-IS が気づくまでトラフィックが失われます。

- 両端のポートがアップのままプライマリ パスに障害が発生した場合、RT01 と RT02 の間のトラフィックは 1 秒以内にバックアップ パスへ
  移ること。RT02 ではそのための準備ができています。
- Check は、SW01 と RT02 の間のリンクのすべてのパケットをしばらく廃棄し、RT01 から RT02 のサービス ネットワークへの ping が
  いくつ失われるかを数えます。

### 課題 M7-5

XR01 には、ルーティング プロセスを再起動するソフトウェア パッチが適用される予定です。サービスの責任者は次の条件を定めました。

- XR01 の IS-IS プロセスが再起動しても、RT01 と RT02 から見て、どの IS-IS の隣接もダウンしないこと。
- XR01 の BGP プロセスが再起動しても、RT02 は XR01 から学習したルートを保持し続けること。
- Check は、XR01 で 2 つのプロセスをそれぞれ 1 回再起動します。
