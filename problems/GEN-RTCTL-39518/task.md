# 問題 GEN-RTCTL-39518 : 選択的経路制御の実装（難易度4）

## シナリオ

あなたは、ある企業のネットワーク・エンジニアです。図に示されているところの
ネットワークは、すでに基本的なコンフィギュレーションが完了しており、EIGRP AS 100
および OSPF プロセス 1 の隣接関係は、確立されています。再配送は、まだ設定されて
いません。あなたのタスクは、以下のタスクを、順番に完了することです。
いくつかのタスクには、使用できる手段に関する制約が、含まれています。

```
        RT04 ── 拠点網(Loopback 群)
        /            \
     RT02            RT03        EIGRP AS 100
        \            /
         RT01 ─────── RT05       OSPF 1 Area 0(RT05 の Loopback 群)
```

## 構成（初期状態で投入済み・変更不可）

| リンク | ネットワーク | 備考 |
|---|---|---|
| RT01 - RT02 | 10.1.12.0/30 | RT01 側 = Ethernet0/0（.1） |
| RT01 - RT03 | 10.1.13.0/30 | RT01 側 = Ethernet0/1（.1） |
| RT01 - RT05 | 10.1.15.0/30 | RT01 側 = Ethernet0/2（.1） |
| RT02 - RT04 | 10.1.24.0/30 | |
| RT03 - RT04 | 10.1.34.0/30 | |

RT04 が広告しているルート（EIGRP）:

- 172.26.96.0/24、172.26.97.0/24、172.26.98.0/24、172.26.99.0/24、172.26.164.0/24
- 10.4.20.0/24、10.4.24.0/24、10.4.28.0/24
- 192.168.67.0/24、192.168.31.0/24

RT05 が広告しているルート（OSPF）:

- 10.43.7.0/24、10.43.15.0/24、10.43.23.0/24、172.25.100.0/24

## タスク

**すべての作業は、RT01 の上で行われる必要があります。** 他のデバイスの構成を
変更してはいけません（採点で検出されます）。

### Task 1

RT01 が RT02 から学習するルートから、192.168.67.0/24 と 192.168.31.0/24 を除外してください。RT03 から学習されるルート、および、除外の対象ではないところのルートに、影響を与えてはいけません。

**制約**: この要件は、**FILTER-CORE-IN** という名前の標準アクセス・リストを使用した distribute-list で、実現される必要があります。アクセス・リストに、**deny エントリを含めてはいけません**。

### Task 2

RT05 のルーティング・テーブルに、172.26.96.0/24、172.26.97.0/24、172.26.98.0/24、172.26.99.0/24 の 4 つのルートだけが、外部ルートとして現れるようにしてください。再配送の設定も、あなたが行います。

**制約**: フィルタリングには、**1 行の prefix-list**（名前: **PL-BRANCH24**）を使用すること。route-map（名前: **RM-REDIST-OUT**）を使用できるのは、RT01 のみです。

### Task 3

OSPF ドメインのルートのうち、**10.43.7.0/24 と 10.43.15.0/24 だけ**を、EIGRP ドメインへ再配送してください。シード・メトリックには **50000 200 255 1 1500** を使用します。

**制約**: このフィルタリングは、**route-map**（名前: **RM-OSPF-IMPORT**・ACL **76** を参照）で実現される必要があります。distribute-list を使用してはいけません。

### Task 4

追加の要件が、判明しました。**10.43.23.0/24 も**、EIGRP ドメインへ再配送される必要があります。

**制約**: ACL **76** の、既存のエントリを削除・再作成せずに、実現してください。

### Task 5

RT04 から、送信元を **172.26.96.1** として、**10.43.7.1** への ping が成功することを、確認してください。

## 注意

- 設定の変更が、ルーティング・テーブルに反映されるまでに、**最大で 1〜2 分**を
  要することがあります（clear コマンドは、必要とされません）。
- データ・プレーン（インターフェイスの IP アドレス / network 文）を、変更しては
  いけません。
