# M4 — 実践(2 周目)

ラボ **XRT-05** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01、RT02、RT03 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。IS-IS が変更をフラッディングしてルートを再計算するには数秒かかります。
  壊れた隣接がタイムアウトするまでには最大 30 秒かかります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は **IOS XRd**(IOS XR のコンテナ版)で動作しています。この単元の範囲では IOS XRv 9000 と同じように動作します。
  自身を通過する ping は転送しますが、traceroute と TCP セッションは転送しません。確認には `show` コマンドと ping を使ってください。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング |
|---|---|---|---|
| ACCESS | GigabitEthernet0/0/0/0 | RT01 Ethernet0/0 | 10.0.11.0/24、2001:db8:11::/64(XR01 .1、RT01 .2) |
| CORE-A | GigabitEthernet0/0/0/1 | RT02 Ethernet0/0 | 10.0.12.0/24、2001:db8:12::/64(XR01 .1、RT02 .2) |
| CORE-B | GigabitEthernet0/0/0/2 | RT03 Ethernet0/0 | 10.0.13.0/24、2001:db8:13::/64(XR01 .1、RT03 .3) |
| SVC-LAN | GigabitEthernet0/0/0/3 | RT02 Ethernet0/2、RT03 Ethernet0/2(1 つの共有セグメント) | 10.0.100.0/24、2001:db8:100::/64(XR01 .1、RT02 .2、RT03 .3) |
| — | — | RT02 Ethernet0/1 ─ RT03 Ethernet0/1 | 10.0.23.0/24、2001:db8:23::/64(RT02 .2、RT03 .3) |

| ルータ | Loopback0 | エリア | レベル | IS-IS に入っているその他のネットワーク |
|---|---|---|---|---|
| XR01 | 10.255.0.1/32、2001:db8:255::1/128 | 49.0001 | 1 と 2 | — |
| RT01 | 10.255.0.11/32、2001:db8:255::11/128 | 49.0001、49.0010 | 1 のみ | アクセス LAN 10.11.1.0/24 〜 10.11.4.0/24、2001:db8:1011:1::/64 〜 2001:db8:1011:4::/64 |
| RT02 | 10.255.0.2/32、2001:db8:255::2/128 | 49.0002 | 2 のみ | サービス 10.20.0.0/16、2001:db8:1020::/64 |
| RT03 | 10.255.0.3/32、2001:db8:255::3/128 | 49.0003 | 2 のみ | サービス 10.30.0.0/16、2001:db8:1030::/64 |

- XR01 は課題 M4-1 から M4-4 を終えたときの設定になっています。IS-IS インスタンス `CORE`、レベル 2 はワイド メトリック、
  IPv6 は単一トポロジ、CORE-B はメトリック 1000、バックボーンのループバックはレベル 1 へ漏らしています。
- RT02 と RT03 は**バックボーン**を構成しています。ワイド メトリックで、バックアップ リンクのメトリックは両方向とも 1000 です。
  CORE-B はバックアップ リンクです。
- RT01 は旧型のアクセス ルータです。レベル 1 のみで動作し、メトリックは元の形式のままで、IS-IS の認証をサポートしていません。
- 3 台の IOS ルータは、IS-IS で IPv4 と IPv6 を単一トポロジで運んでいます。XR01 とのリンクおよび相互のリンクは
  ポイントツーポイント リンクです。SVC-LAN はブロードキャスト セグメントです。

## M4 — IS-IS(2 周目)

### 課題 M4-5
<p class="tolab"><a href="/_learn?id=XRT-05&amp;step=m4t5">ワークスペースで開く</a> — 読み物: <a href="42-m4-isis-deeper.html#s1-1">1.1 何を認証するか</a> · <a href="42-m4-isis-deeper.html#s1-2">1.2 IOS XR のキー チェーン</a> · <a href="42-m4-isis-deeper.html#s1-3">1.3 食い違いはどう見えるか</a> · <a href="42-m4-isis-deeper.html#s1-4">1.4 あるレベルを認証しないままにする</a></p>


昨夜、セキュリティ部門が作業指示 SEC-0412 に基づいて、バックボーンで IS-IS の認証を有効にしました。作業は RT02 と
RT03 を対象としており、XR01 は漏れていました。今朝、XR01 はバックボーンを失い、RT01 は自身のエリアの外に到達できなく
なっています。

| 作業指示 SEC-0412 | |
|---|---|
| 対象 | レベル 2 のすべての IS-IS パケット |
| キー チェーン | `ISIS-L2` |
| キー | ID 1、キー文字列 `Bb0ne-2026` |
| アルゴリズム | HMAC-MD5 |
| 有効期間 | 2026 年 1 月 1 日 00:00 から、期限なし |

- CORE-A と CORE-B で、XR01 を作業指示 SEC-0412 に合わせてください。SVC-LAN は課題 M4-6 で扱います。
- エリア 49.0001 とバックボーンのあいだで、IPv4 と IPv6 のルートの交換を双方向で回復してください。
- レベル 1 は認証しないままにします。RT01 が自身のプレフィックスに加える変更は、すべて XR01 とバックボーンに
  届き続ける必要があります。

### 課題 M4-6
<p class="tolab"><a href="/_learn?id=XRT-05&amp;step=m4t6">ワークスペースで開く</a> — 読み物: <a href="42-m4-isis-deeper.html#s2-1">2.1 擬似ノード</a> · <a href="42-m4-isis-deeper.html#s2-2">2.2 選出</a> · <a href="42-m4-isis-deeper.html#s2-3">2.3 ポイントツーポイントとブロードキャスト</a></p>


サービス基盤用の共有セグメント SVC-LAN が XR01 に配線されました。RT02 と RT03 はすでにそこで IS-IS を実行しています。

- XR01 は SVC-LAN で IPv4 と IPv6 の IS-IS を実行し、作業指示 SEC-0412 に従って、そこで RT02 および RT03 と
  レベル 2 の隣接を確立する必要があります。
- SVC-LAN はレベル 2 のみを運びます。XR01 はそこでレベル 1 のハローを送信してはなりません。
- XR01 は SVC-LAN の指定 IS である必要があり、RT02 または RT03 が再起動したときもその役割を保つ必要があります。
  RT02 と RT03 は変更しません。

### 課題 M4-7
<p class="tolab"><a href="/_learn?id=XRT-05&amp;step=m4t7">ワークスペースで開く</a> — 読み物: <a href="42-m4-isis-deeper.html#s3-1">3.1 どこで、どのように</a> · <a href="42-m4-isis-deeper.html#s3-2">3.2 何を失うか</a></p>


バックボーンのチームから、エリア 49.0001 が広告するプレフィックスを減らすよう依頼がありました。

- バックボーンは、RT01 のアクセス LAN を 1 つの IPv4 ルート 10.11.0.0/16 と 1 つの IPv6 ルート 2001:db8:1011::/48 として
  受け取る必要があり、個々のアクセス LAN のプレフィックスを受け取ってはなりません。
- エリア 49.0001 の内部では、すべてのプレフィックスが個別のルートを保ちます。RT01 のループバックは、バックボーンでも
  個別のルートを保ちます。

### 課題 M4-8
<p class="tolab"><a href="/_learn?id=XRT-05&amp;step=m4t8">ワークスペースで開く</a> — 読み物: <a href="42-m4-isis-deeper.html#s4-2">4.2 エリアの番号の付け替え</a> · <a href="42-m4-isis-deeper.html#s4-1">4.1 複数の NET</a></p>


エリア 49.0001 は 49.0010 に番号を付け替えている途中です。RT01 にはすでに新しいエリア アドレスが 2 つ目の NET として
設定されており、作業の終わりまで古いものも保持します。

- XR01 をエリア 49.0010 に移し、XR01 からエリア 49.0001 を削除してください。XR01 はシステム ID を保ちます。
- この作業のあいだ、XR01 の隣接は 1 つもダウンしてはなりません。RT01 との隣接も、バックボーンとの隣接も同様です。
- Check は、新しいエリアが設定された時点からの XR01 の隣接ログを読みます。隣接がダウンした場合は、49.0001 を
  XR01 の唯一のエリアに戻してから、移行をやり直してください。
