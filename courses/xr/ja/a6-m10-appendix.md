# M10 — 付録 フレキシブル アルゴリズム、SRv6、SID の衝突

この付録は、ブループリントの 3.3 のうち、ラボの課題に出てこないものを扱います。フレキシブル アルゴリズム(3.3.f)と
SRv6(3.3.g)、そして SID が重なったときにルータどうしで起きる食い違いです。フレキシブル アルゴリズムには、ラボ XRT-10 で
試せる「やってみる」があります。

## 1. フレキシブル アルゴリズム

### 1.1 何が嬉しいのか

IGP は、1 つのメトリックで、宛先ごとの最短パスを 1 本ずつ計算します。ネットワークの「地図」が 1 枚だけある状態です。
ところが、遅延の小さい道や、あるリンクを通らない道も、ふつうの道と並べて使いたいことがあります。

SR ポリシー(ページ「SR ポリシーと PCE」)でもできますが、宛先ごとにヘッドエンドが道を計算し、ラベルを何枚も重ねます。
**フレキシブル アルゴリズム**(Flex-Algo、RFC 9350)は、別の地図を全ルータに持たせます。たとえば「アルゴリズム 128 =
PRIMARY を通らない地図」と決めると、参加するルータはみな、ふつうの地図とは別に、その地図でも最短パスを計算します。

各ルータは、地図ごとに別の番号(プレフィックス SID)を配ります。ラボの RT02 では、ふつうの地図の番号は 12(ラベル
16012)、アルゴリズム 128 の地図の番号は 112(ラベル 16112)です。16112 は「RT02 へ、アルゴリズム 128 の地図で最短で
行け」という意味になります。ヘッドエンドはラベルを 1 枚付けるだけで、どの地図で運ぶかを選べます。途中のルータは、
自分でもその地図を持っているので、それに従って転送します。

### 1.2 仕組みと設定

アルゴリズムは 128〜255 の番号で、それぞれが独自の定義を持ちます。どのメトリック(IGP のメトリック、遅延、TE の
メトリック)を使い、どのリンクを除くか(アフィニティ、SRLG)です。1 台のルータが定義をアドバタイズし、他は参加して
それに従います。参加しないルータは、そのアルゴリズムの地図から除かれます(RFC 9350)。

IOS XR では、定義は `router isis` → `flex-algo 128` → `metric-type`、`affinity`、`advertise-definition` で、SID はループバック
の下の `prefix-sid algorithm 128 index <n>` です。遅延の定義にはリンクの遅延の値(`performance-measurement`)が要り、それの
無いリンクは除かれます。遅延を何もアドバタイズしないまま `metric-type delay` にすると、道はまったくできません。

ラボの IOS ルータは、プレフィックス SID のインデックス 111〜113 でアルゴリズム 128 に参加し、定義はアドバタイズしません。
XR02 は参加しません。フレキシブル アルゴリズムには MPLS から MPLS へのエントリしか組み込まれないので、IP のトラフィックは
SR ポリシー(たとえば `sid-algorithm 128` のオンデマンドのポリシー)を通してそこに入ります。

:::try
PRIMARY を避けるアルゴリズム 128 を定義します。課題 M10-5 の後に行います。

1. XR01 の `router isis CORE` の下に、`affinity-map RED bit-position 0`、`advertise-definition` と `affinity exclude-any RED` を
   持つ `flex-algo 128`、`interface GigabitEthernet0/0/0/0` の下に `affinity flex-algo RED`、`interface Loopback0` →
   `address-family ipv4 unicast` の下に `prefix-sid algorithm 128 index 101` を入れてコミットします。
2. XR01 で `show isis flex-algo 128`、`show isis segment-routing label table`、`show mpls forwarding labels 16012`、
   `show mpls forwarding labels 16112` を、RT01 で `show isis topology flex-algo 128` を実行します。
3. 足したものを外してコミットします。

結果の例: XR01 は定義をアドバタイズし(`Exclude Any Affinity Bit Positions: 0`)、アルゴリズム 128 のラベル
16101〜16113 を作りました。ラベル 16012(アルゴリズム 0)は GigabitEthernet0/0/0/0 から RT01 へ、ラベル 16112(アルゴリズム
128)は GigabitEthernet0/0/0/1 から RT03 へ出ました。RT01 は、アルゴリズム 128 でも PRIMARY を通って XR01 に到達したまま
でした(`show isis topology flex-algo 128`)。アフィニティはリンク全体ではなく、XR01 がアドバタイズする向きの属性だから
です。XR02 は `**` と表示され、アルゴリズムの外でした。
:::

## 2. SRv6

### 2.1 何が嬉しいのか

SRv6 は、道順を MPLS のラベルではなく IPv6 のアドレスで書きます。MPLS を動かさない、IPv6 だけのネットワークでも SR を
使えます。SID が IPv6 のアドレスなので、SRv6 を知らないルータも、ふつうの IPv6 のルーティングでパケットを通します。
VPN も SID の機能の 1 つ(End.DT4)として表せるので、LDP も MPLS も無しで L3VPN を作れます。

### 2.2 仕組みと設定

SRv6 の SID は、**ロケータ**(IGP がアドバタイズし、そのルータへ導くプレフィックス)の後に、ルータがパケットをどうするかを
示す**ファンクション**が続きます(End: 次の SID へ進む、End.X: この隣接から出る、End.DT4: IPv4 の VRF を引く)。SID の並びは
セグメント ルーティング ヘッダーで運ばれます。**マイクロ SID**(uSID、IOS XR の既定の形式は f3216)なら、いくつもの
16 ビットの SID が 1 つの宛先アドレスに詰められます。

IOS XR では、ロケータは `segment-routing` → `srv6` → `locators` → `locator <名前>` に `micro-segment behavior unode psp-usd` と
プレフィックスを持たせ、IS-IS が `address-family ipv6 unicast` → `segment-routing srv6` → `locator <名前>` でそれを
アドバタイズします。IOS XE のガイドは、SRv6 を 17.12.1a から ASR 1000 と Catalyst 8000 のプラットフォームでだけ対応として
います。IOL にはコマンドがありますが、その一覧にはなく、ラボのコアは IPv4 だけで動いています。SRv6 はこのページに
留めます。

## 3. 2 台のルータに 1 つの SID

プレフィックス SID はグローバルなので、2 台のルータが別々のプレフィックスに同じインデックスをアドバタイズしては
なりません。そうなると、どのルータも、そのラベルにどちらか一方を選ばなければなりません。RFC 8660 は既定の決め方を示して
います。まず管理距離の最も小さいもの、次にプレフィックスの値の最も小さいものです。ただしこの決め方は SHOULD で、実装は
別の決め方を使ってもよく、その場合 RFC 8660 は、1 つの IGP のエリアには同じ決め方のルータを置くよう運用者に求めています。

RT03 が自分のループバックにインデックス 12、つまり RT02 のインデックスをアドバタイズしたとします。XR01 は既定の
決め方に従い、16012 を小さいほうのプレフィックス 10.255.0.12 に残し、10.255.0.13 をラベルなしにして、
`Label Conflict: Prefix-SID label 16012 for algo SPF is used by 10.255.0.12/32 and 10.255.0.13/32` をログに出します。IOS ルータの
RT01 は逆を選び、16012 を 10.255.0.13 に対応させます。

XR01 は顧客 A のトラフィックを RT02 宛ての 16012 で RT01 に送り、RT01 はそれを RT03 のほうへ転送し、VPN は止まります。
1 台ずつ見れば、どのルータも筋の通った選び方をしています。しかし、ルータどうしで選び方が違うため、ネットワーク全体
では道がつながりません。
