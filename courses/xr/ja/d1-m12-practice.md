# M12 — 実践(1) 印をどこまで信じるか

ラボ **XRT-14** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01** と、課題 M12-5 では **RR1** もです。他のルータはすべて据え付けで、変更しないでください。
  確認のためにログインするのは構いません。CE1、CE2、CUST1、CUST2、INET は、顧客とインターネットのものです。
- 課題の中にはコマンド例を示しません。各課題は必要な動作を記述しています。読み物の各ページには設定例がありますが、
  課題の答えと同じ形のものは折りたたんであります。先に自分で解くなら、CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。確認は試験のトラフィックを流して数えるので、1 回に 1〜3 分かかります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は **IOS XRv 9000** 26.1.1 で動作しています。XR01 の QoS ポリシーのカウンタは、数十秒遅れて反映されます。
  RR1 は **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。RR1 はルート リフレクタで、転送パスの外にあります。
- CE1、CE2 の入力と、P1 の XR01 側の入力には、受け取ったパケットを DSCP または EXP ごとに数えるだけの QoS ポリシーが
  据え付けてあります(CE1・CE2 の `COUNT-DSCP`、P1 の `COUNT-EXP`)。確認がこれを使うので、変更しないでください。

- コアでは、すべてのルータで IS-IS インスタンス `CORE`(レベル 2)が動作し、CORE-1 と CORE-2 では LDP が動作しています。
  P1 は BGP を実行しません。RR1 が、XR01 と PE2 に IPv4 ユニキャストと VPNv4 のルートを反映します。インターネットの通信も、
  BGP のネクスト ホップ(PE の Loopback0)へ LDP のラベルで運ばれます。
- XR01、PE2、RR1 には、捨て先のアドレス 192.0.2.1/32 から Null0 へのスタティック ルートがあります。
- 顧客 A の CE は、宛先ごとに次の DSCP を付けて送信します(据え付け)。

  | 送信する CE | 宛先 | DSCP |
  |---|---|---|
  | CE1 | 音声網 10.46.2.0/24 | EF |
  | CE1 | 業務システム 10.21.2.0/24 | AF21 |
  | CE1 | LAN 10.100.2.0/24 | EF(サイト 1 の PC が付ける) |
  | CE2 | 音声網 10.46.1.0/24 | EF |
  | CE2 | 業務システム 10.21.1.0/24 | AF21 |
  | CE2 | LAN 10.100.1.0/24 | なし |

- PE2 は、CE2 から受け取った EF を EXP 5、AF21 を EXP 3、それ以外を EXP 0 で運びます(据え付け)。

顧客 A との契約では、EF を付けてよいのは音声網(10.46.0.0/16)宛ての通信だけです。サイト 1 の PC は、LAN 宛ての通信にも
EF を付けてしまいます。

- XR01 がサイト 1 から受け取る EF のうち、音声網宛てでないものは、DSCP 0 にして運んでください。それ以外の DSCP は
  変えないでください。
- コアでは、音声網宛ての EF を EXP 5、AF21 を EXP 3、それ以外を EXP 0 で運んでください。積むラベルは、どれも同じ EXP に
  します。
