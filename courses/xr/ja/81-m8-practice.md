# M8 — 実践

ラボ **XRT-07** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01、RT02、RT03 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。LDP がリンク上のネイバーの消失に気づくまでには最大 15 秒、
  IS-IS では最大 30 秒かかります。
- 2 つの Check は、一時的に障害を起こしてから元に戻します。M8-3 の Check は RT01 の 1 つのインターフェイスで LDP を無効にし、
  M8-4 の Check は 1 本のリンクのパケットを廃棄します。どちらも 1〜2 分かかります。実行中は設定を変更しないでください。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は、M4〜M6 のラボと同じく **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。ここにある他のルータと同じように、
  ラベル付きのトラフィックをスイッチングします。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング | IS-IS メトリック |
|---|---|---|---|---|
| PRIMARY | GigabitEthernet0/0/0/0 | RT01 Ethernet0/0 | 10.0.1.0/24(XR01 .1、RT01 .11) | 10 |
| BACKUP | GigabitEthernet0/0/0/1 | RT03 Ethernet0/0 | 10.0.3.0/24(XR01 .1、RT03 .13) | 100 |
| CORE-A | — | RT01 Ethernet0/1 ─ RT02 Ethernet0/0 | 10.0.12.0/24(RT01 .11、RT02 .12) | 10 |
| CORE-B | — | RT03 Ethernet0/1 ─ RT02 Ethernet0/1 | 10.0.23.0/24(RT03 .13、RT02 .12) | 100 |

| ルータ | 役割 | プラットフォーム | Loopback0 | その他のネットワーク |
|---|---|---|---|---|
| XR01 | プロバイダー エッジ | IOS XRd 26.1.1 | 10.255.0.1/32 | 顧客 A 10.30.0.0/16(Loopback100、BGP にのみ載せている)、管理用 10.255.255.1/32(Loopback1) |
| RT01 | コア | IOS XE 17.15 | 10.255.0.11/32 | — |
| RT02 | プロバイダー エッジ | IOS XE 17.15 | 10.255.0.12/32 | 顧客 A 10.20.0.0/16(Loopback100、BGP にのみ載せている) |
| RT03 | コア | IOS XE 17.15 | 10.255.0.13/32 | — |

- 4 台のルータは、IPv4 で IS-IS インスタンス `CORE` を実行しています。エリア 49.0001、レベル 2 のみ、ワイド メトリック、
  ポイントツーポイントの回線で、メトリックは表のとおり両方向とも同じです。
- XR01 と RT02 は、ループバック間で AS 65000 の iBGP を実行し、顧客 A のネットワークを運んでいます。コア ルータの RT01 と
  RT03 は BGP を実行していません。
- RT01、RT02、RT03 はコアの標準に従っています。すべてのコア リンクで LDP を実行し、LDP の識別情報は Loopback0 から取り、
  IS-IS を LDP と同期させています。RT01 はターゲット LDP の hello を受け入れます。RT03 はすべての LDP セッションに認証を
  要求し、ターゲット hello を受け入れません。

## M8 — MPLS と LDP

### 課題 M8-1
<p class="tolab"><a href="/_learn?id=XRT-07&amp;step=m8t1">ワークスペースで開く</a> — 読み物: <a href="80-m8-mpls-ldp.html#s1-1">1.1 BGP を持たないコア</a> · <a href="80-m8-mpls-ldp.html#s2-2">2.2 IOS XR の LDP</a> · <a href="80-m8-mpls-ldp.html#s2-3">2.3 LDP ID とトランスポート アドレス</a></p>


XR01 は、IOS ルータの PE-OLD に代わって顧客 A のプロバイダー エッジになりました。入れ替え以来、XR01 の配下と RT02 の配下にある
顧客 A のネットワークどうしが到達できません。先週、変更 CHG-1021 で PE-OLD の LDP の設定が XR01 にコピーされましたが、
その変更は最後まで終わっていません。

- 10.30.0.0/16 と 10.20.0.0/16 の間のトラフィックが、両方向ともコアを通って流れるようにしてください。コア ルータで BGP を
  実行しないでください。また、顧客 A のネットワークを IS-IS にアドバタイズしないでください。
- XR01 の両方のコア リンク、PRIMARY と BACKUP で LDP を実行してください。
- コアのすべてのルータと同じく、XR01 は LDP で自身を Loopback0 のアドレスだけで識別する必要があります。Loopback1 は管理システム
  用に予約されており、IS-IS にアドバタイズしてはいけません。
- RT03 には LDP セッションについて独自のルールがあります。RT03 とのセッションは課題 M8-2 で扱います。

### 課題 M8-2
<p class="tolab"><a href="/_learn?id=XRT-07&amp;step=m8t2">ワークスペースで開く</a> — 読み物: <a href="80-m8-mpls-ldp.html#s3-1">3.1 認証</a> · <a href="80-m8-mpls-ldp.html#s3-2">3.2 ラベルを受け取るプレフィックス</a></p>


コアのセキュリティ標準は、LDP について 2 つのルールを定めています。

- RT03 とのすべての LDP セッションは、キー `CoreLdp-2026` を使用する TCP MD5 で認証する必要があります。XR01 と RT03 の間の
  セッションを確立してください。RT01 は LDP に認証を使用しません。
- XR01 は、ホスト ルート(/32)にだけローカル ラベルを割り当てる必要があります。XR01 のルーティング テーブルにあるそれ以外の
  プレフィックスに、ローカル ラベルを割り当ててはいけません。

### 課題 M8-3
<p class="tolab"><a href="/_learn?id=XRT-07&amp;step=m8t3">ワークスペースで開く</a> — 読み物: <a href="80-m8-mpls-ldp.html#s4-1">4.1 ブラック ホール</a> · <a href="80-m8-mpls-ldp.html#s4-2">4.2 IOS XR の同期</a></p>


先月、IS-IS がアップのままコア リンクで LDP の障害が起き、顧客のトラフィックがコア ルータに送り込まれて廃棄されました。

- XR01 のコア リンクで IS-IS がアップしているのに LDP の準備ができていない間は、XR01 はそのリンクをトラフィックに使用しては
  いけません。これは両方のコア リンクに適用されます。
- そのようなリンクで LDP の準備が再びできたとき、XR01 はそのリンクを再び使用するまで 10 秒待つ必要があります。
- Check は、PRIMARY の RT01 側で LDP を約 1 分間無効にし、XR01 から顧客のトラフィックを送ってから、RT01 を元に戻します。

### 課題 M8-4
<p class="tolab"><a href="/_learn?id=XRT-07&amp;step=m8t4">ワークスペースで開く</a> — 読み物: <a href="80-m8-mpls-ldp.html#s5-1">5.1 ターゲット hello でセッションを保つ</a> · <a href="80-m8-mpls-ldp.html#s5-2">5.2 保護と同期を組み合わせる</a></p>


PRIMARY の下にあるトランスポート ネットワークで計画作業が行われ、リンクが何度か、そのたびに最大数分間切断されます。

- PRIMARY に障害が起きたとき、XR01 は RT01 との LDP セッションと RT01 から学習したラベルを保持し、PRIMARY が戻ったらすぐに
  使える状態にしておく必要があります。保持するのは、障害の後 10 分以内にしてください。
- RT03 は、ネイバーからのこの保護を受け入れません。XR01 は RT03 に対してこれを試みてはいけません。
- Check は、両方のポートをアップのまま PRIMARY のすべてのパケットを約 45 秒間廃棄し、その後リンクを元に戻します。

### 課題 M8-5
<p class="tolab"><a href="/_learn?id=XRT-07&amp;step=m8t5">ワークスペースで開く</a> — 読み物: <a href="80-m8-mpls-ldp.html#s6-1">6.1 LSP ping と traceroute</a> · <a href="80-m8-mpls-ldp.html#s6-2">6.2 explicit null と最後のホップ</a></p>


RT02 の運用チームは MPLS OAM でラベル スイッチド パスを検証しており、品質チームは、コアがラベルにマークしたトラフィック クラス
(MPLS EXP ビット)を XR01 まで届けることを求めています。

- RT02 から XR01 の Loopback0 への MPLS LSP ping と MPLS LSP traceroute が、XR01 の応答を得て成功する必要があります。XR01 の
  運用者も、RT02 の Loopback0 に対して同じテストを実行できる必要があります。
- XR01 自身のプレフィックス宛てのパケットは、ラベルを付けたまま XR01 に到着する必要があります。これにより XR01 は、コアで
  設定されたトラフィック クラスを読み取れます。XR01 の手前のルータがラベルを取り除いてはいけません。
