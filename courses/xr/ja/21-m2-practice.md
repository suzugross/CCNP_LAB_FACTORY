# M2 — 実践

ラボ **XRT-02** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Steps** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01、RT02、SRV01 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`describe`、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Steps** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取り、課題によっては
  課題が指定するアカウントで XR01 に実際にログインします。押す前にコンフィギュレーション モードを抜けてください。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- ラボの資格情報でログインします。管理アクセス(インターフェイス `MgmtEth0/RP0/CPU0/0`、VRF `MGMT`、SSH)は
  常に動作し続ける必要があります。確認はここを経由して XR01 に到達します。XR01 から締め出される可能性のある課題が
  複数あります。それを見越して作業してください。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング |
|---|---|---|---|
| LINK1 | GigabitEthernet0/0/0/0 | RT01 Ethernet0/0 | 10.0.12.0/24(XR01 .1、RT01 .2) |
| SERVERS | GigabitEthernet0/0/0/1 | SRV01 | 10.0.50.0/24(XR01 .1、SRV01 .10) |
| LINK2 | GigabitEthernet0/0/0/2 | RT01 Ethernet0/1 | 10.0.21.0/24(XR01 .1、RT01 .2) |
| LINK3 | GigabitEthernet0/0/0/3 | RT02 Ethernet0/0 | 10.0.23.0/24(XR01 .1、RT02 .2) |

- XR01 の Loopback0 は 1.1.1.1/32 です。RT01 の Loopback0 2.2.2.2/32 は NOC の端末の代わりです。
  RT01 の Loopback100 198.51.100.1/24 はゲスト ネットワークです。
- XR01 と RT01 は LINK1 上で OSPF プロセス 1、エリア 0 を実行しています。上記のアドレスは、LINK2 と LINK3 の先(M3 の題材)を除き、
  最初から到達可能です。
- IPv6: LINK1 は 2001:DB8:12::/64(XR01 ::1、RT01 ::2)です。XR01 の Loopback0 は 2001:DB8::1/128、RT01 の Loopback0 は 2001:DB8::2/128 です。
- LINK2 は RT01 へのバックアップ リンクです。RT01 は OSPF コスト 100 を設定しています。
- RT02 は OSPF エリア 1 の拠点ルータで、エリア 1 をスタブ エリアとして動作させています。LAN は 172.16.1.0/24、
  172.16.2.0/24、172.16.3.0/24(RT02 .1)で、Loopback0 は 3.3.3.3/32 です。
- SRV01 は TACACS+ サーバです。サーバの管理者によれば、XR01 は **1.1.1.1** のクライアントとして、
  キー `XRT02-Tac-Key` で登録されており、次のユーザを保持しています。

  | ユーザ | パスワード | サーバが与える権限 |
  |---|---|---|
  | `ops1` | `Ops1-Pass` | ネットワーク管理 |
  | `view1` | `View1-Pass` | 読み取り専用 |
  | ラボのアカウント | ラボのパスワード | フル アクセス |

## M2 — 管理プレーンの保護

### 課題 M2-1
<p class="tolab"><a href="/_learn?id=XRT-02&amp;step=m2t1">ワークスペースで開く</a> — 読み物: <a href="20-m2-management-plane.html#s1">1. 権限はタスク ID</a></p>


NOC 用に、パスワード `Noc1-Pass` を持つローカル アカウント `noc1` が必要です。

- `noc1` でログインしたオペレータが、ルーティング テーブル、OSPF ネイバー、インターフェイスを表示でき、
  ping を実行でき、インターフェイスのカウンタをクリアできるようにしてください。
- `noc1` がいかなる設定も変更できないようにしてください。
- `noc1` を定義済みのユーザ グループのメンバーにしないでください。必要なものは自分で構成してください。

### 課題 M2-2
<p class="tolab"><a href="/_learn?id=XRT-02&amp;step=m2t2">ワークスペースで開く</a> — 読み物: <a href="20-m2-management-plane.html#s2">2. 管理セッションを受け付ける場所</a></p>


XR01 で管理セッションを受け付けるインターフェイスを制限してください。

- SSH は管理インターフェイスでのみ受け付けるようにしてください。
- データ側からは、NOC の端末(2.2.2.2)だけが、LINK1 経由でのみ XR01 への Telnet セッションを開始できるようにしてください。
  データ側のその他の送信元が XR01 への Telnet または SSH セッションを開始できないようにしてください。

### 課題 M2-3
<p class="tolab"><a href="/_learn?id=XRT-02&amp;step=m2t3">ワークスペースで開く</a> — 読み物: <a href="20-m2-management-plane.html#s3">3. AAA サーバでのログイン</a></p>


XR01 へのログインを SRV01 で認証および認可してください。

- SRV01 にのみ存在するユーザがログインでき、サーバが与えるとおりの権限を正確に受け取るようにしてください。
  `ops1` は設定を変更でき、`view1` は変更できません。
- ローカル アカウントは、SRV01 に到達できない場合にのみ使用されるようにしてください。SRV01 が稼働している間は、
  XR01 にのみ存在するアカウントがログインできないようにしてください。
- コンソールは、SRV01 の稼働状態にかかわらず、常にローカル アカウントで認証するようにしてください。

### 課題 M2-4
<p class="tolab"><a href="/_learn?id=XRT-02&amp;step=m2t4">ワークスペースで開く</a> — 読み物: <a href="20-m2-management-plane.html#s4">4. ルータ宛てのトラフィック: LPTS</a></p>


XR01 が自身宛ての ICMP エコー要求を受け付けるレートを **毎秒 50 パケット** に制限してください。
SRV01 からの監視用の ping(毎秒 5 回)は引き続き成功する必要があります。その他のトラフィックに対する XR01 の処理は変更しないでください。

### 課題 M2-5
<p class="tolab"><a href="/_learn?id=XRT-02&amp;step=m2t5">ワークスペースで開く</a> — 読み物: <a href="20-m2-management-plane.html#s5">5. アクセス リスト</a></p>


ゲスト ネットワーク 198.51.100.0/24 が XR01 に到達できないようにしてください。トラフィックが XR01 に入る地点で破棄してください。
LINK1 上の OSPF 隣接関係と、LINK1 を通過するその他のすべてのトラフィックには影響を与えないでください。
