## M14 — マルチキャスト

### 課題 M14-5
<p class="tolab"><a href="/_learn?id=XRT-16&amp;step=m14t5">ワークスペースで開く</a> — 読み物: <a href="f4-m14-rp-ipv6-ts.html#s2-1">2.1 BSR: 2 つの選出</a> · <a href="f4-m14-rp-ipv6-ts.html#s2-3">2.3 スタティックと動的を並べたとき</a> · <a href="f4-m14-rp-ipv6-ts.html#s3-1">3.1 BSR</a></p>


プロバイダーは、テレビと超高精細のチャネルの RP を、すべてのルータに手で設定することをやめます。

- 239.16.0.0/15 に、ブートストラップ ルータ(BSR)の仕組みを使用してください。RP の候補は P1、PE3、PE4 で、それぞれ自分の
  Loopback0 を使い、どれも 239.16.0.0/15 だけを通知します。RP は P1 である必要があります。P1 が通知をやめたら PE3 が引き継ぎ、
  PE4 が RP になるのは P1 と PE3 の両方が通知をやめたときだけにしてください。
- BSR の候補は PE1 と P1 で、それぞれ自分の Loopback0 を使います。BSR は PE1 である必要があり、P1 が引き継ぐのは PE1 が
  止まったときだけです。
- すべてのルータが、239.16.0.0/15 の RP を BSR で学習する必要があります。RCV2 と RCV3 は、引き続きチャネルを受信できる
  必要があります。

### 課題 M14-6
<p class="tolab"><a href="/_learn?id=XRT-16&amp;step=m14t6">ワークスペースで開く</a> — 読み物: <a href="f4-m14-rp-ipv6-ts.html#s2-4">2.4 IPv6: PIMv6 と MLD</a> · <a href="f4-m14-rp-ipv6-ts.html#s2-5">2.5 切り分け: 受信者からツリーをたどる</a> · <a href="f4-m14-rp-ipv6-ts.html#s3-3">3.3 IPv6 マルチキャスト</a> · <a href="f4-m14-rp-ipv6-ts.html#s3-4">3.4 故障の見え方</a></p>


前任者は、IPv6 のマルチキャストを試行しました。FF0E::16:0/112 のチャネルを SRC1(2001:db8:100:1::1)から RCV2 と RCV3 へ
届けるもので、RP は P1(2001:db8:255::11)です。RP は、ヘッドエンドの LAN(2001:db8:100:1::/64)の送信元からの Register
メッセージだけを受け付けます。これまで何も届いていません。

- RCV2 と RCV3 が、FF0E::16:0/112 のチャネルを SRC1 から受信できる必要があります。
- RP の制限は維持してください。Register できるのは、ヘッドエンドの LAN の送信元だけです。
