# M4 — 実践

ラボ **XRT-04** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01、RT02、RT03 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。IS-IS が変更をフラッディングしてルートを再計算するには数秒かかります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は **IOS XRd**(IOS XR のコンテナ版)で動作しています。この単元の範囲では IOS XRv 9000 と同じように動作します。
  自身を通過する ping は転送しますが、traceroute と TCP セッションは転送しません。確認には `show` コマンドと ping を使ってください。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング |
|---|---|---|---|
| ACCESS | GigabitEthernet0/0/0/0 | RT01 Ethernet0/0 | 10.0.11.0/24、2001:db8:11::/64(XR01 .1、RT01 .2) |
| CORE-A | GigabitEthernet0/0/0/1 | RT02 Ethernet0/0 | 10.0.12.0/24、2001:db8:12::/64(XR01 .1、RT02 .2) |
| CORE-B | GigabitEthernet0/0/0/2 | RT03 Ethernet0/0 | 10.0.13.0/24、2001:db8:13::/64(XR01 .1、RT03 .3) |
| — | — | RT02 Ethernet0/1 ─ RT03 Ethernet0/1 | 10.0.23.0/24、2001:db8:23::/64(RT02 .2、RT03 .3) |

| ルータ | Loopback0 | エリア | レベル | IS-IS に入っているその他のネットワーク |
|---|---|---|---|---|
| XR01 | 10.255.0.1/32、2001:db8:255::1/128 | 49.0001 | 1 と 2 | — |
| RT01 | 10.255.0.11/32、2001:db8:255::11/128 | 49.0001 | 1 のみ | アクセス LAN 10.11.0.0/16、2001:db8:1011::/64 |
| RT02 | 10.255.0.2/32、2001:db8:255::2/128 | 49.0002 | 2 のみ | サービス 10.20.0.0/16、2001:db8:1020::/64 |
| RT03 | 10.255.0.3/32、2001:db8:255::3/128 | 49.0003 | 2 のみ | サービス 10.30.0.0/16、2001:db8:1030::/64 |

- **システム ID** は Loopback0 のアドレスから作ります。各オクテットを 3 桁で書き、12 桁を 4 桁ずつに区切ります。
  RT02(10.255.0.2)のシステム ID は `0102.5500.0002` です。
- RT02 と RT03 は**バックボーン**を構成しています。バックボーンは**ワイド メトリック**に移行済みです。
  その設計規則では、**バックアップ リンクのメトリックを両方向とも 1000** にします。CORE-B はバックアップ リンクです。
- RT01 は旧型のアクセス ルータです。レベル 1 のみで動作し、メトリックは元の形式のままです。
- 3 台の IOS ルータは、IOS の既定のまま IS-IS で IPv4 と IPv6 を運んでいます。リンクはすべて
  ポイントツーポイント リンクとして設定されています。

## M4 — IS-IS

### 課題 M4-1
<p class="tolab"><a href="/_learn?id=XRT-04&amp;step=m4t1">ワークスペースで開く</a> — 読み物: <a href="40-m4-isis.html#s9">9. IOS XR での IS-IS</a> · <a href="40-m4-isis.html#s2">2. アドレス: NET</a> · <a href="40-m4-isis.html#s3">3. レベルと隣接</a> · <a href="40-m4-isis.html#s4">4. ハロー、ポイントツーポイント リンク、DIS</a></p>


同僚が XR01 の IS-IS(インスタンス `CORE`)の設定を始めましたが、隣接が 1 つも確立しません。

- XR01 はエリア 49.0001 に属し、慣習に従ったシステム ID を持つ必要があります。
- XR01 は RT01 とレベル 1 の隣接を、RT02 および RT03 とレベル 2 の隣接を確立する必要があります。
- 各リンクで、XR01 はネイバーが動作しているレベルのハローだけを送信する必要があります。
- 3 本のリンクはすべてポイントツーポイント リンクです。これらのリンクでは指定 IS を選出しません。
- XR01 は、IOS ルータと同様に、Loopback0 と 3 本のリンクで IPv4 と IPv6 の IS-IS を実行する必要があります。

### 課題 M4-2
<p class="tolab"><a href="/_learn?id=XRT-04&amp;step=m4t2">ワークスペースで開く</a> — 読み物: <a href="40-m4-isis.html#s7">7. メトリック: ナローとワイド</a> · <a href="40-m4-isis.html#s6">6. レベルのあいだ: ATT ビットと経路の漏らし</a></p>


レベル 2 の隣接は確立しています。それでも XR01 はバックボーンへのルートを持たず、バックボーンもエリア 49.0001 への
ルートを持たず、RT01 は自身のエリアの外に到達できません。

- エリア 49.0001 とバックボーンのあいだで IPv4 ルートの交換を回復してください。RT01 は RT02 と RT03 の
  サービス ネットワークに到達できる必要があります。
- RT01 は変更しません。RT01 は自身のルートを保持する必要があります。
- CORE-B の XR01 側に、バックアップ リンクに関するバックボーンの設計規則を適用してください。CORE-A が稼働している
  あいだ、XR01 は RT02 を経由して RT03 に到達する必要があります。

### 課題 M4-3
<p class="tolab"><a href="/_learn?id=XRT-04&amp;step=m4t3">ワークスペースで開く</a> — 読み物: <a href="40-m4-isis.html#s8">8. IPv6: トポロジは 1 つか、複数か</a></p>


すべてのルータが IPv6 の IS-IS を実行していますが、IPv6 はまだ交換されていません。

- XR01 は、RT01、RT02、RT03 の IPv6 のループバックとネットワークへの IS-IS ルートを持つ必要があります。RT02 と RT03 は、
  XR01 と RT01 の IPv6 のループバック、および RT01 のアクセス LAN へのルートを持つ必要があります。RT01 は IPv6 で
  サービス ネットワークに到達できる必要があります。
- IPv6 のトラフィックは、リンクのサブネットを含むすべての宛先に対して、IPv4 のトラフィックと同じ経路を通る必要が
  あります。CORE-B は IPv6 でもバックアップ リンクのままです。

### 課題 M4-4
<p class="tolab"><a href="/_learn?id=XRT-04&amp;step=m4t4">ワークスペースで開く</a> — 読み物: <a href="40-m4-isis.html#s10">10. ルート ポリシーで漏らす</a> · <a href="40-m4-isis.html#s6">6. レベルのあいだ: ATT ビットと経路の漏らし</a></p>


RT01 は MPLS のエッジ ルータになる予定です。各バックボーン ルータのループバックへの個別のルートが必要になり、
デフォルト ルートでは足りません。

- RT01 は、RT02 と RT03 の IPv4 と IPv6 のループバックへの IS-IS ルートを持つ必要があります。
- エリア 49.0001 の外部からのそれ以外のものを、RT01 のルーティング テーブルに追加してはなりません。RT01 は
  それ以外のすべてに、引き続きデフォルト ルートで到達します。
- ループバックは 10.255.0.0/24 と 2001:db8:255::/64 から割り当てます。新しいルータがバックボーンに加わったとき、
  XR01 を変更せずに、そのループバックが RT01 に届く必要があります。
