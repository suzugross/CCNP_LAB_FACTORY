# M8 — 実践(Unified MPLS)

ラボ **XRT-08** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XR01 だけ**です。RT01〜RT05 は据え付けで、変更しないでください。確認のためにログインするのは構いません。
- コマンド例は示しません。各課題は必要な動作を記述しています。CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XR のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。IS-IS と LDP は、変更の後に最大 30 秒かかります。
  RT02 と RT05 の間の iBGP セッションは、2 台が互いに到達できるようになってから上がるまでに最大 2 分かかることがあります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XR01 は、ラボ XRT-07 と同じく **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。ここにある他のルータと同じように、
  ラベル付きのトラフィックをスイッチングします。

- コアでは、XR01、RT01、RT02、RT03 の間で IPv4 の IS-IS インスタンス `CORE` が動作しています。エリア 49.0001、
  レベル 2 のみ、ワイド メトリック、ポイントツーポイントの回線です。LDP は、ラボ XRT-07 の標準どおりにすべてのコアのリンクで動作しています。
- 新しいアクセス網では、RT04 と RT05 の間で IPv4 の IS-IS インスタンス `ACCESS` が動作しています。エリア 49.0002、
  レベル 2 のみ、ワイド メトリック、ポイントツーポイントの回線、メトリック 10 です。LDP はそのリンクで動作し、
  LDP ID は Loopback0 から取ります。
- すべてのルータは AS 65000 にあります。RT01、RT03、RT04 は BGP を実行しません。
  - XR01 と RT02 は、ラボ XRT-07 と同じく、ループバック間で iBGP を実行しています。
  - RT02 と RT05 は、自分の Loopback0 と顧客 A のネットワークを、BGP IPv4 ラベル付きユニキャストで XR01 にアドバタイズします。
  - RT02 と RT05 は、ループバック間の直接の iBGP セッションで、顧客 A のルートを互いに交換します。
    このセッションでは自分のループバックを送りません。

## M8 — Unified MPLS

### 課題 M8-6
<p class="tolab"><a href="/_learn?id=XRT-08&amp;step=m8t6">ワークスペースで開く</a> — 読み物: <a href="84-m8-appendix.html#s2">2. 道の作り方は 3 通り</a> · <a href="82-m8-unified-mpls.html#s1-1">1.1 IGP を分ける理由</a> · <a href="82-m8-unified-mpls.html#s2-1">2.1 2 つの IS-IS インスタンス</a> · <a href="82-m8-unified-mpls.html#s2-2">2.2 境界自身のループバック</a></p>


新しいアクセス網(RT04 と RT05)が、ACCESS-1 で XR01 に接続されます。XR01 は、コアとアクセス網の境界になります。

- XR01 をアクセス網に参加させてください。ACCESS-1 でアクセス網の値の IS-IS インスタンス `ACCESS` を動作させ、
  ACCESS-1 で LDP を動作させます。
- コアとアクセス網は、互いのルートを学習してはなりません。XR01 の Loopback0 を除き、コアのルートをアクセス網に
  出してはならず、アクセス網のルートをコアに出してはなりません。
- アクセス網の運用チームは、MPLS OAM で境界を検証します。RT05 から XR01 の Loopback0 への MPLS LSP ping が成功する必要があります。

### 課題 M8-7
<p class="tolab"><a href="/_learn?id=XRT-08&amp;step=m8t7">ワークスペースで開く</a> — 読み物: <a href="84-m8-appendix.html#s5">5. 境界が PE に伝えること</a> · <a href="84-m8-appendix.html#s7">7. 境界の 2 つの仕事</a> · <a href="82-m8-unified-mpls.html#s3-1">3.1 アドレス ファミリー</a> · <a href="82-m8-unified-mpls.html#s3-2">3.2 ルート リフレクタでのネクスト ホップ セルフ</a> · <a href="82-m8-unified-mpls.html#s3-3">3.3 ラベルの割り当て</a> · <a href="82-m8-unified-mpls.html#s3-4">3.4 ラベルをたどる</a></p>


変更 CHG-1107 で、XR01 は RT02 と RT05 のルート リフレクタとして、プロバイダー エッジのループバックを BGP ラベル付き
ユニキャストでコアとアクセス網の間で運ぶことになっていました。変更は適用されましたが、RT02 と RT05 の間の iBGP セッションが
上がらず、顧客 A の新しいサイトは RT02 の背後のサイトに到達できません。

- RT02 と RT05 の間の iBGP セッションを上げ、10.50.0.0/16 と 10.20.0.0/16 の間のトラフィックを両方向に流してください。
- RT02 と RT05 は、XR01 を経由するラベル スイッチド パスで、互いの Loopback0 に到達する必要があります。XR01 は、
  自分をネクスト ホップにして、2 台のループバックを互いにアドバタイズする必要があります。
- 2 つの IS-IS インスタンスの間でルートを再配送しないでください。RT01、RT03、RT04 で BGP を実行しないでください。

### 課題 M8-8
<p class="tolab"><a href="/_learn?id=XRT-08&amp;step=m8t8">ワークスペースで開く</a> — 読み物: <a href="82-m8-unified-mpls.html#s4-1">4.1 プロバイダー エッジの間の顧客ルート</a> · <a href="82-m8-unified-mpls.html#s4-2">4.2 ループバックだけのラベル</a> · <a href="82-m8-unified-mpls.html#s5-1">5.1 BGP の FEC への LSP ping</a></p>


境界は顧客のルートを運んではなりません。顧客のルートはプロバイダー エッジが持つものです。

- XR01 が BGP のラベルを割り当てるのは、プロバイダー エッジのループバック(10.255.0.0/24 の /32 のルート)だけにしてください。
  XR01 の BGP テーブルにある他のルートには、BGP のラベルを割り当ててはなりません。
- XR01 が RT02 と RT05 にリフレクトするのは、それらのループバックだけにしてください。顧客 A のルートは、RT02 と RT05 の間で
  直接交換します。
- RT02 と RT05 の背後の顧客 A のサイトの間、および XR01 と RT02 の背後のサイトの間のトラフィックは、引き続き流れる必要があります。
