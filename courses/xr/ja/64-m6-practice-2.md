# M6 — 実践(2) 追加パスと PIC

ラボ **XRT-17** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **PE1**(IOS XRv 9000)、**PE2**、**PE3**、**P1**、**RR1**(IOS XRd)と、課題 M6-7、M6-8 の **X1**、**X2**(IOS XE)です。
- **CE1** は顧客のルータ、**X1**、**X2** は AS 65100 のルータ、**T** は AS 65100 の中の宛先です。課題で指示されたもの以外は
  変更しないでください。
- 課題の中にはコマンド例を示しません。各課題は必要な動作を記述しています。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。ルータの現在の状態を読み取り、必要な課題では試験の操作をします。
  押す前にコンフィギュレーション モードを抜けてください。試験の操作は次のとおりです。終わると元に戻します。
  - M6-6: P1 の PE2 向けのインタフェース(GigabitEthernet0/0/0/1)を約 40 秒シャットダウンし、CE1 から T へ 10 ms ごとに
    送ったパケットの途切れを測ります。1 回に 2 分ほどかかります。
  - M6-9: CE1 に経路を一時的に 3 本追加し、PE1 の動作を確かめたあと削除して、PE1 で CE1 とのセッションを再確立します。
  - M6-10: X1 から PE2 への 198.51.100.0/24 を、約 30 秒の間に 3 回取り下げて戻し、PE2 の動作を確かめたあと、PE2 の
    ダンプニングの状態を消去します。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- 各課題には **確かめ方** のボタンもあります。設定が入ったか → 流して数える → 届いた先を見る → 壊していないか、の順に
  確かめる手順の例です。いつ開いても構わず、記録されません。Check を押す前に、自分の手で確かめてみてください。
- **Tasks** タブの **最初からやり直す** は、ルータをラボの構築直後の状態へ戻します。
- PE1 は **IOS XRv 9000** 26.1.1、PE2、PE3、P1、RR1 は **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。
  CE1、X1、X2、T は IOS XE 17.15(IOL)です。

| T | AS 65100 の中の宛先(Loopback1 203.0.113.1/24) | IOS XE 17.15 | 10.100.255.3/32 |

- AS 65000 の 5 台は、IS-IS インスタンス `CORE`(レベル 2)を動作させています。コアのリンク(CORE-1〜3)では LDP も動作しています。
  P1 は BGP を動作させていません。
- PE1、PE2、PE3 は RR1 のクライアントで、Loopback0 の間で iBGP を確立しています(各 PE は next-hop-self)。PE1 と CE1、PE2 と X1、
  PE3 と X2 の間は eBGP です。eBGP のルート ポリシーはすべての経路を通します。PE2 は、X1 から学習した経路のローカル プリファレンスを
  200 に設定します。
- X1 と X2 は、AS 65100 の中で OSPF と iBGP を動作させ、203.0.113.0/24 を広告しています。T からのデフォルト ルートは X2 を
  優先します。

## M6 — BGP(追補)

### 課題 M6-5
<p class="tolab"><a href="/_learn?id=XRT-17&amp;step=m6t5">ワークスペースで開く</a> — 読み物: <a href="63-m6-add-path-pic.html#s2-1">2.1 RR は最良の 1 本しか反射しない</a> · <a href="63-m6-add-path-pic.html#s2-2">2.2 追加パス: パス ID と能力の交渉</a> · <a href="63-m6-add-path-pic.html#s2-3">2.3 何を送り、何を入れるか: selection の advertise と install</a> · <a href="63-m6-add-path-pic.html#s3-1">3.1 追加パスの設定例</a> · <a href="63-m6-add-path-pic.html#s3-3">3.3 出力の読み方</a></p>


プロバイダーは、AS 65100 への出口として PE2 を主、PE3 を予備として使用します。現在、PE3 の最良の経路は PE2 を経由する iBGP の
経路であるため、PE3 は X2 から学習した経路を広告しません。そのため、RR1 と PE1 は PE2 を経由する経路しか知りません。

- PE1 と RR1 が、203.0.113.0/24 について、PE2 を経由する最良の経路に加えて、PE3(X2)を経由する経路を予備の経路として学習する
  必要があります。
- PE3 は、BGP の追加パス(ADD-PATH)を使用して、この経路を RR1 へ送信してください。best-external は使用しないでください。
- PE2 を経由する経路は、引き続きすべてのルータで最良の経路である必要があります。

PE2 が停止したときに、CE1 から T への通信が途切れる時間を短くします。

- PE2 と P1 の間のリンクが停止したときに、CE1 から T(203.0.113.1)への通信の途切れが 1 秒未満である必要があります。
- PE1 は、予備の経路をあらかじめフォワーディング テーブルにインストールしておく必要があります。
