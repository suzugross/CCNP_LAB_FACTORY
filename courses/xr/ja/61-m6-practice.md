# M6 — 実践

ラボ **XRT-03** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Steps** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## トポロジ

| リンク | XR01 | 相手 | アドレッシング |
|---|---|---|---|
| ISP-A | GigabitEthernet0/0/0/0 | RT01 Ethernet0/0 | 10.0.11.0/24(XR01 .1、RT01 .2) |
| ISP-B | GigabitEthernet0/0/0/1 | RT02 Ethernet0/0 | 10.0.12.0/24(XR01 .1、RT02 .2) |
| CUSTOMER | GigabitEthernet0/0/0/2 | RT03 Ethernet0/0 | 10.0.13.0/24(XR01 .1、RT03 .2) |
| CORE | GigabitEthernet0/0/0/3 | RT04 Ethernet0/0 | 10.0.14.0/24(XR01 .1、RT04 .2) |

- XR01 は AS 65000 です。自身のプレフィックスは **203.0.113.0/24** です(Null0 へのスタティック ルートを
  `network` 文でアナウンスしています)。Loopback0 は 1.1.1.1/32 です。
- RT01 は上位プロバイダ ISP-A(AS 65101)、RT02 は上位プロバイダ ISP-B(AS 65102)です。
  どちらも XR01 にインターネットのルートの一式と、AS 65000 が望まないルートの一部を送ってきます。
- RT03 は顧客(AS 65201)です。**198.51.100.0/23** を割り当てられており、これを 1 つのプレフィックスとして、
  または /24 のプレフィックスとして、自身の AS のプリペンドの有無にかかわらずアナウンスできます。
- RT04 は AS 65000 の社内ルータです。XR01 と RT04 は、CORE 上と両者の Loopback0(XR01 1.1.1.1/32、RT04 4.4.4.4/32)で
  OSPF プロセス 1、エリア 0 を実行しています。RT04 は 2 つの社内 LAN、203.0.113.128/26 と 203.0.113.192/26 も OSPF に入れています。
  プロバイダと顧客のリンクは OSPF に入っていません。
- 3 つの外部の相手との eBGP セッションは XR01 に設定済みで、Established になっています。
  RT04 との iBGP セッションも XR01 に設定されていますが、これは M6 の対象で、それまでは確立しません。
- AS 65000 は顧客向けに次のコミュニティを公開しています。

  | コミュニティ | 意味 |
  |---|---|
  | `65000:1001` | このルートを ISP-A にアナウンスしない |
  | `65000:1002` | このルートを ISP-B にアナウンスしない |
  | `65000:101` | AS 65000 が付与: このルートは ISP-A から学習した |
  | `65000:102` | AS 65000 が付与: このルートは ISP-B から学習した |

## M6 — BGP

### 課題 M6-1
<p class="tolab"><a href="/_learn?id=XRT-03&amp;step=m6t1">ワークスペースで開く</a> — 読み物: <a href="60-m6-bgp.html#s2">2. ループバック間の iBGP</a></p>


XR01 と RT04 の間の iBGP セッションが確立しません。RT04 は、自身の Loopback0 から XR01 の Loopback0 とピアを張るよう設定されています。

- 2 つのループバックの間でセッションが確立するようにしてください。
- RT04 は、プロバイダと顧客のルートを自身のルーティング テーブルにインストールする必要があります。
- プロバイダと顧客のリンクを OSPF に追加しないでください。

### 課題 M6-2
<p class="tolab"><a href="/_learn?id=XRT-03&amp;step=m6t2">ワークスペースで開く</a> — 読み物: <a href="60-m6-bgp.html#s3">3. 再配送</a></p>


顧客が AS 65000 の社内 LAN に到達できる必要があります。

- XR01 が OSPF で学習する社内 LAN、つまり 203.0.113.0/24 の内側で /24 より長いプレフィックスを、顧客にアナウンスしてください。
- XR01 が OSPF で学習するそれ以外のもの(ループバックとリンクのサブネット)を BGP に入れてはなりません。
- プロバイダが AS 65000 自身のアドレス空間から受信するものは、引き続き 203.0.113.0/24 だけである必要があります。

### 課題 M6-3
<p class="tolab"><a href="/_learn?id=XRT-03&amp;step=m6t3">ワークスペースで開く</a> — 読み物: <a href="60-m6-bgp.html#s4">4. プリペンドと、apply の罠</a></p>


インターネットから AS 65000 とその顧客への通信は、ISP-A が使用可能な間は ISP-A から入る必要があります。

- XR01 が ISP-B にアナウンスするすべてのルートは、いまより AS 65000 を 3 回多く持つ必要があります。
- XR01 が ISP-A にアナウンスするものは変えてはなりません。
- ISP-B が受信するルートは、以前とまったく同じ(AS 65000 自身のプレフィックスと、課題 M5-4 で許可した顧客のルート)である必要があります。

### 課題 M6-4
<p class="tolab"><a href="/_learn?id=XRT-03&amp;step=m6t4">ワークスペースで開く</a> — 読み物: <a href="60-m6-bgp.html#s5">5. テンプレート</a></p>


プロバイダの追加に備えてください。

- 両方のプロバイダに、受信プレフィックス数の上限 **1000** と、上限の **80%** に達したときの警告を設定してください。
- プロバイダが共有する設定(課題 M5-4 のコミュニティの送信と、この上限)は、1 か所で定義し、各プロバイダが継承する必要があります。
  後で 3 社目のプロバイダを接続するときに、必要なものがそのアドレス、AS 番号、ポリシーに渡す値だけになるようにしてください。
