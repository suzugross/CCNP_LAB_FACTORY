# M11 追補 — 実践(4) E-LAN

ラボ **XRT-12** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **XE1**、**XE2**、**XE3** です。P1、CE、SW1 は据え付けで、変更しないでください。確認のためにログインするのは
  構いません。CE と SW1 は顧客のものです。
- 課題の中にはコマンド例を示しません。各課題は必要な動作を記述しています。読み物の各ページには設定例がありますが、
  課題の答えと同じ形のものは折りたたんであります。先に自分で解くなら、CLI のヘルプ(`?`)、`show` コマンド、
  Cisco IOS XE のコンフィギュレーション ガイドとコマンド リファレンスを使って、コマンドを見つけてください。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。デバイスの現在の状態を読み取ります。
  押す前にコンフィギュレーション モードを抜けてください。変更の後は、LDP と BGP が落ち着くまで 30 秒ほど待ってください。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- XE1、XE2、XE3 は **Catalyst 8000V** 17.15.1a で、ブート ライセンスのレベルは `network-advantage` です(MPLS を使えます)。
  IOS XE にはコミットがなく、各行は入力した時点で有効になります。P1 は IOS XE 17.15 のルータです。

|---|---|---|

|---|---|---|---|---|---|
| VPLS の E-LAN(VPN ID 210) | VLAN 210 | VLAN 210 | VLAN 210 | — | 172.31.210.0/24 |

- コアでは、すべてのコアのリンクで IS-IS のインスタンス `CORE`(レベル 2、ワイド メトリック)と LDP が動作しています。
  BGP の AS は 65000 です。
- P1 は EVPN のアドレス ファミリーのルート リフレクタで、XE1、XE2、XE3 はクライアントとして設定済みです。
  プロバイダー エッジでは、まだ BGP は動作していません。
- プロバイダーのサイト番号: サイト 1 = **1**、サイト 2 = **2**、サイト 3 = **3**、サイト 4 = **4**。各サイトの顧客のアドレスは、
  サイト番号をホスト部に持ちます(たとえば 172.31.200.4 は SW1 です)。サービスに端ごとの識別子が必要な場合、端の識別子は
  そのサイトの番号です。
- サイト 1 とサイト 3 の間の E-Line 130 は据え付けで、動作しています。

## M11 追補 — E-LAN、マルチホーム、イーサネット OAM

### 課題 M11-6
<p class="tolab"><a href="/_learn?id=XRT-12&amp;step=m11t6">ワークスペースで開く</a> — 読み物: <a href="b7-m11-e-lan.html#s2-1">2.1 ブリッジ ドメインを疑似回線のフルメッシュでつなぐ</a> · <a href="b7-m11-e-lan.html#s2-2">2.2 1 つのフレームを追う: CE1 の ARP</a> · <a href="b7-m11-e-lan.html#s2-3">2.3 スプリット ホライズン: なぜフルメッシュでなければならないか</a> · <a href="b7-m11-e-lan.html#s2-4">2.4 IOS XE での VPLS の設定</a> · <a href="b7-m11-e-lan.html#s2-5">2.5 出力の読み方と、うまくいかないとき</a></p>


プロバイダーが EVPN に移行する前に、同僚が顧客 C の E-LAN を VPLS で作りました(VPN ID 210、サイト 1、2、3 で VLAN 210)。
顧客によると、サイト 3 は一度もほかのサイトに到達したことがありません。サイト 1 とサイト 2 は互いに到達できます。

- この E-LAN(172.31.210.0/24)で、3 つのサイトすべてが互いに到達できるようにしてください。
- XE2 の E-LAN の部分は正しく設定されています。変更しないでください。

### 課題 M11-7
<p class="tolab"><a href="/_learn?id=XRT-12&amp;step=m11t7">ワークスペースで開く</a> — 読み物: <a href="b7-m11-e-lan.html#s3-1">3.1 MAC アドレスを BGP で: 経路の種類 2</a> · <a href="b7-m11-e-lan.html#s3-2">3.2 ブロードキャスト: 経路の種類 3 と入口での複製</a> · <a href="b7-m11-e-lan.html#s3-3">3.3 1 つのフレームを追う: CE1 から CE3 へ</a> · <a href="b7-m11-e-lan.html#s3-4">3.4 IOS XE での EVPN の E-LAN の設定</a> · <a href="b7-m11-e-lan.html#s3-5">3.5 出力の読み方</a></p>


顧客 C の新しい E-LAN は、EVPN の EVPN インスタンス **200** で、サイト 1、2、3 の間に作ります。

- サイト 1、2、3 の間で、顧客のフレームを 1 つの LAN(172.31.200.0/24)として運んでください。サイト 1 とサイト 2 では、
  顧客は VLAN 200 を使います。サイト 3 では、この E-LAN は顧客のポートを VLAN のタグなしで使います。そのポートの
  ほかのサービスはタグ付きのままです。
- プロバイダー エッジは、互いの顧客の MAC アドレスを BGP で学習し、EVPN のルートをルート リフレクタ P1 だけを介して
  交換します。2 台のプロバイダー エッジの間に BGP セッションがあってはなりません。各プロバイダー エッジの BGP の
  ルータ ID は、その Loopback0 のアドレスです。
- コアはマルチキャストを運びません。顧客からブロードキャストのフレームを受け取ったプロバイダー エッジは、その E-LAN の
  ほかの各プロバイダー エッジに 1 つずつコピーを送ります。
