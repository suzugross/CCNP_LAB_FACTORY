# M14 — 実践(1) PIM スパース モード

ラボ **XRT-16** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。コマンド例は意図して示していません。

## 進め方の約束

- 設定するのは **PE1**、**PE2**、**P1**、**PE3**(IOS XRd)と **PE4**(IOS XE)です。
- **SRC1**、**RCV2**、**RCV3** はホストです。SRC1 はチャネルを送るヘッドエンドの、RCV2 と RCV3 はセットトップ ボックスの
  代わりです。試験のために、これらのインタフェースでグループへの参加を追加・削除することと、IGMP のバージョンを変更する
  ことは構いません。それ以外は変更しないでください。ホストは参加したグループ宛ての ping に応答するため、SRC1 からグループ
  宛てに ping を送ると、誰が受信したかが分かります。
- 課題の中にはコマンド例を示しません。各課題は必要な動作を記述しています。
- **Tasks** タブには課題ごとに **Check** ボタンがあります。ルータの現在の状態を読み取り、試験のトラフィックを流します。
  押す前にコンフィギュレーション モードを抜けてください。確認は、課題の範囲の中から乱数で選んだグループにホストを参加させ、
  ホストから送って応答を数えたあと、自分の参加を削除し、ホストの IGMP のバージョンを既定に戻します。1 回に 1〜2 分かかります。
- ヒントは 1 段ずつ開きます(キーワード → 参照先 → コマンド)。開いたヒントは記録されます。
- 各課題には **確かめ方** のボタンもあります。設定が入ったか → 送って数える → 届いた先を見る → 壊していないか、の順に
  確かめる手順の例です。いつ開いても構わず、記録されません。Check を押す前に、自分の手で確かめてみてください。
- **Tasks** タブの **最初からやり直す** は、ルータとホストをラボの構築直後の状態へ戻します。
- XR の 4 台は **IOS XRd** 26.1.1(IOS XR のコンテナ版)で動作しています。PE4 とホストは IOS XE 17.15(IOL)です。

## トポロジ

| リンク | 両端 | アドレス |
|---|---|---|
| CORE-12 | PE1 GigabitEthernet0/0/0/0 ─ PE2 GigabitEthernet0/0/0/0 | 10.0.12.0/24(PE1 .1、PE2 .2) |
| CORE-1 | PE1 GigabitEthernet0/0/0/1 ─ P1 GigabitEthernet0/0/0/0 | 10.0.1.0/24(PE1 .1、P1 .11) |
| CORE-2 | P1 GigabitEthernet0/0/0/1 ─ PE2 GigabitEthernet0/0/0/1 | 10.0.2.0/24(P1 .11、PE2 .2) |
| CORE-3 | P1 GigabitEthernet0/0/0/2 ─ PE3 GigabitEthernet0/0/0/0 | 10.0.3.0/24(P1 .11、PE3 .3) |
| CORE-4 | PE2 GigabitEthernet0/0/0/2 ─ PE4 Ethernet0/0 | 10.0.4.0/24(PE2 .2、PE4 .4) |
| HEADEND | PE1 GigabitEthernet0/0/0/2 ─ SRC1 Ethernet0/0 | 192.168.1.0/24(SRC1 .1、PE1 .254) |
| ACCESS-2 | PE2 GigabitEthernet0/0/0/3 ─ RCV2 Ethernet0/0 | 192.168.2.0/24(RCV2 .1、PE2 .254) |
| ACCESS-3 | SW1(非管理スイッチ): PE3 GigabitEthernet0/0/0/1、PE4 Ethernet0/1、RCV3 Ethernet0/0 | 192.168.3.0/24(PE3 .252、PE4 .253、RCV3 .1) |

すべてのリンクで IPv6 も動作しています。コアのリンクは 2001:db8:&lt;3 つ目のオクテット&gt;::/64(CORE-12 は 2001:db8:12::/64)で、
ホストの番号は IPv4 と同じです。アクセスのリンクは 2001:db8:100:&lt;3 つ目のオクテット&gt;::/64 です(SRC1 2001:db8:100:1::1、
RCV2 2001:db8:100:2::1、RCV3 2001:db8:100:3::1。ルータは IPv4 のホストの番号を使い、たとえば 2001:db8:100:3::252)。
ACCESS-3 のリンクローカル アドレスは固定です(PE3 FE80::252、PE4 FE80::253)。

| デバイス | 役割 | プラットフォーム | Loopback0 |
|---|---|---|---|
| PE1 | プロバイダー エッジ(ヘッドエンドの側) | IOS XRd 26.1.1 | 10.255.0.1/32、2001:db8:255::1/128 |
| PE2 | プロバイダー エッジ | IOS XRd 26.1.1 | 10.255.0.2/32、2001:db8:255::2/128 |
| P1 | プロバイダー コア | IOS XRd 26.1.1 | 10.255.0.11/32、2001:db8:255::11/128 |
| PE3 | 共用のアクセスのプロバイダー エッジ | IOS XRd 26.1.1 | 10.255.0.3/32、2001:db8:255::3/128 |
| PE4 | 共用のアクセスのプロバイダー エッジ | IOS XE 17.15 | 10.255.0.4/32、2001:db8:255::4/128 |
| SRC1 | ヘッドエンド(ホスト) | IOS XE 17.15 | — |
| RCV2、RCV3 | セットトップ ボックス(ホスト) | IOS XE 17.15 | — |

- 5 台のルータは、IPv4 と IPv6 の IS-IS インスタンス `CORE`(レベル 2)を動作させています。アクセスのリンクとループバックは
  パッシブです。そのため、ACCESS-3 が PE3 と PE4 の間の通信を運ぶことはありません。
- ホストは自分のルータへのデフォルト ルートを使用します。RCV3 のデフォルト ルートは PE4(192.168.3.253、2001:db8:100:3::253)です。
- IPv4 のマルチキャストは、どこにも設定されていません。前任者は IPv6 のマルチキャストを試行として設定しました(課題 M14-6)。

## M14 — マルチキャスト

### 課題 M14-1
<p class="tolab"><a href="/_learn?id=XRT-16&amp;step=m14t1">ワークスペースで開く</a> — 読み物: <a href="f0-m14-igmp-pim-sm.html#s2-2">2.2 IGMP: 受信者が自分のルータに伝える</a> · <a href="f0-m14-igmp-pim-sm.html#s2-4">2.4 PIM スパース モード: RP を通る共有ツリー</a> · <a href="f0-m14-igmp-pim-sm.html#s2-5">2.5 Register: RP が送信元を知る方法</a> · <a href="f0-m14-igmp-pim-sm.html#s3-1">3.1 マルチキャストを有効にする: multicast-routing・router pim・router igmp</a> · <a href="f0-m14-igmp-pim-sm.html#s3-2">3.2 スタティック RP</a> · <a href="f0-m14-igmp-pim-sm.html#s3-5">3.5 状態の読み方</a></p>


プロバイダーは、テレビのチャネルを、ヘッドエンドの SRC1 からセットトップ ボックスへ、PIM スパース モードの IPv4 マルチキャストで
届けます。

- PE1、PE2、P1、PE3 ではすべてのインタフェースで、PE4 では 2 本のリンクの両方で、IPv4 のマルチキャスト ルーティングを
  有効にしてください。
- すべてのルータで、P1 の Loopback0(10.255.0.11)を、239.0.0.0/8 に限ったスタティック RP として使用してください。
  239.0.0.0/8 の外のグループには、RP があってはなりません。
- RCV2 と RCV3 が、239.16.0.0/16 のチャネルを SRC1 から受信できる必要があります。

### 課題 M14-2
<p class="tolab"><a href="/_learn?id=XRT-16&amp;step=m14t2">ワークスペースで開く</a> — 読み物: <a href="f0-m14-igmp-pim-sm.html#s2-6">2.6 最短パス ツリーへの切り替え</a> · <a href="f0-m14-igmp-pim-sm.html#s3-4">3.4 共有ツリーに留まる</a> · <a href="f0-m14-igmp-pim-sm.html#s3-5">3.5 状態の読み方</a></p>


239.17.0.0/16 のチャネルは超高精細の配信です。これらは RP を通る共有ツリーに留まり、PE1 と PE2 の間の直結のリンクを
通ってはなりません。

- どのルータも、239.17.0.0/16 のグループを最短パス ツリーへ切り替えてはなりません。
- 239.16.0.0/16 のグループは、これまでどおり最短パス ツリーへ切り替わる必要があります。
- RCV2 と RCV3 は、引き続き両方の種類のチャネルを受信できる必要があります。
