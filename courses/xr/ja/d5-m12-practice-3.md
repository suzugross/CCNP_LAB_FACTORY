## M12 — データプレーンの保護と QoS

### 課題 M12-4
<p class="tolab"><a href="/_learn?id=XRT-14&amp;step=m12t4">ワークスペースで開く</a> — 読み物: <a href="d4-m12-protect.html#s2-1">2.1 uRPF: 送信元をルーティング テーブルで確かめる</a> · <a href="d4-m12-protect.html#s2-2">2.2 インフラ ACL</a> · <a href="d4-m12-protect.html#s3-1">3.1 uRPF</a> · <a href="d4-m12-protect.html#s3-2">3.2 インフラ ACL</a> · <a href="d4-m12-protect.html#s3-5">3.5 確かめ方</a></p>


- CUST1 は、XR01 に 1 本だけで接続しています。XR01 は、CUST1 から受け取るパケットのうち、送信元が、CUST1 から届くはずの
  アドレスでないものを捨ててください。
- XR01 は、INET から受け取るパケットのうち、送信元がどこにもルートの無いアドレスであるものを捨ててください。既定ルートは、
  ルートがあるものとして数えません。マルチホームの顧客の通信はインターネット経由で戻ってくることがあるので、送信元への
  ルートがどのインターフェイスを向いているかは問いません。
- INET から、プロバイダーのループバック(10.255.0.0/24)とコアのリンク(10.0.0.0/16)へのパケットを、XR01 の入口で
  捨ててください。INET との BGP と、顧客へ向かう通信は保ちます。どの条件に一致したパケットが何個あったかを、条件ごとに
  ハードウェアで数えてください。

### 課題 M12-5
<p class="tolab"><a href="/_learn?id=XRT-14&amp;step=m12t5">ワークスペースで開く</a> — 読み物: <a href="d4-m12-protect.html#s2-3">2.3 RTBH: 宛先で捨てる</a> · <a href="d4-m12-protect.html#s2-4">2.4 RTBH: 送信元で捨てる</a> · <a href="d4-m12-protect.html#s3-3">3.3 RTBH の起点</a> · <a href="d4-m12-protect.html#s3-4">3.4 境界のルータ: set next-hop discard</a> · <a href="d4-m12-protect.html#s3-5">3.5 確かめ方</a></p>


前任者が RR1 に、RTBH の起点を作りました。RR1 でスタティック ルートにタグ 666 を付けると、そのルートが PE に配られ、
PE はそのアドレスへのパケットを捨てます。顧客 CUST2 の 198.51.100.130 が攻撃を受け、宛先の 198.51.100.130 と、攻撃元の
203.0.113.66 が RR1 に登録されています。ところが、攻撃元からのパケットは、今も CUST2 に届いています。

- 攻撃元(RR1 にタグ 666 で登録したアドレス)から来るパケットを、XR01 の入口で捨ててください。攻撃を受けている宛先への
  パケットも、引き続き XR01 で捨てます。
- RR1 に登録したアドレスのルートを、インターネットへ広告してはなりません。
- 起点の仕組みはそのまま使います。攻撃元や宛先の足し外しは RR1 だけで済み、XR01 に個々のアドレスを書いてはなりません。
- PE2 は変更しません。PE2 は従来どおり、登録された宛先へのパケットを、捨て先の 192.0.2.1 を経由して捨て続けます。
