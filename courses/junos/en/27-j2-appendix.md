# J2 — Appendix

## 1. Quick reference: the order of evaluation

The order in which one packet passes through firewall filters.

1. The input filter of the interface it came in on.
2. Look up the routing table. If it is forwarded elsewhere, the output filter of the interface it leaves through. If it is for this
   router, through the input filter on lo0 to the RE. Packets that the RE sends also pass the output filter of the interface they leave through.
3. If filters are listed, one at a time from the left. Within a filter, one term at a time from the top.
4. A term's `from` matches when every condition of a different kind matches (AND) and one of the values of the same kind matches (OR).
   In a list of addresses, the one that covers the packet's address most specifically decides; if it is `except`, there is no match.
5. Run the `then` of the matching term.
   - `accept`, `discard`, `reject`: it ends here. Listed filters after this one are not checked either.
   - Only `count`, `log`, `syslog`, `policer`: run them, then let the packet through (an implicit accept).
   - `next term`: on to the next term (on Junos OS Evolved it cannot be the last term).
6. If no term matches, on to the next filter. At the end of the last filter, the implicit discard.

## 2. Quick reference: actions

| Action | Kind | What it does | In an IOS or IOS XR ACL |
|---|---|---|---|
| `accept` | terminating | Let it through | permit |
| `discard` | terminating | Drop it silently | deny |
| `reject` | terminating | Drop it and send an ICMP unreachable (code 13 by default) | deny (ICMP handling depends on device settings) |
| `count name` | modifier | Count it | per-line counter |
| `log` | modifier | Keep it in the PFE buffer (`show firewall log`) | `log` |
| `syslog` | modifier | Turn it into a syslog message (the firewall facility) | `log` |
| `policer name` | modifier | Limit the rate | `police` (CoPP, QoS) |
| `next term` | flow | On to the next term | — |

## 3. Quirks of this virtual router

The router of this unit is vJunos-Evolved (Junos OS Evolved 26.2R1.7, a virtual router modelled on the PTX10001-36MR).
The part that forwards packets is a software simulator (up to 2 kpps) instead of a real ASIC.

### 3.1 reject tcp-reset does not send a RST

`reject` has a type `tcp-reset` (send a RST for TCP), but the PTX table of filter actions says that tcp-reset is not supported.
On this router it commits, and for a TCP packet it sent back an ICMP unreachable with code 0 (network unreachable) instead of a RST.
Use `reject` without a type.

### 3.2 Policers do not limit the rate

A policer commits, and a Policers section appears in `show firewall`, but it does not limit the rate. With a 64 kbps limit, 100 pings
of 1000 bytes per second (about 0.8 Mbps) were not dropped at all, whether in transit or to the RE, and the number dropped stayed at 0.
The vJunosEvolved deployment guide says of vJunosEvolved-BX, from the same family, that it does not support firewall policers.
Check designs that rely on policers on real equipment.

### 3.3 Output filters, and packets the RE sends

On this router, an interface's output filter acted on packets sent by the RE too (section 2.8 of the second page). Juniper's
documentation has a note in the chapter on EX and QFX switches saying that egress filters do not affect control packets generated by
the RE. Behaviour differs between models, so after applying an output filter, check the router's own traffic too (answers to SSH, to ping and so on).

### 3.4 Delays and leftovers in counters and records

- Read right after the traffic, a counter may not have gone up yet. Wait a few seconds and read again.
- The `show firewall log` buffer loses its oldest entries first. In this topology, entries from a few minutes before had disappeared.
- Putting the configuration back does not clear the counters, the `show firewall log` entries or the syslog files inside the router.
  They are cleared with `clear firewall all`, `clear firewall log` and `file delete /var/log/name` (the lab's "Start over" clears these too).

### 3.5 Filters on the management port, and 0.0.0.0/8

The Junos OS Evolved 26.2R1 release notes list a known issue: writing the reserved prefix 0.0.0.0/8 in a management interface filter or
a host-inbound policy causes unintended filtering and the loss of management traffic, SSH included (PR1910579). A source check is a place
where you may want 0.0.0.0/8, so do not use it around the management port of this router.
