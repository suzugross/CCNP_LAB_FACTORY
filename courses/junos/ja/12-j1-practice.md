# J1 — 実践 1

ラボ **JNT-02** の課題です。ラボから離れた場所でも読めるように、ここに載せています。
取り組むのはラボのワークスペースです。**Tasks** タブに、課題ごとの確認ボタン、段階式のヒント、
通過後に開く模範解があります。

## 進め方の約束

- JUN01 と JUN02 には、J0 の範囲(アドレス・OSPF・静的経路)と、JUN02 と FRR1 の間の BGP のセッションが設定されています。
  ルーティング ポリシーは何も設定されていません。
- FRR1(ISP)と SRV1(サーバ)は設定済みです。変更しないでください。コンソールから見る(`show` コマンド)ことはできます。
- **Topology** タブで機器をクリックすると、その機器のコンソールが開きます。Junos のルータには `admin` でログインしています。
- 各課題には、成り立つべきことを書いています。**確認**ボタンは機器の状態を見ます。
- 課題は順番に進めてください。後の課題は前の課題の結果を使います。後の課題を解いた後も、前の課題の要件を満たしていること。

## トポロジ

```
SRV1 eth1 ──── et-0/0/1 JUN01 et-0/0/0 ──── et-0/0/0 JUN02 et-0/0/1 ──── eth1 FRR1(ISP)
       172.16.10.0/24                10.0.12.0/30                10.0.23.0/30
```

| 機器 | インターフェース | アドレス |
|---|---|---|
| SRV1 | eth1 | 172.16.10.10/24(既定経路は 172.16.10.1) |
| SRV1 | lo(サーバの網) | 172.16.20.1/24 |
| JUN01 | et-0/0/1.0 | 172.16.10.1/24 |
| JUN01 | et-0/0/0.0 | 10.0.12.1/30 |
| JUN01 | lo0.0 | 192.168.0.1/32 |
| JUN02 | et-0/0/0.0 | 10.0.12.2/30 |
| JUN02 | et-0/0/1.0 | 10.0.23.1/30 |
| JUN02 | lo0.0 | 192.168.0.2/32 |
| FRR1 | eth1 | 10.0.23.2/30 |
| FRR1 | lo | 203.0.113.1/32 |

- JUN01 と JUN02 は AS 65000 です。2 台は、2 台の間のリンクとループバックで OSPF を area 0 で動かしています。
- JUN01 には静的経路が 2 つあります。172.16.20.0/24 は SRV1(172.16.10.10)の奥のサーバの網、172.16.99.0/24 は
  検証用の網で、行き先は discard です。
- JUN02 は FRR1(ISP・AS 64500)と eBGP のセッションを張っています。ISP は、インターネットの経路の代わりに、
  既定経路といくつかの経路を送ってきます。

## J1 ルーティング ポリシー

単元 J1 に沿った課題です。経路の出入りを、Junos のルーティング ポリシーで制御してください。

### 課題 J1-1  サーバの網を OSPF で広告する
<p class="tolab"><a href="/_learn?id=JNT-02&amp;step=j1t1">ワークスペースで開く</a> — 読み物: <a href="11-j1-policy-statement.html#s2-1">2.1 policy-statement の形</a> · <a href="11-j1-policy-statement.html#s2-2">2.2 from: 同じ種類は OR、違う種類は AND</a> · <a href="11-j1-policy-statement.html#s2-3">2.3 then: 3 種類の動作</a> · <a href="11-j1-policy-statement.html#s2-6">2.6 OSPF へ export する: 外部経路の型と metric</a> · <a href="11-j1-policy-statement.html#s3-1">3.1 OSPF へ静的経路を 1 つ、type 1 で</a></p>


JUN02 が、JUN01 の後ろの 2 つのサーバの網に届くようにしてください。

JUN01 は、172.16.10.0/24 と 172.16.20.0/24 を OSPF で広告すること。172.16.20.0/24 の metric は 20 とすること。
検証用の 172.16.99.0/24 は広告しないこと。JUN01 のサーバの網のインターフェース(et-0/0/1)では OSPF を動かさないこと。

### 課題 J1-2  ISP の既定経路を社内へ配る
<p class="tolab"><a href="/_learn?id=JNT-02&amp;step=j1t2">ワークスペースで開く</a> — 読み物: <a href="11-j1-policy-statement.html#s2-4">2.4 評価の順: term → 次のポリシー → 既定のポリシー</a> · <a href="11-j1-policy-statement.html#s2-7">2.7 BGP の経路を OSPF へ</a> · <a href="11-j1-policy-statement.html#s2-6">2.6 OSPF へ export する: 外部経路の型と metric</a></p>


JUN01 は、OSPF で既定経路を学ぶこと。この既定経路は、JUN02 が ISP から既定経路を受け取っている間だけ存在すること。
ISP とのセッションが落ちたら、JUN01 の既定経路も消えること。

ISP から受け取るほかの経路は、OSPF に入れないこと。
